# 노션 용어 각주 계획 (방법 A: 절별 번호 각주)

방식: 용어가 그 절에서 처음 나올 때 본문 끝에 ¹ ² ³ 번호를 붙이고, 절 맨 끝(구분선 바로 위)에 «이 절의 용어» 작은 목록을 둔다. 번호는 절마다 ¹부터 다시 센다. 「용어 정리」·「용어 보충」 표와 제목은 없앤다.
노션에는 각주 블록이 없다(슬래시 메뉴에서 «/footnote» 검색 결과 없음 확인). 그래서 유니코드 위첨자 ¹²³과 절 끝 목록으로 흉내 낸다.
실행 시점: 결제 구현·스크린샷 결과를 본문에 반영해 글이 확정된 뒤 한 번에 한다(본문이 바뀌면 번호가 어긋난다).

## 절별 목록

### 한눈에 보기
¹ 원가 — 서비스를 제공하는 데 드는 돈. 쓸수록 늘면 변동비, 쓰든 안 쓰든 매달 나가면 고정비
² 전환율 — 무료 사용자 가운데 크레딧을 실제로 사는 사람의 비율
³ 원장(ledger) — 늘고 줄어든 기록을 한 줄씩 쌓기만 하는 표. 잔액은 그 줄들의 합계(가계부와 같다)

### 1절 원가
¹ 토큰 — LLM이 글을 세는 단위. 입력 토큰(보낸 글)과 출력 토큰(받은 글)에 각각 단가를 곱해 요금이 나온다
² 모델 호출 — 서버가 LLM(여기서는 gpt-4o-mini)에게 질문을 보내고 답을 받는 일. 요금은 이 호출에만 붙는다
³ 트레이스(trace) — Langfuse에서 메시지 한 건(한 턴)을 처리한 기록 전체. 도장 도우미에서는 chat-turn이라는 이름이 붙는다
⁴ generation — 트레이스 안에서 모델 호출 한 번에 해당하는 기록(모델 이름·토큰 수·비용). 트레이스가 영수증 한 장이면 generation은 그 안의 품목 한 줄이다

### 2절 가격과 무료 한도
¹ 전환율 — (위와 같음, 이 절에서 처음 계산에 쓰이면 여기에 단다)
² PG(결제 대행사) — 카드사와의 연결을 대신 맡는 회사. 이번에는 토스페이먼츠
³ BYOK — 사용자가 자기 LLM 키를 직접 넣어 쓰는 방식. 그 경우 운영자 원가가 없다(도장 코드의 `pick_llm`)

### 3절 크레딧 원장
¹ 원장(ledger) — (위와 같음)
² 경쟁 상태(race condition) — 두 요청이 거의 동시에 같은 값을 읽고 각자 고쳐서 결과가 어긋나는 버그. 읽고 → 계산하고 → 저장을 따로 하면 생긴다
³ 402 / 429 — 402는 «결제가 필요하다»는 HTTP 상태 코드로 크레딧 부족에 쓴다. 429는 도장 서버가 속도 한도를 넘은 요청에 돌려주는 값(busy)이라 둘을 구별한다

### 4절 결제 흐름
¹ 결제 인증 / 결제 승인 — 인증은 사용자가 결제창에서 카드사 확인을 마치는 것, 승인은 우리 서버가 «이 결제를 확정해 달라»고 요청해 돈이 빠지는 것
² successUrl — 인증이 끝나면 토스페이먼츠가 브라우저를 보내는 우리 서버 주소. paymentKey·orderId·amount가 주소 뒤에 붙어 온다
³ 클라이언트 키 / 시크릿 키 — 클라이언트 키는 화면에 있어도 되는 키, 시크릿 키는 돈이 움직이는 일(승인·취소)에 쓰며 서버에만 둔다
⁴ 웹훅 — 결제 대행사가 결제 결과를 우리 서버의 주소로 직접 알려 주는 호출
⁵ 샌드박스 — 토스페이먼츠 개발자센터에서 SDK 없이도 테스트용 paymentKey를 받아 볼 수 있는 곳. 실제로 결제되지 않는다(토스페이먼츠 문서)
⁶ 시퀀스 다이어그램 — 누가 누구에게 어떤 순서로 요청하는지를 위에서 아래로 그린 도표

### 5절 중복·위조 방어
¹ 멱등성(Idempotency-Key) — 같은 요청이 여러 번 와도 결과가 한 번 받은 것과 같게 만드는 성질. 같은 값의 키를 보내면 토스페이먼츠가 다시 처리하지 않고 첫 응답을 돌려준다
² 대사(reconciliation) — 토스페이먼츠 기록, 우리 주문, 원장 세 곳의 금액과 주문 번호가 서로 맞는지 맞춰 보는 일

## 하지 않는 것
- 각 용어를 노션 하위 페이지로 만들어 `@`로 연결하는 방식(B)은 시험해 보고 접었다(사용자가 A를 선택).
