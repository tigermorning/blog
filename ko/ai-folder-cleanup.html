6편 끝에 남겨둔 예고 그대로, 이번엔 6편에서 만든 terminal-practice 폴더 정리를 Claude Code에게 맡겨봤어요. 그런데 목표가 "AI가 대신 치워주는 것"이 아니었어요. 분류 계획을 먼저 내고, 제가 승인한 뒤에만 실제로 옮기게 하는 것이 이번 실습의 핵심이었어요. 이건 4편에서 다룬 "지시 → 생성 → 판단 → 재지시" 루프를 그대로 쓰는 거예요. 다만 이번엔 되돌리기 어려운 파일 이동이 걸려 있어서, "판단" 단계를 실행 전으로 앞당긴 거예요.

먼저 폴더를 어지럽히고, dry-run 개념부터 이해했어요

6편에서 만든 terminal-practice 폴더에는 ideas, assets/images/landing-page.txt, archive가 있었죠. 여기에 연습 삼아 screenshot.png, notes.txt, draft.docx 세 개를 폴더 맨 위(어디에도 안 들어간 상태)에 그냥 흩어뒀어요. 파일 이름 뒤에 점을 찍고 붙는 .png, .txt, .docx를 확장자라고 부르는데, 각각 그림·글자메모·워드 문서라는 뜻이에요. 종류가 서로 다른 파일을 일부러 섞어둔 거예요. 실제 바탕화면이 아니라 이 연습 폴더에서만 하는 거라, 마음 편하게 어지럽힐 수 있었고요.

그런데 이대로 "정리해줘"라고만 하면, AI가 그 즉시 파일을 옮겨버려요. 그게 싫었어요. 그래서 이번 실습의 진짜 주인공인 dry-run을 먼저 이해하고 가야 했어요.

dry-run은 실제로는 아무것도 바꾸지 않고, "이대로 실행하면 무슨 일이 일어날지"만 미리 보여주는 것을 말해요. 이름을 뜯어보면 뜻이 그대로 보여요. dry는 "마른", run은 "한 번 돌려보기"예요. 원래 소방 훈련에서 물을 틀지 않고 하는 연습을 dry run이라고 불렀대요. 실제로 물이 나가면 되돌릴 수 없으니, 물 없이 동선만 맞춰보는 거죠. 연극에서 무대장치 없이 대사만 맞춰보는 연습도 같은 말로 불러요.

이게 왜 중요하냐면, 4편의 루프에서 "판단"은 결과가 나온 뒤에 하는 단계였거든요. 글이나 코드는 마음에 안 들면 다시 만들면 그만이에요. 그런데 파일 이동은 달라요. 이미 옮겨진 뒤에 잘못을 알아채면, 뭐가 어디로 갔는지 되짚어가며 손으로 되돌려야 해요. 그래서 dry-run은 그 판단 시점을 결과가 나오기 전으로 끌어당기는 장치예요. AI가 계획을 다 세운 상태에서 실행 직전에 저를 한 번 멈춰 세우는 거죠.

그러니까 AI가 곧바로 파일 이동 명령을 실행하려고 하면, 그 자리에서 "아직 실행하지 말고 dry-run 목록만 보여줘"라고 끊어야 해요. 저는 아예 처음 요청에 이 규칙을 넣어서 보내기로 했어요.

Claude Code에게 보낸 프롬프트와 dry-run 결과

수업 자료에는 정리를 맡길 때 지켜야 할 규칙이 개조식으로 나와 있었어요. 개조식은 문단으로 줄줄 쓰지 않고, 한 줄에 한 가지씩 끊어서 나열하는 방식이에요. 4편에서 다뤘던 "추가할 것 / 지킬 것"과 같은 구조인데, 조건이 한 줄에 하나씩 떨어져 있어야 AI가 그중 하나를 흘려버리지 않아요. 저도 같은 형태로 요청했어요.

terminal-practice 폴더의 파일과 폴더를 읽고 정리 계획을 세워줘.
지킬 것:
- 삭제 명령(rm 등)은 절대 실행하지 마.
- 먼저 dry-run으로 "현재 위치 → 제안 위치" 목록과 분류 기준만 보여줘.
- 이동은 내가 목록을 검토하고 "승인"이라고 답한 뒤에만 실행해.
- 이름을 추측하지 말고, 확장자와 현재 이름을 근거로 분류해.
- 실행 뒤에는 이동한 목록과 남은 파일 목록을 보여줘.

참고로 위의 rm은 파일을 지우는 명령어예요. PowerShell에서도 그대로 통하는 이름이라, 아예 이름을 콕 집어서 금지해둔 거예요.

파일을 하나도 건드리지 않은 채, 계획만 표로 돌아왔어요.

draft.docx를 AI가 마음대로 넘기지 않고 "질문"으로 남긴 부분이 특히 마음에 들었어요. 이름을 추측하지 말라는 규칙이 실제로 지켜진 증거였거든요.

그런데 여기서 바로 "좋아요, 진행해"라고 답하면 dry-run을 요청한 의미가 절반은 사라져요. 미리 보여달라고 한 이유는 제가 그걸 실제로 검토하기 위해서였으니까요. 그래서 뭘 기준으로 볼지부터 정했어요.

다섯 개 중 넷은 계획만 보고도 통과 판정을 낼 수 있었고, 마지막 하나는 실행한 뒤에야 확인할 수 있는 항목이었어요. 그러니까 여기까지 온 이상, 이제 실제로 실행을 승인해도 되는 상태였어요.

계획이 대체로 마음에 들었지만, draft.docx는 지금 당장 정하고 싶지 않았어요. 그래서 이렇게 답했어요.

계획을 검토했어. screenshot.png와 notes.txt는 제안한 대로 옮겨줘.
draft.docx는 지금 분류하지 말고 그대로 폴더 맨 위에 둬.
삭제·이름 변경은 하지 마. 실행 후 이동 전후 목록을 비교해서 보여줘.

이 문장도 4편에서 배운 개조식 그대로예요 — "무엇은 진행, 무엇은 보류, 무엇은 하지 마"를 한 줄씩 나눠서 답하니 AI가 헷갈릴 여지가 줄었어요. 실행 후 ls(지금 폴더 안에 뭐가 들어 있는지 목록으로 보여주는 명령어예요)로 확인해보니 screenshot.png와 notes.txt만 옮겨졌고, draft.docx는 그대로 남아 있었어요 — 승인한 그대로 딱 맞게 실행된 거예요. 아까 체크리스트에서 미뤄뒀던 마지막 항목까지 이렇게 통과됐어요.

정리해보면 오늘 한 일은 "AI에게 청소를 시킨 것"이 아니었어요. 되돌리기 어려운 일 앞에서, 실행 전에 검토할 자리를 하나 만들어둔 것이었어요. 손으로 직접 mv를 쳤던 6편과 비교하면 계획을 세우는 속도는 훨씬 빨랐지만, 그 계획이 맞는지 확인하는 책임은 여전히 저에게 있었고요. 속도는 AI가 가져가고 판단은 제가 쥐는 이 배분이 어떤 느낌인지, 두 방식을 나란히 놓고 비교해보는 게 다음 8편이에요.

이럴 때 의심하세요 — AI에게 파일 정리를 맡긴 앞뒤

파일 정리의 실수는 옮기고 난 뒤에야 눈에 띄는데, 그때는 뭐가 어디로 갔는지 손으로 되짚어야 해요. 그래서 열어 볼 자리는 대부분 실행 전의 dry-run 표와 AI가 명령을 실행해도 되냐고 묻는 화면에 있어요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
"정리해 줘"라고 했더니 계획표 없이 곧바로 mv나 Move-Item 명령을 실행해도 되냐고 물어요 허락 요청에 뜬 명령 한 줄, 그리고 내가 보낸 첫 요청에 "dry-run 먼저", "승인 뒤에만 실행" 줄이 따로 있었는지예요 허락하지 말고 "아직 실행하지 말고 현재 위치 → 제안 위치 목록만 보여 줘"라고 끊어요. 이미 옮겨졌다면 "방금 옮긴 파일마다 원래 위치 → 지금 위치를 표로 보여 줘"라고 받아서, 그 표를 거꾸로 따라 되돌려요
dry-run 표의 분류 기준 칸에 "추정", "~로 보임" 같은 말이 있거나, 이름만으론 애매한 파일까지 보류 없이 전부 자리가 정해져 있어요 dry-run 표의 분류 기준 칸이에요. 확장자처럼 눈으로 확인되는 근거인지, 이름에서 짐작한 건지 봐요 그런 줄마다 "무엇을 근거로 이 폴더를 골랐어?"라고 물어요. 확장자나 현재 이름으로 설명이 안 되면 보류로 돌려요. 결과를 보고 뒤늦게 알아챈 경우는 첫 글의 이 줄에 있어요
승인하고 나서 ls로 보니 dry-run 표에 없던 이동이 있어요. 보류하라던 파일이 옮겨졌거나, 폴더가 통째로 옮겨졌어요 dry-run 표와 실행 뒤 받은 이동 전후 목록이에요. 둘을 나란히 놓고 표에 없는 줄을 찾아요. 표의 제안 위치에 작업 폴더 이름이 빠진 경로나 ..\가 든 경로가 있었는지도 봐요 표에 없는 이동은 원래 위치를 물어 되돌려요. 다음부터는 본문의 체크리스트 다섯 칸을 하나씩 채운 뒤에 "승인"이라고 답해요
삭제 명령은 한 번도 없었는데, 실행 뒤 세어 보니 파일 개수가 줄었어요 dry-run 표의 제안 위치에 같은 이름 파일이 이미 있었는지예요. bash의 mv는 같은 이름이 있으면 묻지 않고 덮어써요. PowerShell의 Move-Item은 에러로 멈추지만, -Force가 붙으면 덮어써요 승인하기 전에 "제안 위치마다 같은 이름 파일이 이미 있는지 표에 한 칸 더 적어 줘"라고 해요. 겹치는 줄은 이름을 바꿀지 보류할지 내가 정해요. "삭제 명령 금지" 규칙만으로는 이 경우를 못 막아요

넷째 줄이 제일 놓치기 쉬워요. 체크리스트의 삭제 방지 칸은 통과했는데, 옮기기가 지우기와 같은 결과를 낸 경우라서요. 계획표를 받을 때부터 확인할 칸을 늘려 달라고 하면, 승인 전에 한 번에 볼 수 있어요.

실행: 코딩 에이전트에 붙여넣기 — Claude Code 등 — 정리할 폴더를 연 상태에서

이 폴더를 정리하는 이동 계획을 표로만 보여 줘. 아직 아무것도 옮기거나 지우지 마.
표의 칸은 이렇게 해 줘.
1. 현재 위치 / 제안 위치
