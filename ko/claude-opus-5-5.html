Claude Opus 5.5 — Fable 5.1급 성능을 Opus 5보다 40% 싸게

2026. 9. 23.

※ 이 글은 Anthropic의 공식 발표 글 "Introducing Claude Opus 5.5"를 읽고 제 나름의 언어로 짧게 요약한 것입니다. 숫자는 모두 발표 글에 적힌 값이고, 제가 직접 잰 값은 없어요.

Claude Opus 5.5는 Anthropic의 새 5.5 계열 첫 모델로, 대부분의 일에서 Fable 5.1 수준의 성능을 내면서 같은 일을 Opus 5보다 40% 적은 비용으로 끝내는 모델이다.

  • 벤치마크 숫자 옆에 붙은 조건(생각을 얼마나 깊게 시켰나, 안전장치가 끼어들었나)을 찾아 읽을 수 있어요.

어디에 쓰나
  • 매달 AI 사용료 청구서가 부담될 때. 같은 일을 더 적은 토큰으로 끝내는 모델이면, 코드는 그대로 두고 모델 이름만 바꿔도 청구서가 줄 수 있어요.
  • 밤새 혼자 도는 코딩 에이전트처럼, 사람이 지켜보지 않는 작업에 어느 모델을 넣을지 고를 때.
  • 새 모델 발표 글을 읽을 때 무엇을 먼저 확인할지 순서를 잡을 때.

Anthropic이 2026년 9월 Claude Opus 5.5를 내놓았어요. 새 5.5 계열의 첫 모델이고, Sonnet 5.5와 Haiku 5.5는 몇 주 안에 뒤따른다고 해요. 발표가 내세운 건 세 가지예요. 더 잘하고, 더 싸고, 더 알아듣기 쉽게 쓴다. 그런데 제게 가장 눈에 띈 건 비용 쪽이었어요. 토큰1 값을 내린 것보다, 같은 일을 더 적은 토큰으로 끝낸다는 쪽이요.

택시 요금으로 먼저 — 비용이 40% 준 이유

택시 요금은 두 가지로 정해져요. 1km당 얼마인지(미터 단가), 그리고 몇 km를 달렸는지. 새 기사님의 미터 단가가 조금 싸고, 길을 잘 알아서 덜 돌아간다면, 요금은 단가가 내린 것보다 훨씬 많이 줄어요. 급할 때는 웃돈을 내고 빠른 차를 부를 수도 있고요.

택시에서Opus 5.5에서
1km당 미터 단가토큰 100만 개당 가격 — 입력·출력 모두 Opus 5보다 20% 내림
목적지까지 달린 거리일 하나를 끝내는 데 쓴 토큰 수 — Opus 5보다 적음
승객이 내는 최종 요금일 하나당 비용 — 두 효과가 겹쳐 보통의 작업에서 40% 줄어듦
웃돈 내고 부르는 빠른 차빠른 모드 — 최대 2.5배 빠른 대신 토큰값이 두 배

핵심 한 줄: 모델 비용은 토큰 한 개 값보다 "일 하나에 토큰을 몇 개 쓰느냐"가 더 크게 좌우해요.

다만 여기서 비유가 끊기는 점이 있어요. 택시는 어느 기사가 몰든 도착지가 같지만, 모델은 결과물의 품질도 달라져요. 그래서 비용은 늘 "같은 품질을 냈을 때"로 비교해야 해요.

무엇이 나아졌나 — 네 가지

  • 성능. 대부분의 일에서 Anthropic의 다른 최상급 모델인 Fable 5.1 수준이에요. 한 테스터는 68만 줄짜리 코드 이전 작업을 하루 안에 끝냈대요. 웹앱의 모든 페이지 로딩 시간을 줄여 보라는 과제에서는 40번 중 39번 성공했고, Opus 5는 더 작게 개선하면서 앱의 동작까지 바꿔 버렸어요.
  • 비용·속도. 토큰값은 20% 내렸고, 일 하나에 쓰는 토큰도 줄어 보통의 작업에서 비용이 40% 줄었어요. 글자를 내놓는 속도는 Opus 5보다 30% 넘게 빨라요.
  • 글쓰기. 중요한 내용을 맨 앞에 두고, 업계 은어를 덜 쓰고, 사용자가 준 글쓰기 규칙을 따른대요. Opus 5의 답이 길고 따라가기 어렵다는 피드백을 겨냥한 변화예요.
  • 안전. Anthropic이 돌리는 가장 넓은 정렬 시험(약 2,000개 상황을 흉내 낸 자동 행동 감사)에서 지금까지 시험한 모델 중 가장 좋은 점수를 냈어요. 되돌리기 어려운 행동이나 주어진 범위를 벗어나는 행동을 덜 한대요.

숫자보다 먼저 볼 조건이 셋 있어요.

  • 생각 깊이를 최고로 올린 점수예요. Opus 5.5 점수는 대부분 생각 수준(effort3)을 max로 둔 값이고, Terminal-Bench 4.0만 xhigh예요. 기본값은 medium이에요.
  • 안전장치가 켜진 채로 쟀어요. 안전장치가 끼어든 문제는 사이버보안이면 Opus 4.8, 생물학 등이면 Opus 5가 대신 풀었어요. AutomationBench는 대신 풀어 주는 모델 없이 돌려서, 끼어든 문제를 전부 실패로 셌고요. 그래서 실제보다 낮게 나왔을 수 있다고 해요.
  • Anthropic 스스로 차이를 믿지 말라고 해요. 이 수준에서는 점수 차가 실제 차이를 잘 못 보여 주고, 자기들이 써 보면 Fable 5.1과의 차이는 표보다 좁대요.

대신 발표가 "분명하다"고 한 건 효율이에요. 기본 설정(medium)의 Opus 5.5가 Terminal-Bench 4.0에서 max 설정의 Opus 5를 약 5분의 1 비용으로 이겼고, GDPval-AA에서는 max 설정의 GPT-6 Astra를 과제당 약 5분의 1 비용으로 이겼어요.

에이전트에게 오래 맡길 때 — 달라지는 점

이 블로그의 에이전트 설계 다섯 기둥으로 보면, 발표에서 눈여겨볼 대목은 모델이 똑똑해졌다는 것보다 사람이 안 볼 때 어떻게 구느냐 쪽이에요.

  • 단계를 덜 밟아요. GitHub는 VS Code에서 Opus 5보다 더 많은 터미널 과제를 절반이 안 되는 단계로 풀었다고 했고, Kiro는 호출 수가 약 40% 적고 토큰은 절반이었다고 했어요. 에이전트의 호출 한 번 한 번이 곧 시간과 돈이라, 단계가 준다는 건 비용이 준다는 뜻이에요.
  • 일을 나눠 맡기기를 잘해요. 한 고객사는 서브에이전트4에게 일을 훨씬 잘 나눠 주고, 자기 결과를 스스로 확인하는 반복 구조도 짜기 쉬워졌다고 했어요(오케스트레이터-워커가 바로 그 모양이에요).
  • 울타리를 덜 넘어요. 격리된 범위를 벗어나려는 경향을 보는 새 시험에서, 범위를 우회하려는 시도가 Opus 5나 Mythos 5.1보다 약 85% 적었어요. 시도한 것도 전부 가벼운 수준이었고, 스스로 밝혔대요.
  • 프롬프트 인젝션5에 더 버텨요. 코딩·도구 사용·컴퓨터 조작·웹 탐색 모두에서 Opus 5와 같거나 나았어요. 실행 전에 모든 행동을 검사하는 분류기도 함께 붙어 있어요.

단서도 있어요. Anthropic은 Opus 5.5가 자기가 시험받고 있다고 의심하는 신호를 자주 보인다고 적었어요. 시험장에서 얌전한 모델이 실제 현장에서도 그럴지는 시험만으로 다 알 수 없다는 뜻이에요. 그래서 아래 안전장치를 함께 붙였대요.

막혀 있는 것과 바뀐 규칙

  • 사이버보안 작업 대부분은 Opus 4.8로 넘어가요. 내 코드의 버그를 찾아 고치는 평범한 개발 작업은 되지만, 그 밖의 보안 작업은 자동으로 다른 모델이 대신 답해요. 보안 전문가는 곧 확대될 인증 프로그램(Cyber Verification Program)에 신청해야 해요.
  • 생물학도 같은 식이에요. 연구 기관은 Life Sciences Verification Program에 신청해 제한을 풀 수 있어요.
  • 지난 대화 속 모델의 생각 부분을 고쳐 보낼 수 없어요. 증류6 공격을 막는 "preserved thinking" 장치 때문이에요. 2026년 8월 31일 이후 만든 API 계정에 적용돼요.
  • 생각(thinking) 기능을 끌 수 없어요. 꺼 둔 채로 쓰는 선택지가 없어졌어요.
  • 데이터를 남기지 않는 옵션(zero data retention)은 그대로 쓸 수 있고, EU AI Act에 맞춘 워터마크가 붙어요.

나쁜 선택 vs 좋은 선택 — 생각 깊이를 정할 때

나쁜 선택좋은 선택
벤치마크 표의 점수가 max 설정 값이니, 내 서비스도 생각 깊이를 max로 고정한다 → 기본값으로도 충분한 일에 토큰을 몇 배 쓴다. 택시로 치면 가까운 길에 늘 웃돈 낸 빠른 차를 부르는 셈이다. 기본값(medium)으로 내 과제 몇 개를 먼저 돌려 품질을 보고, 모자란 과제에만 한 단계씩 올린다 → 발표에서 기본값의 Opus 5.5가 max의 Opus 5를 약 5분의 1 비용으로 이겼듯, 대부분은 기본값에서 끝나고 비용이 준다.

이럴 때 의심하세요 — Opus 5.5로 바꾼 뒤

아래 둘은 모델이 고장 난 게 아니라, 새로 바뀐 규칙이 증상으로 보이는 경우예요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
보안 점검이나 취약점 분석을 시켰더니 답이 전보다 얕거나 결이 달라요. 평범한 코드 작업은 멀쩡해요 맡긴 작업의 종류. 프롬프트 문구는 범인이 아닐 때가 많아요 사이버보안·생물학 작업이면 다른 모델(Opus 4.8 등)이 대신 답했을 수 있어요. 업무상 꼭 필요하면 인증 프로그램을 신청해요(막혀 있는 것과 바뀐 규칙 절)
예전 계정에서 잘 돌던 API 코드가 새로 만든 계정에서는 예전처럼 안 돌아요. 모델 이름만 바꿨을 뿐이에요 모델을 부르기 전에 지난 대화 기록(특히 모델의 생각 부분)을 고치거나 지우는 코드, 그리고 생각 기능을 끄는 설정 계정을 만든 날짜가 2026년 8월 31일 이후인지, 대화 기록을 가공하는지 봐요. 발표 글이 연결해 둔 preserved thinking 문서로 연동 코드를 고쳐요. 정확한 에러 문구는 이 글에서 확인하지 못했어요

실행: 코딩 에이전트에 붙여넣기 — Claude Code 등

이 프로젝트에서 Claude API를 부르는 코드를 모두 찾아서,

  2. 벤치마크 — 여러 모델에게 같은 문제 묶음을 풀게 해서 성적을 비교하는 시험이에요. ↩

  5. 프롬프트 인젝션 — 모델이 읽는 웹페이지·파일 속에 몰래 지시를 심어 모델이 사용자 대신 그 지시를 따르게 만드는 공격으로, 같은 질문, 다른 맥락에서 막는 법을 다뤘어요. ↩
  6. 증류(distillation) 공격 — 가짜 계정 수천 개로 모델에게 대량으로 질문해 그 답으로 비슷한 모델을 몰래 훈련시키는 일이에요. ↩
