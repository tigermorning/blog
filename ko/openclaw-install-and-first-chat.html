2026. 9. 4.

← 이전 편 새 껍데기, 같은 바닷가재 — OpenClaw는 무엇이고 어디서 왔나

OpenClaw 설치는 "연습 폴더를 만들고, npm으로 받고, 온보딩으로 첫 설정을 하고, 진단 명령 두 개로 상태를 확인한 뒤, WebChat에 한 문장 보내기"까지가 한 묶음이다.

1편에서 OpenClaw가 늘 켜져 있는 집사 같은 도구라는 것과, 그 중심에 게이트웨이가 있다는 걸 봤어요. 이번 편은 실제로 들이는 날이에요. 터미널1을 열어 명령을 몇 개 치는데, 저는 명령 자체보다 "왜 이 순서인지"와 "어디서 멈춰야 하는지"를 더 챙겼어요.

비유 — 새 직원의 첫 출근일

회사에 새 직원이 처음 출근했어요. 총무는 먼저 그 직원의 자리를 정해 주고(아직 금고 옆은 아니에요), 입사 서류를 받고, 사원증을 발급해요. 그러고 나서 바로 고객을 만나게 하지 않고, 사내 메신저로 "잘 들리나요?" 한 줄을 보내 연결이 되는지 확인해요. 퇴근 시간이 되면 직원은 사무실을 나가지만, 인사 기록은 서랍에 남아요.

비유 속 요소원래 개념
금고 옆이 아닌, 따로 마련한 자리실제 업무 폴더가 아닌 연습 폴더 ~/openclaw-lab
입사 서류 작성온보딩(onboard) — 첫 실행에 필요한 선택을 대화형으로 받는 과정
사원증(어떤 명의로 일하나)인증 경로 — 구독 로그인이냐, API 키냐

퇴근해도 남는 인사 기록프로그램을 멈춰도 남는 ~/.openclaw/ 설정·상태 폴더

핵심 한 줄: 설치는 "깔았다"로 끝나지 않고, 자리·서류·명의·연결 확인·퇴근까지가 한 세트예요.

전체 흐름

읽는 법: 왼쪽에서 오른쪽으로 순서대로 가요. 굵은 상자 ④가 이 흐름의 검문소예요. 진단이 실패하면 채팅으로 넘어가지 말고 그 자리에서 멈추라는 게 강의의 지시였어요.

① 자리를 정한다 — 연습 폴더와 Node 버전

이 실습은 오늘 처음 만드는 연습 폴더에서만 해요. 실제 업무 저장소, 개인 파일이 있는 곳, 홈 폴더의 설정 폴더 안에서는 하지 않아요. 새 터미널을 열고 아래를 실행해요.

mkdir -p ~/openclaw-lab && cd ~/openclaw-lab
pwd
node --version

mkdir는 폴더 만들기, -p는 "이미 있어도 오류 내지 마"라는 옵션, cd는 그 폴더로 들어가기예요. ~는 내 홈 폴더를 뜻해요. pwd는 지금 내가 어느 폴더에 있는지 출력하고, node --version은 Node.js2 버전을 보여 줘요. 공식 설치 문서는 Node 22.22.3 이상, 24.15 이상, 25.9 이상을 요구하고 Node 26을 권장해요. 화면의 버전이 이 범위에 안 맞으면 Node를 억지로 바꾸지 말고 멈춰요. 버전을 바꾸다가 다른 프로그램이 깨지는 일이 흔해서요.

여기서 제가 놓칠 뻔한 게 있어요. 폴더를 따로 만들었다고 격리가 끝나는 게 아니에요. OpenClaw는 어디서 설치하든 설정과 상태를 홈 폴더의 ~/.openclaw/ 아래에 모으고, 자격 증명3도 거기 저장해요. 그래서 "연습 폴더니까 괜찮겠지" 하고 실제 업무 계정을 넣으면 그 계정 정보가 홈 폴더에 남아요. 수업용 계정, 수업용 키만 쓰고, 온보딩 화면에서 실제 업무 계정이나 비밀값을 요구하면 입력을 멈추는 게 규칙이에요.

② ③ 설치와 온보딩

공식 README는 macOS·Linux·WSL2에는 install.sh, Windows에는 install.ps1 스크립트를 안내해요. 하지만 npm은 운영체제와 상관없이 같은 명령으로 설치되고 버전도 지정할 수 있어서, 여러 노트북이 섞인 수업에서는 npm 경로를 공통으로 썼어요.

npm install -g openclaw@latest --allow-scripts=openclaw
openclaw --version

-g는 이 폴더만이 아니라 컴퓨터 전체에서 쓸 수 있게 설치하라는 뜻이고, @latest는 설치하는 시점의 최신 버전을 받으라는 뜻이라 화면에 보이는 숫자는 날짜마다 달라요. --allow-scripts=openclaw는 npm이 패키지 설치 중 실행하는 부가 스크립트4를 이 패키지에 한해 허용하는 옵션이에요. 두 번째 줄은 설치가 됐는지 버전으로 확인하는 거예요.

openclaw onboard --install-daemon

온보딩은 처음 실행에 필요한 선택을 질문-답 형식으로 받는 과정이고, --install-daemon은 데몬5까지 같이 설치하라는 옵션이에요. 데몬은 터미널 창을 계속 열어 두지 않아도 뒤에서 돌아가는 관리 서비스예요. macOS에서는 LaunchAgent, Linux와 WSL2에서는 systemd 사용자 서비스라는 방식으로 등록될 수 있어요. 이름은 몰라도 돼요. "터미널을 닫아도 집사는 계속 집에 있다"는 뜻이에요.

인증 경로 — 누가 열쇠를 들고 있나

온보딩 화면에서 제일 중요한 선택이 인증 경로예요. 공식 문서가 안내하는 길은 둘이에요.

경로어떻게 동작하나요금은 어디서열쇠는 누가
claude-cli (구독 재사용)같은 컴퓨터에 로그인해 둔 Claude Code 세션을 OpenClaw가 내부적으로 Claude CLI를 실행해 대신 씀구독 한도에서 차감CLI(로그인 세션)
ANTHROPIC_API_KEY (API 키)OpenClaw가 키를 직접 들고 API6를 호출쓴 만큼 종량 과금OpenClaw

강의가 단서를 붙인 대목이 있어요. 구독 계정을 연결해도 "Claude가 구독으로 완벽하게 동작하는" 건 아니에요. 요금과 한도는 구독에서 빠지지만 실제 호출은 CLI를 거치는 우회로라서요. 그리고 어느 쪽이든 API 키 값을 메모나 화면 캡처에 남기지 않아요. 이 "열쇠를 누가 들고 있나"의 차이는 3편에서 사용량 숫자를 읽을 때 다시 나와요. 두 경로가 실제로 어떻게 다른지 더 알고 싶다면 로컬이냐 API냐는 틀린 질문 — 세 갈래가 도움이 돼요.

④ 진단 — 세 곳에서 확인하고, 실패하면 멈춘다

openclaw doctor
openclaw gateway status

doctor는 구성 진단 명령이에요. 여기서 강의가 강조한 읽는 법이 하나 있어요. 마지막 줄만 보고 성공이라고 판단하지 않는다. 경고와 오류가 중간에 있어도 마지막 줄은 멀쩡해 보일 수 있어서, 통과한 항목과 남은 항목을 화면 그대로 읽는 게 진단의 목적이에요. gateway status는 게이트웨이가 실행 중인지 보여 줘요. 둘 중 하나라도 실패하면 그 시점에서 멈춰요.

⑤ 첫 대화 — WebChat

WebChat은 OpenClaw가 자체로 제공하는 대화 화면이에요. 실행 중인 게이트웨이가 이 화면을 http://127.0.0.1:18789에서 내어 놓아요. 127.0.0.1은 "이 컴퓨터 자신"을 가리키는 특별한 주소라 밖에서는 접속할 수 없고, 18789는 포트7 번호예요. 브라우저는 이 게이트웨이와 WebSocket8이라는 방식으로 연결을 끊지 않은 채 메시지를 주고받아요. 화면은 저절로 열리지 않고, 아래 명령으로 열어요.

openclaw dashboard

게이트웨이가 멈춰 있으면 화면이 열려도 메시지를 보낼 수 없어요. 화면이 열리면 무해한 한 문장을 보내요. 강의가 쓴 문장은 이거였어요.

이 메시지를 받았다면 연결 확인이라고만 답해 주세요.

주소를 추측해서 입력하거나, 외부에서 접속되게 포트를 열지 않아요. 기본 주소의 외부 접속은 공식 문서가 권장하지 않고, 원격 접속에는 별도 승인 절차가 있어요. 원격에서 꼭 써야 한다면 공식 문서가 안내하는 길은 Tailscale9이에요. 게이트웨이는 127.0.0.1에 그대로 둔 채, Serve 기능으로 내 기기들끼리만 쓰는 HTTPS 주소를 붙이거나 Funnel 기능으로 공개 주소를 만드는 방식이에요. 이건 4편의 텔레그램 연결과는 다른 길이에요. 텔레그램은 에이전트가 메시지를 받을 새 입구를 여는 것이고, Tailscale은 이미 떠 있는 WebChat 화면을 다른 기기에서도 보는 것이에요.

⑥ 생긴 것을 열어 보고, 멈춘다

ls -la ~/.openclaw

설치와 온보딩 뒤에 남은 폴더예요. 폴더 이름과 파일 이름이 설치가 남긴 흔적이에요. 파일 안에 토큰10, 키, 개인 대화가 보이면 복사하거나 공유하지 않아요. 그리고 화면에 표시된 경로만 따라가고, 화면에 없는 경로를 추측해서 만들거나 열지 않아요. 이 폴더 안이 어떻게 나뉘어 있는지는 3편에서 자세히 봐요.

수업이 끝나면 멈춰요. 데몬으로 띄웠다면 아래 첫 줄, 터미널에서 직접 실행했다면 그 터미널에서 Ctrl+C. 그다음 두 번째 줄로 정말 멈췄는지 확인해요.

openclaw daemon stop
openclaw gateway status

프로그램을 멈춰도 상태 폴더와 설정 파일은 지우지 않는 한 남아요. 기본 설정 파일은 ~/.openclaw/openclaw.json이고, 위치는 openclaw config file로 확인할 수 있어요. 마무리에서는 프로그램을 끄고, 수업용 토큰과 인증 경로가 어디에 보관됐고 누가 접근할 수 있는지를 다시 살펴요.

나쁜 선택 vs 좋은 선택 — 첫 출근일에 벌어지는 일

나쁜 선택좋은 선택
doctor 출력이 길어서 마지막 줄 "done"만 보고 통과했다고 여기고 바로 텔레그램 토큰까지 넣는다 → 중간의 경고를 못 본 채 채널을 열어, 나중에 실패했을 때 어느 단계가 원인인지 못 가른다. doctor와 gateway status를 위에서 아래까지 읽고, 경고가 하나라도 있으면 채팅으로 넘어가지 않고 그 항목부터 해결한다 → 다음 단계에서 문제가 나도 "설치는 멀쩡하다"는 전제를 믿을 수 있다.
연습 폴더니까 안전하다고 여겨 온보딩에 실제 업무용 API 키를 넣는다 → 그 키가 홈 폴더 ~/.openclaw/에 저장되어 연습이 끝나도 남는다. 수업용 계정과 수업용 키만 쓰고, 끝난 뒤 ls -la ~/.openclaw로 무엇이 남았는지 확인한다 → 지워야 할 것과 남겨도 되는 것을 구분할 수 있다.

직접 해보기

설치가 끝났다는 증거를 네 가지 화면에서 모아 보세요. openclaw --version의 버전 숫자, 온보딩 완료 화면, openclaw gateway status의 상태, WebChat의 첫 응답. 이 넷을 순서대로 확인했다면 설치가 된 거예요. 어느 하나가 안 나오면 openclaw --version부터 다시 봐요. 설치 자체가 안 됐는지, 설치는 됐는데 게이트웨이가 안 떴는지, 게이트웨이는 떴는데 인증이 안 됐는지가 순서대로 갈려요. WebChat 응답이 없다면 게이트웨이 상태와 오류 문구를 같이 봐요. 이건 PowerShell 명령어 실습에서 익힌 "명령 하나 치고 출력 읽기"의 연장이에요.

  1. 터미널 — 글자로 명령을 입력해 컴퓨터를 조작하는 창으로, 터미널·셸·커널·프롬프트 차이에서 처음 다뤘어요. ↩
  2. Node.js — 브라우저 밖에서 자바스크립트를 실행하게 해 주는 프로그램으로, Node.js·npm 설치 확인에서 설치했어요. ↩
  3. 자격 증명 — 로그인 정보, API 키, 토큰처럼 "내가 나임"을 증명하는 비밀값의 총칭. ↩
  4. lifecycle script — npm 패키지가 설치·제거 같은 단계에서 자동으로 실행하는 부가 스크립트로, 보안상 기본으로 막고 필요한 패키지만 허용해요. ↩
  5. 데몬 — 사용자가 창을 열어 두지 않아도 뒤에서 계속 실행되는 서비스 프로그램. ↩
  6. API — 프로그램끼리 정해진 방식으로 요청과 응답을 주고받는 창구로, API란 무엇인가에서 처음 다뤘어요. ↩
  7. 포트 — 한 컴퓨터 안에서 여러 프로그램이 통신을 나눠 받기 위한 번호로, 도메인·포트·HTTPS에서 처음 다뤘어요. ↩
  8. WebSocket — 브라우저와 서버가 연결을 끊지 않고 양쪽에서 계속 메시지를 보낼 수 있는 통신 방식. ↩
  9. Tailscale — 내 기기들을 하나의 사설망처럼 묶어 서로만 접속할 수 있게 해 주는 도구. ↩
  10. 토큰 — 여기서는 AI의 글자 단위가 아니라, 서비스 접속을 허가하는 비밀 문자열을 뜻하며 AI 쪽 토큰은 AI 토큰이란에서 다뤘어요. ↩
