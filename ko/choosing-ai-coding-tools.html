AI 코딩 도구 고르기 — 터미널이냐 편집기냐 클라우드냐

2026. 7. 26.

※ 이 글은 모두의연구소 AI AIFFEL 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 스킬과 규칙 파일 — 반복 작업을 AI에게 외워 두기

마감 전날 브라우저에서 빠르게 화면을 손보고 싶을 수도 있고, 팀의 저장소를 내려받아 테스트와 터미널 명령까지 맡기고 싶을 수도 있어요. 둘 다 "AI 코딩"이지만 필요한 하네스와 권한은 달라요. 도구를 고르기 전에 제가 어디서 일하고, 무엇을 AI에게 맡길지부터 정해야 했어요.

네 부류로 나뉘는 하네스

앞서 배운 "에이전트 = 모델 + 하네스"에서, 이 하네스(도구)는 종류가 아주 많지만 크게 네 부류로 나뉘었어요 — '어디서 돌아가고, 내가 얼마나 지켜보느냐'로 갈렸어요. 터미널/CLI형은 검은 명령창에서 돌아가요. 깊고 강력하지만 조금 낯설어요(Claude Code, Codex CLI, Aider). 편집기(IDE)형은 VS Code 같은 코드 편집기 안에서 도는데(Cursor, Devin Desktop, Cline), 변경 사항을 눈으로 보며 승인·취소할 수 있어 심리적 문턱이 낮았어요. 브라우저형은 웹에서 클릭 몇 번으로, 처음엔 가장 수월해요(Lovable, Bolt, Replit Agent). 클라우드/비동기형은 "이 이슈 고쳐줘"를 통째로 맡기면 백그라운드에서 일하고 결과를 초안으로 가져와요(Devin, Google Jules).

비교할 때는 모델 이름만 보지 말고 네 가지를 확인하는 게 좋았어요 — 파일을 읽고 쓸 수 있는지, 터미널·브라우저 같은 도구를 쓸 수 있는지, MCP로 내 자료를 연결할 수 있는지, 실행 전후에 제가 승인·검토할 수 있는지. 처음에는 되돌리기 쉬운 작은 수정으로 시험해보는 게 가장 좋은 비교 방법이었어요.

대표 도구 비교 — "정답 하나는 없다"

커뮤니티에서 가장 자주 나오는 결론부터 말하면 "정답 하나는 없다"였어요. 도구마다 성격이 뚜렷해서 고르는 사람의 자리와 취향을 타요. "코파일럿은 회사가 골라주고, Claude Code나 Cursor는 엔지니어가 직접 고른다"는 우스개가 돌 정도였어요.

도구형태언제 / 누구에게
Claude Code터미널 에이전트어려운 문제를 끝까지 파고들 때
OpenAI Codex터미널 + 클라우드돌려 두고 결과만 검토할 때
Aider · opencode터미널·오픈소스비용을 직접 조절하고 터미널이 편할 때
Cursor편집기(VS Code 포크)편집기에서 매끄럽게 쓰고 싶을 때
GitHub Copilot여러 편집기의 확장회사 규정·컴플라이언스가 중요할 때
Lovable · Bolt · Replit브라우저(노코드)코딩이 처음이거나, 기획자의 첫 도구
Devin · Google Jules클라우드/비동기결과만 검토하며 맡기고 싶을 때

고르는 기준은 프레임워크 고를 때와 같았어요 — 정답이 아니라 내 조건. 터미널이 편한가 편집기가 편한가, 비용은, 확장(MCP·스킬)이 필요한가, 빠른 시제품인가 어려운 문제인가. "다들 최고라는 것" 말고 제 상황으로 고르면 됐어요.

"세계 최초의 AI 소프트웨어 엔지니어" 논쟁 — Devin

2024년 3월, 스타트업 Cognition이 Devin을 공개하며 "세계 최초의 AI 소프트웨어 엔지니어"라고 내세웠어요. 프리랜서 플랫폼에서 실제로 일을 받아 돈을 번다는 시연 영상이 큰 화제가 됐죠. 그런데 곧 반론이 나왔어요. 한 개발자가 그 영상을 뜯어보니 홍보만큼 과제를 제대로 끝내지 못했고, 잘 되는 장면만 골라 담았다는 지적이었어요. 이후 독립 테스트에서도 성공률이 기대에 크게 못 미쳤대요.

여기서 얻은 교훈은 두 가지였어요. 첫째, 화려한 데모는 가려서 볼 것 — "된다"는 시연과 "믿고 맡길 수 있다"는 전혀 다른 이야기예요. 둘째, 그럼에도 이 소동은 자율 코딩 에이전트 경쟁에 불을 붙인 촉매였다는 것 — 과대광고와 진짜 발전은 늘 섞여 온다는 걸 알게 됐어요.

초보라면 어떤 형태부터, 그리고 무엇을 보고 고를까

만들기부터 배포까지 클릭으로 끝내고 싶다면 브라우저형(Lovable·Bolt·Replit)이 문턱이 가장 낮았어요. 코드를 조금씩 보며 배우고 싶다면 편집기형이 좋았어요 — AI가 고친 걸 눈으로 보고 승인/취소하며 감을 익힐 수 있으니까요. 터미널형은 힘이 세지만 검은 화면이 익숙해진 뒤에 넘어가는 게 나았고, 클라우드형은 "알아서 다 해줌"이 매력이지만 결과를 검토·판단할 안목이 아직 부족한 초보의 첫 도구로는 통제감이 떨어졌어요.

고를 때 볼 기준은 다섯 가지였어요 — 모델을 고를 수 있나(한 회사 모델만 되나, 아무 모델이나 꽂나), 비용 구조(월 정액인가, 쓴 만큼 API 요금인가), 오픈소스 여부(오픈소스면 그 도구가 서비스를 접어도 남이 이어받아 살릴 수 있어요), 터미널이 편한가, 맡길까 지켜볼까. 실무자들도 하나만 쓰지 않는다는 게 인상적이었어요 — 어려운 건 터미널 에이전트, 일상 편집은 편집기, 가끔 백그라운드용으로 클라우드 에이전트를 섞어 쓴다고 해요. 다음 글에서는 이렇게 강력한 도구에게 컴퓨터를 맡길 때 꼭 알아야 할 권한과 안전, 그리고 비용 이야기를 볼게요.

한 걸음 더: 위 비교표는 "형태"로 나눈 첫 감각이었다면, Claude Code·opencode·Aider 같은 터미널형 도구를 실제 연구 수치로 훨씬 깊게 비교한 시리즈가 에이전트 하네스 톺아보기예요. 도구 이름표보다 "내 일이 어디서 막히는가"부터 관찰하는 법(1편)과, 일곱 개 실제 하네스를 기능별로 나란히 놓은 비교표(5편)가 특히 이 글과 바로 이어져요.
