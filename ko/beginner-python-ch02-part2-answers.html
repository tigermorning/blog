모든 코드는 Python 3.12에서 직접 실행해 출력을 확인했어요. 문제 원문은 실습 문제 3개에 있어요.

문제를 누르면 해설이 펼쳐져요.

문제 1 — 정회원 확인 (and)

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

members = ['서준', '하은', '도윤']
name = input()
points = int(input())

if name in members and points >= 1000:
    print('VIP 회원입니다')
else:
    print('VIP 회원이 아닙니다')

한 줄씩 짚어보기

  • name in members — 이름이 리스트 안에 있으면 True, 없으면 False. 그 자체로 참/거짓 값 하나예요.
  • points >= 1000 — 이것도 참/거짓 값 하나예요.
  • A and B는 둘 다 True일 때만 True예요. 하나라도 False면 전체가 False가 돼요.

and로 이은 두 조건 중 왼쪽 항인 name in members부터 검사해요. 네 가지 입력으로 어떻게 갈리는지 표로 볼게요.

namepointsname in members ?points >= 1000 ?출력
하은1200참참VIP 회원입니다
수아1200거짓(평가 안 함)VIP 회원이 아닙니다
서준500참거짓VIP 회원이 아닙니다
도윤1000참참VIP 회원입니다

'수아' 행이 중요해요. name in members가 이미 거짓이라 and 전체 결과가 거짓으로 확정되고, 파이썬은 오른쪽의 points >= 1000은 아예 검사하지 않아요(지난 글에서 본 단락 평가). 그래서 명단에 없는 사람의 포인트가 아무리 높아도 소용없어요.

여기서 자주 막혀요: "포인트 1200인데 왜 수아는 VIP가 아니지?" → 명단에 없으면(in이 이미 False) 포인트는 아예 안 보고 넘어가요. and는 "둘 다" 만족해야 하니까요.

나쁜 선택좋은 선택
if name in members:과 if points >= 1000:을 따로따로 쓰고, 두 번째 if의 결과로 앞의 판정을 덮어씀 → 명단에 없어도 포인트만 높으면 VIP로 잘못 판정 if name in members and points >= 1000:처럼 한 문장으로 묶음 → 두 조건이 동시에 참일 때만 통과

실제 코드에서 · 쿠폰 발급, 등급 산정처럼 "자격 + 실적"을 같이 봐야 하는 판정 로직은 거의 다 이 모양이에요.

문제 2 — 장바구니 총액, 이번엔 for로

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

cart = [12000, 8500, 3000]
total = 0
for i in range(len(cart)):
    total += cart[i]
print('총액:', total)

한 줄씩 짚어보기

  • len(cart) — 리스트 개수. cart는 3개니까 3.
  • range(3) — 0, 1, 2 세 숫자를 순서대로 만들어요.
  • for i in range(3): — i가 0 → 1 → 2 순서로 바뀌면서 몸통을 3번 반복해요.
  • cart[i] — i번째 값. i=0이면 cart[0](12000), i=1이면 cart[1](8500), i=2면 cart[2](3000).
  • total += cart[i] — total = total + cart[i]의 줄임말. 반복마다 누적돼요.
icart[i]total
01200012000
1850020500
2300023500

len(cart)는 3이라서 range(len(cart))는 0, 1, 2를 순서대로 만들어요. while로 짤 때 i = 0을 미리 만들고 i += 1을 몸통 끝에 직접 써야 했던 것과 달리, for는 그 두 줄을 대신 해 줘요 — i를 0으로 시작해서 1씩 늘리며 range가 끝날 때까지 도는 일을 for가 통째로 맡는다는 뜻이에요.

여기서 자주 막혀요: "i가 대체 뭔데?" → 그냥 순서 번호(0, 1, 2)예요. "왜 cart[i]지 cart[0]이 아니야?" → i가 반복마다 바뀌니까 cart[i]를 쓰면 자동으로 0, 1, 2번째 값이 차례로 들어와요. cart[0]으로 고정하면 매번 첫 번째 값(12000)만 더하게 돼요.

더 나아가기: 사실 인덱스 i가 굳이 필요 없다면, for price in cart:처럼 리스트 원소를 바로 꺼내 total += price로 써도 결과는 같아요. range(len())은 "몇 번째인지(i)"가 진짜 필요할 때만 쓰는 게 더 파이썬다워요.

흔한 실수: range(cart)처럼 리스트를 통째로 넣으면 TypeError: 'list' object cannot be interpreted as an integer가 나요. range()는 정수만 받으니 꼭 range(len(cart))로 길이를 넣어야 해요.

실제 코드에서 · 장바구니·영수증·재생목록처럼 리스트 값을 다 더하는 코드는 while로도 for로도 짤 수 있는데, 실무 코드는 대부분 for 쪽이에요 — 반복 횟수를 세는 변수를 직접 관리하지 않아도 되기 때문이에요.

문제 3 — 명단에서 이름 찾기, 이번엔 for-else로

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

members = ['지민', '서준', '하은']
name = input()
for m in members:
    if m == name:
        print('있음')
        break
else:
    print('없음')

한 줄씩 짚어보기

  • for m in members: — m이 '지민' → '서준' → '하은' 순서로 리스트 원소를 하나씩 꺼내 와요.
  • 매번 if m == name:으로 지금 꺼낸 값이 찾는 이름과 같은지 확인해요.
  • 같으면 있음을 찍고 break로 반복을 그 자리에서 즉시 끝내요.
  • else:는 for에 딸린 것이에요(if의 else가 아니에요!). break를 한 번도 안 타고 반복이 끝까지 다 돌았을 때만 실행돼요.

name = '하은'과 name = '수아'를 표로 따라가 볼게요.

mm == '하은' ?동작
지민거짓다음 원소로
서준거짓다음 원소로
하은참'있음' 출력, break로 반복 즉시 종료 → else 건너뜀
mm == '수아' ?동작
지민거짓다음 원소로
서준거짓다음 원소로
하은거짓다음 원소로 (원소 끝)
(반복 끝)—break 없이 끝까지 돎 → else 실행, '없음' 출력

여기서 자주 막혀요: 헷갈리는 지점은 else가 for와 같은 들여쓰기라는 거예요. "if를 못 만족하면 else"가 아니라 "반복 전체가 break 없이 끝나면 else"예요. break를 빼먹으면 '있음'을 찍고도 계속 돌다가 결국 else까지 실행돼서 '있음'과 '없음'이 같이 찍히는 버그가 나요 (바로 아래에서 실제로 확인해요).

기존 while + found 플래그 방식과 비교하면 이래요.

나쁜 선택(과거 방식)좋은 선택(for-else)
found = False를 미리 만들고, 찾으면 found = True로 바꾼 뒤, 반복이 끝나고 나서 if found:로 따로 검사 → 코드가 한 줄 더 길고, found = True로 바꾸는 줄을 깜빡하면 찾았는데도 "없음"이 나오는 조용한 버그가 생김 for ... else:를 쓰면 break를 못 타고 끝까지 돈 경우를 파이썬이 알아서 판단해 줌 → found 변수 자체가 필요 없고, 깜빡할 지점도 하나 줄어듦

흔한 실수 — break를 빠뜨리면? 아래처럼 break 없이 짜면, '하은'을 찾아 있음을 출력하고도 반복이 계속 돌다가 끝까지 다 돌았으니(멈춘 적이 없으니) else도 함께 실행돼요.

for m in members:
    if m == name:
        print('있음')
        # break 없음
else:
    print('없음')
있음
없음

이게 바로 지난 글 "이럴 때 의심하세요"에서 말한 증상이에요 — break가 없으면 for는 찾은 뒤에도 멈추지 않고 끝까지 돌고, else는 "break로 안 멈췄다"는 사실만 보고 무조건 실행되니 두 줄이 같이 찍혀요.

실제 코드에서 · 아이디 중복 확인, 재고에 있는지 검사처럼 "리스트 안에 있는지"를 찾고 없을 때만 안내가 필요한 코드에 이 모양이 그대로 쓰여요.

이름을 찾았는데도 "있음"과 "없음"이 같이 찍혀요 for-else 블록의 break 위치 일치를 찾은 if 안에 break가 실제로 있는지 확인해요 (문제 3)
명단에 없는 이름인데도 VIP로 판정돼요 if 조건에서 and 대신 or를 쓰지 않았는지 and인지 or인지 다시 읽어봐요 — or는 "하나만 참이어도" 통과예요 (문제 1)
