사람이 기억하지 않도록 — 자동화 예약과 cron (7)

2026. 9. 4.

※ 이 글은 모두의연구소 학습 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 한 게이트웨이에 여러 역할 — 바인딩·델리게이트·스탠딩 오더

automations는 게이트웨이 안에 들어 있는 스케줄러로, 반복되는 일을 사람이 기억하지 않도록 시간표에 올려 두는 기능이다.

3편에서 지금 상태를 보는 눈을 얻었어요. 이번에는 스스로 움직이는 시간표를 만들어요. 반복되는 일을 예약하는 기능이 automations(오토메이션)예요. "자동화"라는 말이 뭘 뜻하는지, 워크플로나 에이전트와 어떻게 다른지는 자동화·워크플로·에이전트, 뭐가 다를까에서 정리했어요. 이 편은 그 자동화 중 가장 단순한 "정해진 시각에 정해진 일"을 OpenClaw로 해 보는 거예요.

비유 — 학교 종과 시간표

학교에는 종이 있어요. 종은 교무실 벽의 시간표대로 울리고, 선생님이 매시간 시계를 보며 "지금 쳐야지" 하지 않아요. 시간표는 벽에 붙어 있어서 교무실 불이 꺼졌다 켜져도 그대로 남아요. 다만 종을 울리는 장치의 전원이 꺼져 있으면 시간표가 있어도 종은 안 울려요. 그리고 "오늘만 3시에 한 번" 같은 임시 알림은 울리고 나면 시간표에서 지워지고, "매시간 50분" 같은 정규 종은 계속 남아요.

비유 속 요소원래 개념
종을 울리는 장치게이트웨이 안의 스케줄러 — 게이트웨이가 켜져 있어야 동작
벽에 붙은 시간표SQLite 데이터베이스에 저장된 일정 — 재시작해도 남음
"오늘만 3시에 한 번"일회성 예약 (ISO 시각) — 성공하면 자동 삭제
"매시간 50분"반복 예약 (cron 표기식) — 실행 뒤에도 목록에 남음
종이 울린 기록부openclaw automations runs의 실행 기록
시간표를 고칠 수 있는 교무 담당operator.admin 권한

핵심 한 줄: 시간표(일정)는 남지만 종(스케줄러)은 게이트웨이가 켜져 있을 때만 울려요.

다만 여기서 비유가 끊기는 점은, 학교 종은 소리만 내지만 OpenClaw의 예약은 프롬프트를 실행해서 에이전트가 실제 일을 한다는 거예요. 그래서 5편의 권한 경계가 예약에도 그대로 적용돼요.

전체 흐름

읽는 법: 왼쪽부터 순서대로 해요. 굵은 상자 ④가 3편의 "말이 아니라 기록"을 예약에 적용하는 자리예요. 종이 울렸다는 걸 채팅에 뜬 메시지로도 알 수 있지만, 실행 기록부에 두 번 적혔는지까지 봐야 확인이 끝나요.

스케줄러는 게이트웨이 안에 있다

automations는 1편에서 본 게이트웨이에 들어 있는 스케줄러1예요. 모델 안에서 실행되는 기능이 아니에요. 게이트웨이 프로세스가 실행 중이어야 예약한 시각에 일이 시작돼요. 일정, 실행 상태, 실행 기록은 OpenClaw의 공유 SQLite2 데이터베이스에 저장되니, 게이트웨이를 다시 시작해도 예약 자체는 사라지지 않아요. 실행 결과는 채팅 채널, 웹훅3, 또는 기록으로 보낼 수 있어요.

먼저 빈 시간표를 봐요. 처음 쓰는 환경이면 목록이 비어 있어요.

openclaw automations list

openclaw automations는 작업을 만들고, 목록과 상세 정보, 실행 기록을 보고, 지우는 명령이에요. 짧게 openclaw cron이라고 써도 같아요. 작업을 만들거나 지우거나 즉시 실행하는 변경 명령에는 operator.admin 권한이 필요해요. 권한은 예약이 실행되는 조건과 별개로 먼저 확인해요.

3분 뒤의 알림 하나 — 일회성 예약

먼저 UTC4의 현재 시각을 확인하고, 거기서 3분 뒤의 ISO 시각5을 계산해요.

date -u +%FT%TZ

아래 <ISO시각> 자리에 그 값을 넣어요. --session main은 앞에서 연 WebChat의 main 세션으로 시스템 이벤트를 보내라는 뜻이에요.

openclaw automations create "<ISO시각>" --name "첫 알림" --session main --system-event "3분 전에 예약한 알림이 도착했습니다"

시간이 되면 main 세션에 메시지가 도착해요. WebChat을 열어 확인해요. 한 번만 실행하는 작업은 성공하면 자동으로 지워져요. 명령의 순서도 정해져 있어요. 일정이 먼저, 프롬프트가 그다음. 위 명령은 프롬프트 대신 시스템 이벤트를 넣은 형태이고, 이름은 목록에서 알아보기 쉽게 붙여요.

5분마다 울리는 시보 — cron 표기식

cron 표기식은 반복 시간을 다섯 칸으로 적는 방식이에요. 칸의 순서는 "분 시 일 월 요일"이에요.

칸1번째2번째3번째4번째5번째
뜻분시일월요일
*/5 * * * *5분마다모든 시모든 날모든 달모든 요일

*는 "모든"이고 */5는 "5 단위마다"예요. 그래서 */5 * * * *는 "5분마다, 언제든"이 돼요.

openclaw automations create "*/5 * * * *" "지금 시각과 대기 중인 알림이 있으면 한 줄로 알려 줘" --name "5분 시보"

몇 분 기다리며 WebChat에 시보가 두 번 도착하는지 봐요. 이 작업은 반복 일정이라 한 번 실행되어도 목록에 남고 다음 5분을 기다려요.

실행된 기록을 본다

openclaw automations list에서 시보의 작업 ID를 확인한 뒤, 그 작업의 실행 기록을 봐요.

openclaw automations runs --id <job-id>

시보가 두 번 울렸다면 기록에도 두 번의 실행이 있어요. 일회성 작업은 실행 뒤 목록에서 사라지지만 반복 작업은 다음 실행 시각을 가진 채 남아요. 목록과 실행 기록을 나란히 보면 이 차이가 그대로 보여요. 그리고 게이트웨이를 끄면 스케줄러도 함께 멈춰요. 그동안은 예약 시각이 되어도 실행되지 않고, 다시 켠 뒤에도 SQLite에 저장한 일정과 이전 기록은 남아 있어요.

같은 일을 대화로 시킨다

다섯 칸 표기식을 외우지 않아도 예약을 만들 수 있어요. 길이 둘이에요.

첫째, 반복을 알아채는 길. 같은 부탁을 여러 번 하면 에이전트가 먼저 "예약으로 바꿀까요?" 하고 제안해요. 만들기 전에 일정과 할 일을 사람의 말로 한 문장 확인해요. "매주 평일 오전 7시에 어제 밤 업데이트를 요약해 이 방에 올립니다" 같은 문장이에요. 이 문장을 확인하면 예약이 만들어져요. cron 표기식이 아니라 사람의 문장으로 확인하게 하는 설계예요.

둘째, 대화 명령 /loop. WebChat에서 /loop 5m 지금 시각을 한 줄로 알려 줘를 보내면 이 대화에 묶인 5분 반복 작업이 만들어져요. 소유자만 쓸 수 있는 명령이에요. 간격을 빼면 1분에서 1시간 사이에서 에이전트가 스스로 다음 실행을 정해요. /loop status로 이 대화의 반복 작업을 보고 /loop stop으로 꺼요.

WebChat에서 /loop로 시보를 하나 만들고, openclaw automations list를 다시 실행해 보면 CLI6로 만든 시보와 /loop로 만든 시보가 한 목록에 나타나요. 만드는 입구가 달라도 스케줄러는 하나예요.

실습이 끝나면 시간표를 비운다

openclaw automations remove <job-id>

/loop로 만든 시보는 대화창에서 /loop stop으로도 지울 수 있어요. 반복 작업을 남겨 두면 게이트웨이가 켜져 있는 동안 계속 실행되고, 그때마다 토큰을 써요. 실습이 끝난 작업은 지우는 습관이 필요해요.

나쁜 선택 vs 좋은 선택 — 시간표를 짤 때

나쁜 선택좋은 선택
5분 시보를 만들어 두고 "잘 되네" 하고 지우지 않은 채 게이트웨이를 켜 둔다 → 밤새 12번씩 매시간 모델을 호출해 다음 날 3편의 /usage cost에 이유 모를 비용이 쌓여 있다. 실습 뒤 list로 남은 작업을 확인하고 remove로 지운다 → 시간표에 내가 아는 것만 남는다.
시보를 만들고 채팅에 메시지가 안 떠서 "예약이 사라졌나?" 하고 다시 만든다 → 실은 게이트웨이가 꺼져 있었을 뿐이고, 켜는 순간 같은 시보 두 개가 돈다. 먼저 openclaw gateway status로 종 장치가 켜져 있는지, 그다음 runs --id로 기록이 있는지 본다 → 예약이 없는 건지, 스케줄러가 멈춘 건지 갈린다.

직접 해보기

내가 매일 손으로 하는 반복 확인 하나를 고르세요(예: "오늘 회의 목록 정리"). 그걸 cron 표기식 한 줄로 적어 보고(예: 평일 오전 8시 → 0 8 * * 1-5), 같은 걸 "사람의 문장" 한 줄로도 적어 봐요. 그다음 5편의 권한 기준 메모를 꺼내, 이 예약이 실행될 때 에이전트가 어느 권한 모드로 도는지 확인해요. 예약은 내가 안 볼 때 실행되니, 권한 경계가 대화 때보다 더 중요해요. 이런 자동화 흐름을 화면으로 짜는 다른 도구는 n8n에서 봤어요. 어느 쪽이 내 일에 맞는지는 "대화로 시킬 일인가, 그림으로 그릴 일인가"로 갈려요.

  1. 스케줄러 — 정해진 시각이나 간격에 맞춰 일을 시작시키는 프로그램 부품. ↩
  2. SQLite — 서버 없이 파일 하나로 동작하는 작은 데이터베이스로, 3편에서 세션 기록의 저장소로 봤어요. ↩
  3. 웹훅 — 어떤 일이 생겼을 때 미리 정해 둔 주소로 알림을 보내는 방식으로, n8n의 IF 노드 글에서 다뤘어요. ↩
  4. UTC — 시간대에 상관없이 전 세계가 공통으로 쓰는 기준 시각으로, 한국 시각보다 9시간 느려요. ↩
  5. ISO 시각 — 2026-09-04T09:30:00Z처럼 날짜와 시각을 국제 표준 형식으로 적은 것. ↩
  6. CLI — 터미널에서 글자 명령으로 프로그램을 다루는 방식으로, 터미널·셸·커널·프롬프트 차이에서 처음 다뤘어요. ↩
