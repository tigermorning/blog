어디에 쓰나
학습 시간 평균처럼 반복 계산하는 값을 노트북 셀에 코드로 남기기 · 답을 아는 계산(print(37+5))으로 연결 전체를 검증하기 · 계산 기준을 텍스트 셀에 적어 숫자 옆에 남기기 · 연결이 멈춘 위치를 단계별로 좁혀 찾기

9편까지는 판단을 문서로 남겼어요. 주간 보고서를 쓰고, 그 판단 기준을 SKILL.md에 적고, 다음 주에도 같은 기준이 적용되는지 확인했죠. 그런데 팀원이 이런 말을 꺼냈다고 해 볼게요. "앞으로는 학습 시간 같은 기록도 모아서 평균을 보고 싶어요. 어떤 값을 어떻게 계산했는지 나중에 다시 확인할 수 있게 남겨 주세요."

보고서에 "평균 30분"이라고 적힌 문장 하나만 남으면, 석 달 뒤에 그 30분이 어떤 값을 어떻게 나눈 결과인지 아무도 못 되짚어요. 그래서 이번 편에는 문서 대신 돌려 볼 수 있는 형태가 등장해요. 브라우저에서 노트북을 쓰고 Python을 실행하는 환경이 Colab이고, 여기에 2편에서 배운 MCP2 방식으로 에이전트를 붙이는 게 이번 편의 일이에요.

먼저 말 두 개만 풀고 갈게요. 노트북의 한 칸을 셀3이라고 불러요. Python을 적는 코드 셀과 제목·설명을 적는 텍스트 셀이 있고, 코드 셀을 실행하면 그 칸 바로 아래에 출력이 붙어요. 그리고 그 코드를 실제로 계산해 주는 자리를 런타임4이라고 해요. 이 둘이 다른 곳이라는 게 이번 편에서 제일 중요한 이야기예요.

비유 하나 — 요리 교실의 레시피 공책과 가스레인지

요리 교실을 하나 그려 볼게요. 저는 강의실에 앉아 있고, 주방은 유리벽 너머에 있어요. 벽에는 레시피 공책이 한 권 걸려 있고, 공책은 칸칸이 나뉘어 있어서 한 칸에 한 단계씩 적게 돼 있어요. 주방 안에는 가스레인지 앞에 선 요리사가 있고요.

저는 주방에 직접 못 들어가요. 대신 심부름꾼에게 부탁합니다. "공책 새 칸에 당근 세 개를 썬다라고 적어 줘"라고 하면 심부름꾼이 가서 그 줄을 적어요. 그렇다고 당근이 썰리진 않죠. 당근이 썰리려면 "그 칸에 적힌 대로 실제로 해 줘"라고 한 번 더 말해야 하고, 그제서야 요리사가 칼을 잡아요.

비유 속 요소원래 개념
강의실에 앉은 나내가 말을 거는 Claude Code 또는 OpenCode — 내 컴퓨터에서 도는 에이전트
주방을 오가는 심부름꾼Colab MCP 서버 — 이것도 내 컴퓨터에서 돌아요
벽에 걸린 레시피 공책Chrome 탭에 열려 있는 Colab 노트북 문서
공책의 한 칸셀 — 코드 셀 또는 텍스트 셀
가스레인지 앞의 요리사Colab 런타임의 Python — 계산이 실제로 일어나는 곳
"공책 새 칸에 이 줄을 적어 줘"셀 추가 — 노트북 문서가 바뀐다
"그 칸에 적힌 대로 실제로 해 줘"셀 실행 — 런타임에 계산을 시킨다
적기만 하고 아직 아무것도 안 익은 상태코드는 저장됐지만 런타임에는 아무 값도 없는 상태

핵심 한 줄: 적는 것과 익히는 것은 다른 일이에요 — 그래서 에이전트에게 시킬 때도 "셀을 만들어 줘"와 "그 셀을 실행해 줘"는 서로 다른 부탁이에요.

다만 여기서 비유가 끊기는 점이 하나 있어요. 진짜 요리사라면 공책에 새 줄이 적히는 걸 보고 알아서 움직일 수도 있어요. 그런데 런타임은 절대 스스로 읽지 않아요. 누군가 그 셀을 실행하기 전까지는, 공책에 뭐가 적혔든 주방 쪽에서는 아무 일도 일어나지 않아요.

전체 흐름 그림 — 내 컴퓨터에서 Colab 런타임까지 네 단계

제 말 한마디가 실제 계산에 닿기까지 네 곳을 거쳐요. 이 네 곳이 각각 어디서 도는지, 그리고 이따 나올 두 개의 Connect 버튼이 각각 어느 사이를 잇는지를 한 장에 그렸어요.

읽는 법: 세로 실선은 내 말 한마디가 흘러가는 길이고, 화살표 옆의 글씨는 그 단계에서 무엇이 넘어가는지예요. 왼쪽의 점선 상자 두 개가 이번 편에서 제일 헷갈리는 부분인데, 이름이 똑같이 Connect인 버튼 두 개가 서로 다른 사이를 잇는다는 뜻이에요. 맨 아래 두 상자는 어디까지 가느냐의 차이고요 — 부탁하는 말 한 줄에 따라 ③에서 멈추기도 하고 ④까지 가기도 해요.

①과 ②가 둘 다 내 컴퓨터라는 점도 눈여겨보세요. 3편에서 직접 만들어 본 업무 기록 서버가 그랬듯, MCP 서버는 먼 어딘가의 서비스가 아니라 내 컴퓨터에서 도는 프로그램일 수 있어요. Colab MCP 서버가 딱 그래요. 대신 이 서버가 브라우저 탭 하나를 붙잡고 그 안의 노트북을 조작한다는 게 지금까지와 다른 점이에요.

준비물 — Chrome과 내 컴퓨터의 실행 환경

준비물은 두 갈래예요. 브라우저 쪽은 Chrome을 권해요(승인 창부터 셀 실행까지 확인된 환경이에요). 실습에 쓸 Google 계정으로 미리 로그인해 두세요.

내 컴퓨터 쪽은 MCP 서버를 돌릴 환경이에요. Colab MCP 프로그램은 Python 3.13 이상을 요구하는데, 이건 노트북 안에서 돌 Python 버전이 아니라 내 컴퓨터에서 MCP 서버를 띄울 Python 버전이에요. 그리고 uv로 환경을 준비하고 uvx로 실행해요 — uvx는 도구가 필요한 패키지를 별도 환경에 알아서 설치하고 실행해 주는 명령이라, 내 컴퓨터를 어지럽히지 않고 도구 하나만 굴릴 때 편해요. Git도 필요하고요. uv와 가상 환경 이야기는 3편에서 서버를 만들 때 이미 한 번 나왔어요.

설치와 등록까지는 지금 쓰는 도구에 그대로 부탁하는 게 빨라요.

Colab에 연결해 줘.

이때 처음에는 open_colab_browser_connection이라는 연결용 도구 하나만 보일 수 있어요. 이 도구가 하는 일은 계산이 아니라 Colab 탭을 열어서, 지금 도는 로컬 서버와 그 노트북이 이어질 기회를 만드는 것이에요.

그러면 브라우저 가운데에 "Connect to a local Colab MCP server"라는 승인 창이 떠요. 여기서 제가 승인하는 대상은 로컬 MCP 서버와 이 노트북의 연결이고, 안내에는 한 로컬 MCP 서버에 노트북 세션5 하나를 연결한다는 설명이 붙어 있어요.

문제는 Colab 화면 오른쪽 위에도 Connect라는 버튼이 하나 더 있다는 거예요. 이름이 똑같아서 "아까 눌렀는데 왜 또?" 싶어지는데, 둘은 아예 다른 일을 해요.

어느 Connect어디에 있나무엇과 무엇을 잇나누르면 가능해지는 것
런타임 연결Colab 화면 오른쪽 위노트북 ↔ 코드를 실행할 런타임코드 셀을 실행할 수 있는 상태가 된다

핵심: 위 칸은 주방에 불을 켜는 일이고, 아래 칸은 심부름꾼에게 이 공책을 맡기는 일이에요. 둘 다 눌러야 "에이전트가 셀을 만들고, 그 셀이 실제로 계산된다"가 성립해요.

참고로 Colab 화면 오른쪽에 보이는 Gemini 패널은 Colab에 딸린 별도의 AI 대화 화면이에요. 이번 실습의 요청은 거기가 아니라 내 컴퓨터의 Claude Code나 OpenCode에 넣는 거라, 헷갈리지 마세요.

연결하고 나면 도구 목록 자체가 바뀐다

연결 전후로 서버가 내주는 도구 목록이 달라질 수 있어요. 연결 전에는 "연결해 줘" 하나뿐이었는데, 연결 뒤에는 "셀을 추가해 줘", "셀을 실행해 줘" 같은 도구들이 새로 나타나는 식이죠. 이렇게 상황에 따라 목록이 바뀌는 걸 동적 도구 목록6이라고 해요. 이때 서버는 호스트에게 "도구 목록이 바뀌었다"는 알림을 보내고, 호스트가 그 알림을 받아 목록을 다시 읽어야 새 도구가 보여요.

그래서 공식 Colab MCP 안내는 도구 목록 변경 알림을 지원하는 호스트를 요구하고, 지원 예시에 Claude Code가 들어 있어요. 5편에서 "도구가 많아지면 문맥이 무거워진다"며 목록을 다루는 이야기를 했는데, 여기서는 목록이 고정된 게 아니라는 사실이 새로 붙는 셈이에요.

연결이 됐으면 계산을 시키기 전에 지금 붙잡고 있는 게 어느 노트북인지부터 확인해요.

실행: Colab 노트북 셀에 붙여넣기 — 에이전트가 대신 넣어 주지만, 손으로 넣어 봐도 같은 결과예요

print(37 + 5)

예상되는 출력은 42예요. 여기서 에이전트는 도구를 두 번 부릅니다 — add_code_cell로 코드를 담은 셀을 추가하고, run_code_cell로 그 셀을 실행해요. 첫 호출은 노트북 문서에 쓰는 단계, 두 번째 호출은 Python 계산을 요청하는 단계고요. 흐름 그림의 ③과 ④가 그대로 도구 두 개로 나뉘어 있는 거예요.

왜 하필 이렇게 시시한 덧셈이냐면, 답을 미리 알고 있는 계산이라야 검증이 되기 때문이에요. 42가 아니라 다른 게 나오거나 아무것도 안 나오면, 계산이 틀린 게 아니라 어딘가 연결이 끊긴 거예요. 확인할 건 세 가지예요.

  • 요청한 코드가 셀에 생겼는지 — ③까지 갔는가
  • 그 셀이 실행됐는지 — ④까지 갔는가
  • 셀 아래 출력이 예상값과 같은지 — 42인가

입력을 바꿔 보며 계산의 근거 읽기

연결이 확인됐으니 처음의 부탁으로 돌아가요. 학습 시간의 평균이요. 기록이 20분, 30분, 40분 세 번이라면 합계는 90분, 기록 수는 3개, 평균은 30분이에요.

실행: Colab 노트북 셀에 붙여넣기 — 위 검증 셀 아래에 새 셀로 넣으세요

minutes = [20, 30, 40]
average = sum(minutes) / len(minutes)
print(average)

줄별로 읽어 볼게요. 첫 줄의 대괄호는 여러 값을 차례로 담는 리스트7예요. sum(minutes)는 그 값을 다 더한 합(90), len(minutes)는 기록의 개수(3), /로 나누면 30이 나와요. 다만 Python은 나눗셈 결과를 소수로 다루는 편이라 화면에는 30.0처럼 찍힐 수 있어요 — 틀린 게 아니에요.

여기서 손으로 먼저 적어 보는 연습을 하나 권해요. 마지막 값 40을 70으로 바꾸기 전에, 바뀐 합계·기록 수·예상 평균을 종이에 먼저 적어 두는 거예요. 그다음 실행해서 맞춰 보세요. 이렇게 하면 코드가 내가 이해한 대로 도는지를 매번 확인하게 돼요.

Colab이 대신 정해 주지 않는 것

그런데 여기서 진짜 중요한 질문이 하나 남아요. 30분은 무엇의 평균일까요?

정확히 말하면 "기록이 남은 세 번"의 평균이에요. 일주일이 7일인데 기록은 3일치뿐이라면, 나머지 4일을 0분으로 보고 7로 나눌 수도 있어요. 그러면 90 ÷ 7 = 약 12.9분이 나와요. 30분과 12.9분, 둘 다 계산은 정확해요. 다른 건 계산이 아니라 "기록 없는 날을 어떻게 볼 것인가"라는 기준이거든요.

Colab은 제가 고른 계산을 실행해 줄 뿐이에요. 숫자만 보고 "기록이 없는 날은 이렇게 다뤄야 한다"까지 정해 주지는 않아요. 이건 6편에서 "같은 기록인데 판정이 갈린다"고 했던 것과 같은 자리예요 — 도구는 규칙을 실행하고, 규칙은 사람과 팀이 정한다는 이야기요.

덧붙여 실무에서 자주 걸리는 함정 하나요. 아직 기록이 하나도 없어서 리스트가 비어 있으면 len(minutes)가 0이라 위 코드는 0으로 나누게 돼요. 여기서 곧장 "오류 처리 코드를 길게 붙이자"로 가기 쉬운데, 그 전에 정할 게 있어요 — "자료가 없음"을 보고서에 어떻게 표시할 것인가요. 0분이라고 쓸지, "기록 없음"이라고 쓸지, 아예 그 주를 빼고 낼지를 먼저 정하면 코드는 그다음에 따라와요.

나쁜 선택 vs 좋은 선택 — 요리 교실에서

나쁜 선택좋은 선택
공책에 줄만 적어 놓고 "다 됐다"고 한다 = 셀만 추가하고 실행은 안 시킨다 → 셀 아래에 출력이 없는데 계산이 끝난 줄 안다. 적은 다음 "그대로 해 줘"까지 말한다 = 추가와 실행을 따로 시키고 → 셀 아래 출력이 생긴 것까지 눈으로 확인한다.
심부름꾼이 "적어 뒀어요"라고 하니 그냥 믿는다 = 연결된 노트북 이름과 셀 내용을 확인하지 않는다 → 열어 둔 다른 탭의 노트북을 만지고 있을 수 있다. 공책을 직접 올려다본다 = 노트북 이름·셀 내용을 화면과 맞춰 보고, 답을 아는 print(37 + 5)로 42까지 확인한다.
"안 나온 날은 알아서 처리해 줘"라고 맡긴다 = 기록 없는 날의 기준을 도구에 맡긴다 → 보고된 평균이 30분인지 12.9분인지 아무도 모르게 된다. "기록이 있는 날만 평균 낸다"를 사람이 먼저 정하고 → 그 기준을 텍스트 셀에 한 줄 적어 계산 셀 위에 둔다.
임시로 걸린 공책에 적고 그냥 나온다 = scratchpad 임시 노트북에 결과를 남긴 채 닫는다 → 다음에 열면 계산도 결과도 없다. 보관할 게 있으면 Copy to Drive로 내 드라이브에 복사하고 → 내용을 알아볼 수 있는 제목을 붙여 둔다.
주방 열쇠가 달린 쪽지를 게시판에 붙인다 = 연결 도구가 만든 주소 전체를 과제·채팅·캡처에 붙여넣는다 → 그 주소에 연결용 임시 값이 들어 있다. 주소는 브라우저에만 두고 = 공유할 땐 노트북 이름과 결과 화면만 남기고 → 주소창은 캡처에서 잘라 낸다.

보관과 다시 실행 — 위에서부터 순서대로

실행 결과 화면 위쪽에 Cannot save changes와 Copy to Drive가 보이면, 지금 열린 scratchpad 노트북이 임시라는 뜻이에요. 남길 게 있으면 Copy to Drive로 내 드라이브에 복사하고 제목을 제대로 붙이세요. "무제"로 쌓인 노트북은 한 달 뒤에 열어도 뭘 계산했는지 알 수 없거든요.

그리고 저장한 노트북을 나중에 다시 열 때 조심할 게 하나 있어요. 셀은 위에서부터 순서대로 실행하는 편이 안전해요. 첫 셀에서 minutes를 만들고 둘째 셀에서 평균을 냈다면, 새 런타임에서 둘째 셀만 덜컥 실행할 경우 minutes를 찾지 못해요. 문서에는 분명히 적혀 있는데 말이죠 — 이게 바로 맨 위 비유의 "적는 것과 익히는 것은 다르다"가 다시 나타나는 자리예요. 런타임이 새로 시작되면 주방은 텅 빈 상태로 되돌아가 있어요.

직접 해보기

이번 연습의 목적은 평균을 구하는 게 아니라, 계산의 근거를 남기는 자리를 만드는 것이에요.

① 두 부탁을 일부러 나눠서 해 보기. "셀을 하나 추가만 해 줘"까지만 시키고 화면을 확인하세요. 셀은 생겼는데 아래에 출력이 없는 상태를 눈으로 보는 게 목적이에요. 그다음에 "이제 그 셀을 실행해 줘"를 시키고, 무엇이 새로 생겼는지 한 줄로 적으세요.

② Connect 두 개를 표로 그려 보기. 이 글의 표를 보지 말고, 내 화면을 보면서 "어디에 있는 어떤 버튼이 무엇과 무엇을 잇는지"를 직접 적어 보세요. 헷갈린 쪽이 이따 문제가 생겼을 때 제일 먼저 의심할 자리예요.

③ 바꾸기 전에 예측 적기. minutes의 마지막 값을 70으로 바꾸기 전에 합계·개수·평균을 종이에 먼저 적고 실행하세요. 값이 다르면 어느 줄에서 제 예측이 틀렸는지를 찾으세요 — 이게 코드를 읽는 힘이 붙는 지점이에요.

④ 내 기준을 텍스트 셀에 적기. 계산 셀 바로 위에 텍스트 셀을 하나 만들고 "이 평균은 기록이 남은 날만 대상으로 한다"처럼 한 줄 적어 두세요. 숫자만 남은 노트북과, 기준이 같이 적힌 노트북은 석 달 뒤에 완전히 다른 물건이 돼요.

⑤ 런타임을 새로 시작해 보기. 두 번째 셀만 단독으로 실행해서 일부러 실패시켜 보세요. "문서에는 적혀 있는데 런타임은 모른다"를 직접 겪어 보는 것이 이 편의 핵심 감각이에요. 확인했으면 위에서부터 다시 실행하세요.

⑥ 보관 결정하기. 남길 게 있으면 Copy to Drive로 옮기고 제목을 붙이세요. 안 남길 거면 그냥 닫되, "이건 사라지는 노트북"이라는 걸 알고 닫는 것과 모르고 닫는 것은 달라요.

여기까지 하면 계산의 입력·과정·결과·기준이 한 문서에 나란히 남아요. 다음 편에서는 방향을 한 번 더 틀어서, 팀이 실제로 쓰는 공유 표(구글 스프레드시트)를 읽어 오는 준비를 합니다. 여기서 미리 짚어 둘 게 하나 있어요 — Colab에 로그인해 있다는 사실이 다른 앱의 접근 동의까지 대신해 주지는 않아요. 그래서 다음 편에서는 Google Workspace용 credential JSON을 새로 준비하는 절차부터 시작해요.

  1. 노트북(notebook) — 입력값·코드·실행 결과·설명을 한 문서 안에 칸 단위로 나란히 남길 수 있는 형식이며, Colab은 이 노트북을 브라우저에서 쓰고 실행하는 환경이에요. ↩
  2. MCP — 외부 자료나 기능을 도구 형태로 에이전트에 연결하는 공통 규약이며, 2편에서 호스트·클라이언트·서버 구조를, 4편에서 실제 연결을 다뤘어요. ↩
  3. 셀(cell) — 노트북을 이루는 한 칸으로, Python을 적는 코드 셀과 제목·설명을 적는 텍스트 셀이 있어요. ↩
  4. 런타임(runtime) — 노트북에 적힌 코드를 실제로 계산하고 그동안 만들어진 값을 들고 있는 자리이며, 새로 시작하면 이전에 만든 값이 모두 사라져요. ↩
  5. 세션(session) — 지금 로컬 MCP 서버와 이어져 있는 노트북 연결 하나를 가리키는 말이에요. ↩
  6. 동적 도구 목록 — 상황에 따라 서버가 내주는 도구 목록이 달라지는 것으로, 서버가 보내는 변경 알림을 호스트가 받아 목록을 다시 읽어야 새 도구가 보여요. ↩
  7. 리스트 — 대괄호 안에 여러 값을 순서대로 담는 파이썬 자료 형태로, 파이썬 코드 읽기에서 다른 기본 문법과 함께 처음 다뤘어요. ↩
