문제 1짝짓기

코드에서 용어 찾기

회원을 나타내는 아래 코드를 보고, 왼쪽 설명에 맞는 용어(클래스 · 인스턴스 · 속성 · 메서드)와 코드에서 그것이 가리키는 것을 각각 적어 보세요.

class User:                                   # User 클래스를 정의해 주세요
    def __init__(self, name):                 # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
    def greet(self):                          # greet 메서드를 정의해 주세요
        return "안녕하세요, " + self.name     # 인사말을 만들어 돌려주세요
u = User("민지")                              # u 에 이름이 "민지" 인 User 를 만들어 담아 주세요
print(u.greet())                              # u 의 인사말을 화면에 보여 주세요
print(u.name)                                 # u 의 name 을 화면에 보여 주세요

설계는 class로 정의한 것이고, 그 설계에 ()를 붙여 부른 결과가 실제 객체예요. 점(.) 뒤에 괄호가 있으면 동작, 괄호가 없으면 값이에요.

헷갈리기 쉬운 곳

  • “클래스로 만든 값”은 인스턴스 또는 객체라고 불러요. 두 말은 거의 같은 뜻으로 쓰여요.
  • self.name은 메서드 안에서 쓰는 이름이고, 바깥에서는 인스턴스 이름으로 바꿔 u.name이라고 불러요.

핵심 한 줄: 클래스는 설계, 인스턴스는 그 설계로 만든 객체, 속성은 객체가 가진 값, 메서드는 객체에게 시키는 동작이에요.

문제 2빈칸 채우기

__init__ 정리하기

아래 코드를 실행했을 때 __init__이 어떻게 쓰이는지 빈칸 ① ~ ⑤를 채워 정리해 보세요.

__init__은 ( ① ) 때 ( ② )가 자동으로 부르고, 인스턴스 하나당 ( ③ ) 번 실행된다. 하는 일은 ( ④ )이다. 아래 코드에서는 __init__이 모두 ( ⑤ ) 번 실행된다.

class User:                                   # User 클래스를 정의해 주세요
    def __init__(self, name):                 # 만들 때 불리는 __init__ 을 정의해 주세요
        print("만듦:", name)                  # "만듦:" 과 name 을 화면에 보여 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
a = User("민지")                              # a 에 이름이 "민지" 인 User 를 만들어 담아 주세요
b = User("준호")                              # b 에 이름이 "준호" 인 User 를 만들어 담아 주세요
c = a                                         # c 에 a 를 담아 주세요

헷갈리기 쉬운 곳

  • 변수에 옮겨 담거나 리스트에서 꺼내는 것은 새로 만드는 일이 아니에요.

핵심 한 줄: __init__은 인스턴스를 만들 때 파이썬이 한 번 불러 주는 “처음 값 정하기” 메서드예요.

문제 3빈칸 채우기

self 와 호출 모양

메서드는 정의할 때 self를 적는데, 부를 때는 적지 않아요. 이 차이를 아래 코드로 확인해 보세요. (1) 마지막 줄 빈칸에 들어갈 것을 쓰고, (2) 이 줄이 hero.take_hit(30)과 같은 일을 하는 이유를 self라는 말을 써서 한 문장으로 설명해 보세요.

class Player:                                 # Player 클래스를 정의해 주세요
    def __init__(self, name, health):         # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
        self.health = health                  # 이 인스턴스의 health 에 health 를 담아 주세요
    def take_hit(self, damage):               # take_hit 메서드를 정의해 주세요
        self.health = max(0, self.health - damage)  # health 를 damage 만큼 줄이되 0 밑으로는 안 내려가게 해 주세요
        return self.health                    # 줄어든 health 를 돌려주세요
hero = Player("elon", 100)                    # hero 에 체력 100 인 Player 를 만들어 담아 주세요
print(hero.take_hit(30))                      # hero 가 30 의 피해를 입은 뒤 체력을 화면에 보여 주세요
print(Player.take_hit(____, 30))              # (1) self 자리에 hero 를 직접 넘겨 30 의 피해를 입힌 뒤 체력을 보여 주세요

  • 부를 때 hero.take_hit(hero, 30)처럼 self를 또 적으면 값이 너무 많아서 TypeError가 나요.

핵심 한 줄: hero.take_hit(30)은 Player.take_hit(hero, 30)을 줄여 쓴 모양이고, self는 그 hero예요.

문제 4빈칸 채우기

클래스에 적은 값과 내 값

클래스에 적은 값과 인스턴스가 따로 저장한 값이 어떻게 읽히는지, 빈칸 ① ~ ⑥을 채워 정리해 보세요.

a.power를 읽을 때 a에 power가 따로 저장돼 있으면 ( ① ) 값을, 없으면 ( ② ) 값을 읽는다. self.power += 5는 ( ③ )의 power에 새 값을 저장한다. 그래서 아래 코드를 실행한 뒤 a.power는 ( ④ ), b.power는 ( ⑤ ), Hero.power는 ( ⑥ )이다.

class Hero:                                  # Hero 클래스를 정의해 주세요
    power = 10                                # 클래스 변수 power 에 10 을 담아 주세요
    def train(self):                          # train 메서드를 정의해 주세요
        self.power += 5                       # 이 인스턴스의 power 에 5 를 더해 주세요
a = Hero()                                    # a 에 Hero 인스턴스를 만들어 담아 주세요
b = Hero()                                    # b 에 Hero 인스턴스를 만들어 담아 주세요
a.train()                                     # a 에게 훈련을 시켜 주세요
print(a.power, b.power, Hero.power)           # a, b, 클래스의 power 를 화면에 보여 주세요

헷갈리기 쉬운 곳

  • “클래스에 적은 변수는 모든 인스턴스가 같이 쓴다”는 말은 읽을 때만 맞아요. self.이름 = 값으로 저장하는 순간 그 인스턴스만의 값이 생겨요.

핵심 한 줄: 읽을 때는 자기 값이 먼저이고 없으면 클래스 값이에요. 저장하면 그 인스턴스만의 값이 생겨요.

문제 5객관식

상속을 써도 되는 관계

상속은 “자식은 부모의 한 종류다”(자식 is a 부모)로 읽어서 말이 될 때 써요. 아래 네 가지 중 상속으로 만들기에 어색한 것을 고르고, 두 번째로 t.start()를 부를 때 파이썬이 이름을 찾는 순서를 적어 보세요.

class Vehicle:                                # Vehicle 클래스를 정의해 주세요
    def start(self):                          # start 메서드를 정의해 주세요
        return "시동"                         # "시동" 을 돌려주세요
class Truck(Vehicle):                         # Vehicle 을 상속받는 Truck 클래스를 정의해 주세요
    def load(self):                           # load 메서드를 정의해 주세요
        return "적재"                         # "적재" 를 돌려주세요
t = Truck()                                   # t 에 Truck 인스턴스를 만들어 담아 주세요
print(t.start(), t.load())                    # t 의 start 와 load 결과를 화면에 보여 주세요

왜 이런 답이 나올까요

“관리자는 사용자다”(①), “저축 계좌는 계좌다”(②), “트럭은 탈것이다”(④)는 말이 되지만, ③ “사용자는 관리자다”는 말이 안 돼요. 관리자는 사용자의 한 종류이므로 부모는 User이고 자식이 AdminUser여야 해요. 이름은 인스턴스 → 자식 클래스 → 부모 클래스 순서로 올라가며 찾고, start는 Truck에 없어서 Vehicle에서 찾아요.

헷갈리기 쉬운 곳

  • 괄호 안에 부모를 적어요. 부모와 자식을 거꾸로 적으면 모든 사용자가 관리자의 기능을 물려받는 이상한 구조가 돼요.
  • 코드를 재사용하고 싶다는 이유만으로 상속하면 이름만 어색해지고 불필요한 것까지 물려받아요.

핵심 한 줄: 상속은 “자식은 부모의 한 종류다”가 말이 될 때만 쓰고, 이름은 인스턴스 → 자식 → 부모 순서로 찾아요.

문제 6결과 예측

게임 속 인물 만들기

class Player:                                 # Player 클래스를 정의해 주세요
    def __init__(self, name, health, skill):  # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
        self.health = health                  # 이 인스턴스의 health 에 health 를 담아 주세요
        self.skill = skill                    # 이 인스턴스의 skill 에 skill 을 담아 주세요
        self.xp = 0                           # 이 인스턴스의 xp 에 0 을 담아 주세요
    def say_hello(self):                      # say_hello 메서드를 정의해 주세요
        return "안녕, 나는 " + self.name      # 인사말을 만들어 돌려주세요
    def take_hit(self, damage):               # take_hit 메서드를 정의해 주세요
        self.health = max(0, self.health - damage)  # health 를 damage 만큼 줄이되 0 밑으로는 안 내려가게 해 주세요
        return self.health                    # 줄어든 health 를 돌려주세요

print(p.take_hit(30))                         # p 가 30 의 피해를 입은 뒤 체력을 화면에 보여 주세요
print(p.take_hit(90))                         # p 가 90 의 피해를 입은 뒤 체력을 화면에 보여 주세요
print(p.xp, p.health)                         # p 의 xp 와 health 를 화면에 보여 주세요

왜 이런 답이 나올까요

체력 100에서 30을 맞아 70, 다시 90을 맞으면 -20이 되어야 하지만 0 밑으로는 내려가지 않게 해서 0이에요. xp는 값을 받지 않고 __init__에서 항상 0으로 저장하니 0 그대로예요. 위 코드가 한 가지 정답이에요.

헷갈리기 쉬운 곳

  • take_hit이 값을 돌려주지 않으면 print(p.take_hit(30))이 None을 보여 줘요.

        return super().intro() + ", 회사: " + self.company  # 부모의 소개 뒤에 회사를 붙여 돌려주세요
e = Employee("민지", "한빛전자")              # e 에 민지, 한빛전자 직원을 만들어 담아 주세요
print(e.intro())                              # e 의 소개를 화면에 보여 주세요

지금은 이렇게 오류가 나요.

AttributeError: 'Employee' object has no attribute 'name'

기대 출력:

이름: 민지, 회사: 한빛전자
힌트 보기

오류 문장의 “no attribute ‘name’”을 보세요. name은 어느 클래스의 __init__이 저장하나요? 그 __init__은 지금 실행되고 있나요?

정답·해설 보기

고친 코드와 실행 결과예요.

class Person:                                 # Person 클래스를 정의해 주세요
    def __init__(self, name):                 # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
    def intro(self):                          # intro 메서드를 정의해 주세요
        return "이름: " + self.name           # 이름 소개 글자를 만들어 돌려주세요
class Employee(Person):                       # Person 을 상속받는 Employee 클래스를 정의해 주세요
    def __init__(self, name, company):        # Employee 의 __init__ 을 정의해 주세요
        super().__init__(name)                # 부모 Person 의 __init__ 을 name 으로 불러 주세요
        self.company = company                # 이 인스턴스의 company 에 company 를 담아 주세요
    def intro(self):                          # intro 메서드를 다시 정의해 주세요
        return super().intro() + ", 회사: " + self.company  # 부모의 소개 뒤에 회사를 붙여 돌려주세요
e = Employee("민지", "한빛전자")              # e 에 민지, 한빛전자 직원을 만들어 담아 주세요
print(e.intro())                              # e 의 소개를 화면에 보여 주세요
이름: 민지, 회사: 한빛전자

왜 이런 답이 나올까요

Employee가 자기 __init__을 다시 적었기 때문에 부모 Person.__init__은 자동으로 실행되지 않고, name이 저장되지 않아요. intro가 부모의 intro를 불러 self.name을 읽는 순간 AttributeError가 나요. Employee.__init__ 안에 super().__init__(name)을 넣으면 해결돼요.

헷갈리기 쉬운 곳

  • 오류는 Employee(...)를 만드는 줄이 아니라 e.intro()에서 나요. 만드는 줄만 봐서는 문제가 보이지 않아요.

핵심 한 줄: 자식 클래스에 __init__을 적으면 super().__init__(...)으로 부모의 __init__도 불러야 해요.

문제 12코드 쓰기

상품 가격 계산

쇼핑몰에서 일반 상품과 할인 상품의 최종 가격을 계산해요. 아래 조건에 맞는 두 클래스를 직접 써 보세요.

  • Product(name, price) — 이름과 가격을 저장하고, final_price()는 가격을 그대로 돌려줘요.
  • SaleProduct(name, price, rate) — Product를 물려받아요. 할인율 rate(0~1)도 저장하고, final_price()는 부모의 final_price()에서 할인율만큼 깎은 값을 int로 돌려줘요.
  • 아래 실행 줄은 두 종류를 같은 방식으로 다뤄요. 새 상품 종류가 생겨도 이 반복문은 고치지 않아도 되게 만들어 보세요.
class Product:
    pass


class SaleProduct(Product):
    pass


items = [Product("노트", 3000), SaleProduct("펜", 2000, 0.25)]
total = 0
for item in items:
    total += item.final_price()
print(total)

기대 출력:

4500
힌트 보기

할인 상품의 __init__은 이름과 가격을 부모에게 맡기고 할인율만 자기가 저장해요. final_price는 같은 이름으로 다시 적고, 안에서 super().final_price()로 부모 값을 받아 와요.

정답·해설 보기

정답 코드(한 가지 예)와 실행 결과예요.

class Product:                                # Product 클래스를 정의해 주세요
    def __init__(self, name, price):          # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 인스턴스의 name 에 name 을 담아 주세요
        self.price = price                    # 이 인스턴스의 price 에 price 를 담아 주세요
    def final_price(self):                    # final_price 메서드를 정의해 주세요
        return self.price                     # price 를 그대로 돌려주세요
class SaleProduct(Product):                   # Product 를 상속받는 SaleProduct 클래스를 정의해 주세요
    def __init__(self, name, price, rate):    # SaleProduct 의 __init__ 을 정의해 주세요
        super().__init__(name, price)         # 부모의 __init__ 을 name, price 로 불러 주세요
        self.rate = rate                      # 이 인스턴스의 rate 에 rate 를 담아 주세요
    def final_price(self):                    # final_price 메서드를 다시 정의해 주세요
        return int(super().final_price() * (1 - self.rate))  # 부모의 가격에서 할인율만큼 깎아 정수로 돌려주세요
items = [Product("노트", 3000), SaleProduct("펜", 2000, 0.25)]  # items 에 일반 상품과 할인 상품을 담아 주세요
total = 0                                     # total 에 0 을 담아 주세요
for item in items:                            # items 의 상품을 하나씩 item 으로 꺼내 주세요
    total += item.final_price()               # total 에 item 의 최종 가격을 더해 주세요
print(total)                                  # total 을 화면에 보여 주세요
4500

왜 이런 답이 나올까요

노트는 3000, 펜은 2000에서 25%를 깎은 1500이라서 합계가 4500이에요. 반복문은 item이 어느 종류인지 따지지 않고 final_price()만 불러요. 각 인스턴스가 자기 클래스의 final_price를 알아서 쓰기 때문에, 새 상품 종류는 클래스만 추가하면 이 반복문을 고치지 않아도 돼요.

헷갈리기 쉬운 곳

  • 종류마다 if로 나눠 계산하면 새 종류가 생길 때마다 반복문을 고쳐야 해요.

핵심 한 줄: 같은 이름의 메서드를 클래스마다 다르게 적으면, 부르는 쪽 코드는 종류를 몰라도 돼요.
