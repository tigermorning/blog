7.1 클래스와 인스턴스

7.1 · 1객관식

클래스와 인스턴스의 관계

붕어빵 틀(클래스)과 틀로 구운 붕어빵(인스턴스)에 대한 설명 중 맞는 것을 하나 고르세요.

  1. ① 클래스는 설계이고, 인스턴스는 그 설계로 만든 실물이에요.
  2. ② 클래스와 인스턴스는 같은 말이에요.
  3. ③ 인스턴스가 모여서 클래스를 만들어요.
  4. ④ 클래스 하나로는 인스턴스를 하나만 만들 수 있어요.

핵심 한 줄: 클래스는 설계, 인스턴스는 그 설계로 만든 실물이에요.

__init__ 은 언제 불릴까

아래 코드가 출력하는 세 줄을 순서대로 적어 보세요. __init__이 실행되는 때를 맞히는 문제예요.

class Tea:                       # Tea 클래스를 정의해 주세요
    def __init__(self):          # 만들 때 자동으로 불리는 __init__ 을 정의해 주세요
        print("끓이는 중")       # "끓이는 중" 을 화면에 보여 주세요
print("시작")                    # "시작" 을 화면에 보여 주세요
t = Tea()                        # t 에 Tea 인스턴스를 만들어 담아 주세요
print("끝")                      # "끝" 을 화면에 보여 주세요

왜 이런 답이 나올까요

class 줄을 지나갈 때는 틀만 만들어지고 __init__은 실행되지 않아요. t = Tea()로 인스턴스를 만드는 순간 파이썬이 __init__을 자동으로 불러서 “끓이는 중”이 나와요.

헷갈리기 쉬운 곳

  • __init__은 우리가 직접 부르지 않아요. 인스턴스를 만들 때 한 번만 자동으로 불려요.

핵심 한 줄: __init__은 클래스()로 인스턴스를 만드는 순간 자동으로 한 번 불려요.

붕어빵 가게와 파이썬 짝짓기

왼쪽 붕어빵 가게 요소에 맞는 파이썬 용어를 클래스 · 인스턴스 · 속성 · 메서드 중에서 골라 짝지어 보세요. (아래 코드의 Bungeoppang 클래스를 보고 답해요.)

class Bungeoppang:                        # Bungeoppang 클래스를 정의해 주세요

x = Bungeoppang("팥")                     # x 에 팥 붕어빵을 만들어 담아 주세요

7.2 변수와 메서드

클래스에 적은 값과 인스턴스의 값이 어떻게 다른지, self가 무엇을 가리키는지 확인해요.

7.2 · 1객관식

self 는 무엇을 가리킬까

아래 코드에서 a.toggle()을 부를 때 toggle 메서드 안의 self가 가리키는 것을 하나 고르세요.

class Lamp:                      # Lamp 클래스를 정의해 주세요
    def __init__(self):          # 만들 때 불리는 __init__ 을 정의해 주세요
        self.on = False          # 이 램프의 on 에 False 를 담아 주세요
    def toggle(self):            # toggle 메서드를 정의해 주세요
        self.on = not self.on    # 이 램프의 on 을 반대로 바꿔 담아 주세요
a = Lamp()                       # a 에 Lamp 인스턴스를 만들어 담아 주세요
b = Lamp()                       # b 에 Lamp 인스턴스를 만들어 담아 주세요
a.toggle()                       # a 를 켜고 꺼 주세요
print(a.on, b.on)                # a 와 b 의 on 을 화면에 보여 주세요
  1. ① Lamp 클래스
  2. ② 메서드를 부른 인스턴스 a
  3. ③ 만들어진 모든 Lamp 인스턴스
  4. ④ on 변수
힌트 보기

a.toggle()을 부르면 파이썬이 self 자리에 점 앞의 값을 넣어 줘요. 실행 결과에서 b의 on이 바뀌었는지도 보세요.

정답·해설 보기

정답: ②

실행하면 이렇게 나와요.

True False

왜 이런 답이 나올까요

self는 메서드를 부른 인스턴스 자신이에요. a.toggle()이니 self는 a이고, 그래서 a.on만 True가 되고 b.on은 False 그대로예요.

헷갈리기 쉬운 곳

  • b.toggle()을 부르면 같은 코드가 실행되지만 이번에는 self가 b예요.

핵심 한 줄: self는 그 메서드를 부른 인스턴스 자신이에요.

7.2 · 2결과 예측

클래스 변수와 자기 값

클래스에 적은 count = 0과 메서드 안의 self.count += 1이 만나면 값이 어떻게 될까요? 출력을 적어 보세요.

class Counter:                   # Counter 클래스를 정의해 주세요
    count = 0                    # 클래스 변수 count 에 0 을 담아 주세요
    def hit(self):               # hit 메서드를 정의해 주세요
        self.count += 1          # 이 인스턴스의 count 에 1 을 더해 주세요
a = Counter()                    # a 에 Counter 인스턴스를 만들어 담아 주세요
b = Counter()                    # b 에 Counter 인스턴스를 만들어 담아 주세요
a.hit()                          # a 에게 hit 을 시켜 주세요
a.hit()                          # a 에게 hit 을 한 번 더 시켜 주세요
b.hit()                          # b 에게 hit 을 시켜 주세요
print(a.count, b.count, Counter.count)  # a, b, 클래스의 count 를 화면에 보여 주세요
출력내 답
출력?
힌트 보기

self.count += 1은 읽은 값에 1을 더해서 그 인스턴스 자신의 변수로 저장해요. 틀(클래스)의 count는 바뀌지 않아요.

정답·해설 보기

실행하면 이렇게 나와요.

2 1 0

왜 이런 답이 나올까요

a.hit()을 두 번 했으니 a는 자기 count를 갖고 2가 돼요. b는 한 번 해서 1이에요. 틀에 적힌 Counter.count는 한 번도 바뀌지 않아 0이에요.

헷갈리기 쉬운 곳

  • “클래스에 적은 변수는 모든 인스턴스가 같이 쓴다”고 생각하기 쉬워요. 읽을 때는 같이 쓰지만, self.이름 = 값으로 저장하는 순간 그 인스턴스만의 값이 돼요.

핵심 한 줄: self.변수 = 값을 하면 그 인스턴스만의 값이 생기고, 클래스에 적힌 값은 그대로예요.

7.2 · 3OX

self 를 직접 넘겨야 할까

메서드를 부를 때 a.hit(a)처럼 self 자리에 인스턴스를 직접 적어 줘야 한다. ○ 또는 ✕로 답하세요.

class Counter:                   # Counter 클래스를 정의해 주세요
    def hit(self):               # hit 메서드를 정의해 주세요
        print("hit")             # "hit" 을 화면에 보여 주세요
a = Counter()                    # a 에 Counter 인스턴스를 만들어 담아 주세요
a.hit(a)                         # a 에게 hit 을 시키면서 a 를 직접 넘겨 주세요
힌트 보기

hit(self)가 받는 값은 self 하나뿐인데, 부르는 쪽에서 몇 개를 넘기고 있는지 세어 보세요.

정답·해설 보기

정답: ✕ (오류가 나요)

실행하면 이렇게 나와요.

TypeError: Counter.hit() takes 1 positional argument but 2 were given

왜 이런 답이 나올까요

a.hit()만 써도 파이썬이 self 자리에 a를 넣어 줘요. 거기에 a를 또 적으면 값이 두 개가 넘어가서 TypeError가 나요.

헷갈리기 쉬운 곳

  • 정의할 때는 self를 적고, 부를 때는 적지 않아요. 둘이 서로 반대처럼 보이지만 같은 약속이에요.

핵심 한 줄: self는 정의할 때만 적고, 부를 때는 파이썬이 알아서 넣어 줘요.

7.3 상속

자식이 부모에게서 무엇을 물려받는지, super()가 언제 필요한지 확인해요.

7.3 · 1객관식

자식 클래스가 쓸 수 있는 메서드

아래 코드에서 b가 쓸 수 있는 메서드를 하나 고르세요.

class Animal:                    # Animal 클래스를 정의해 주세요
    def breathe(self):           # breathe 메서드를 정의해 주세요
        return "숨쉬기"          # "숨쉬기" 를 돌려주세요
class Bird(Animal):              # Animal 을 상속받는 Bird 클래스를 정의해 주세요
    def fly(self):               # fly 메서드를 정의해 주세요
        return "푸드덕"          # "푸드덕" 을 돌려주세요
b = Bird()                       # b 에 Bird 인스턴스를 만들어 담아 주세요
print(b.breathe(), b.fly())      # b 에게 숨쉬기와 날기를 시킨 결과를 화면에 보여 주세요
  1. ① fly()만
  2. ② breathe()만
  3. ③ breathe()와 fly() 모두
  4. ④ 하나도 못 써요
힌트 보기

자식은 부모의 메서드를 물려받고, 자기 것도 더해요.

부모도 자식의 메서드를 쓸 수 있을까

앞 문제의 Animal로 만든 인스턴스도 fly()를 쓸 수 있다. ○ 또는 ✕로 답하세요.

class Animal:                    # Animal 클래스를 정의해 주세요
    def breathe(self):           # breathe 메서드를 정의해 주세요
        return "숨쉬기"          # "숨쉬기" 를 돌려주세요
class Bird(Animal):              # Animal 을 상속받는 Bird 클래스를 정의해 주세요
    def fly(self):               # fly 메서드를 정의해 주세요
        return "푸드덕"          # "푸드덕" 을 돌려주세요
print(Animal().fly())            # Animal 인스턴스에게 날기를 시켜 주세요

물려주는 방향은 부모 → 자식이에요. fly는 어느 클래스에 적혀 있나요?

AttributeError: 'Animal' object has no attribute 'fly'

왜 이런 답이 나올까요

fly는 자식 Bird에만 있고 부모 Animal에는 없어요. 그래서 Animal()에게 fly()를 시키면 AttributeError가 나요.

헷갈리기 쉬운 곳

  • “학생은 사람이다”는 맞지만 “사람은 학생이다”는 아니에요. 같은 이치예요.

핵심 한 줄: 상속은 부모 → 자식 한 방향이에요.

7.3 · 3결과 예측

덮어쓰기와 super()

자식이 부모와 같은 이름의 메서드를 적고, 그 안에서 super()로 부모 것을 불러요. 출력 두 줄을 적어 보세요.

class Shop:                                     # Shop 클래스를 정의해 주세요
    def greet(self):                            # greet 메서드를 정의해 주세요
        return "어서 오세요"                    # "어서 오세요" 를 돌려주세요
class CheeseShop(Shop):                         # Shop 을 상속받는 CheeseShop 클래스를 정의해 주세요
    def greet(self):                            # greet 메서드를 다시 정의해 주세요
        return super().greet() + ", 치즈도 있어요"  # 부모의 인사 뒤에 문장을 붙여 돌려주세요
print(Shop().greet())                           # Shop 의 인사를 화면에 보여 주세요
print(CheeseShop().greet())                     # CheeseShop 의 인사를 화면에 보여 주세요

같은 이름이 자식에도 있으면 자식 것이 먼저 쓰여요. super().greet()는 부모의 greet를 불러요.

왜 이런 답이 나올까요

Shop().greet()는 부모 것만 실행해서 어서 오세요예요. CheeseShop().greet()는 자식 것이 먼저 쓰이고, 그 안의 super().greet()가 부모의 어서 오세요를 받아 뒤에 문장을 붙여요.

헷갈리기 쉬운 곳

  • super()가 없으면 부모 것은 쓰이지 않아요. 자식 것이 부모 것을 통째로 가려요.

핵심 한 줄: 같은 이름이면 자식 것이 먼저이고, 부모 것이 필요하면 super()로 불러요.

7.3 · 4결과 예측

부모의 __init__ 을 안 부르면

자식이 자기 __init__을 적었어요. 아래 코드를 실행하면 어떻게 될까요? 마지막 줄까지의 출력을 적어 보세요.

class Base:                      # Base 클래스를 정의해 주세요
    def __init__(self, name):    # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name         # 이 인스턴스의 name 에 name 을 담아 주세요
class Kid(Base):                 # Base 를 상속받는 Kid 클래스를 정의해 주세요
    def __init__(self, name):    # Kid 의 __init__ 을 정의해 주세요
        self.age = 3             # 이 인스턴스의 age 에 3 을 담아 주세요
k = Kid("민수")                  # k 에 이름이 "민수" 인 Kid 를 만들어 담아 주세요
print(k.age)                     # k 의 age 를 화면에 보여 주세요
print(k.name)                    # k 의 name 을 화면에 보여 주세요

자식에 __init__이 있으면 그것만 실행돼요. 부모의 __init__이 하던 일(name 저장)은 누가 하나요?

정답·해설 보기

실행하면 이렇게 나와요.

3
AttributeError: 'Kid' object has no attribute 'name'

왜 이런 답이 나올까요

Kid.__init__만 실행돼서 age는 만들어지지만 name은 만들어지지 않아요. 그래서 첫 print는 3을 보여 주고, 둘째 print에서 AttributeError가 나요. Kid.__init__ 안에 super().__init__(name)을 넣으면 해결돼요.

헷갈리기 쉬운 곳

  • 오류는 k = Kid("민수") 줄이 아니라 k.name을 읽는 줄에서 나요. 만들 때는 아무 문제가 없어 보여요.

핵심 한 줄: 자식에 __init__을 적으면 super().__init__(...)으로 부모 것도 불러야 해요.
