.env가 안 읽혔던 네 겹의 이유 — 강의 화면에서 API 키 넣기 (5)

2026. 9. 11.

※ 이 글은 모두의연구소 학습 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 모델이 다음 길을 고르게 한다 — 도구를 쥐여 주는 루프 (4)

강의 서버에서 .env가 안 읽히는 건 파일이 내 컴퓨터에 있거나, python-dotenv가 없는데 에러가 삼켜졌거나, 이미 들어간 빈 값을 override=False가 못 덮었거나, 커널이 재시작된 네 경우 중 하나다.

이 글을 읽기 전에

어디쯤인가
8단계 › 에이전트 팀 꾸리기 — LangGraph — 5번째 글 (전 7편). 4편에서 처음 API 키1가 필요해지는데, 거기서 막혔다면 이 편이에요.
뭐를 할 수 있나
강의 서버든 남의 주피터든, 코드가 실제로 어느 폴더에서 도는지 확인하고 거기에 .env를 만들어 키를 읽힐 수 있어요. "비어 있음"만 나오고 에러는 안 날 때 어디를 먼저 볼지 순서가 생겨요.
왜 배우나
"프로젝트 폴더에 .env를 만드세요"라는 안내는 내 컴퓨터에 주피터를 설치해 돌리는 경우의 이야기예요. 강의 화면은 그렇지 않은데 안내문이 같아서, 같은 자리에서 한참 막혀요.
왜 중요한가
이 문제는 에러를 안 내요. except ImportError: pass가 원인을 삼키고 "비어 있음"이라는 결과만 보여 줘서, 파일을 몇 번씩 다시 만들며 엉뚱한 데를 고치게 돼요. 게다가 남의 서버에 내 키를 두는 일이라 한도 설정 같은 대비도 필요해요.
어디에 쓰나
강의 서버·Colab·사내 주피터에서 키 넣기 · 키가 안 읽힐 때 원인 좁히기 · 실습용 키를 안전하게 분리하기

4편의 도구 루프에서 이 시리즈 처음으로 API 키가 필요해져요. 저는 키 넣는 방법 세 가지 중 .env를 골랐는데, 거기서 한참 막혔어요. 파일은 분명히 만들었는데 "키 설정 여부: 비어 있음"만 나오고, 에러는 한 줄도 안 났거든요.

풀고 보니 막힌 이유가 네 겹이었어요. 하나를 풀어도 다음 게 그대로 남아 있어서 계속 같은 화면이 나왔던 거예요. 같은 데서 막힐 분을 위해 순서대로 적어 둘게요. 이 편은 LangGraph 문법이 아니라 실습 환경 이야기라, 키가 잘 들어갔다면 6편으로 건너뛰어도 돼요.

비유 — 남의 식당 주방을 빌려 하루 장사하기

먼저 비유 없이 사실만 말하면 이래요. 강의 화면에서 [실행]을 눌러도 코드는 제 노트북이 아니라 강의 회사의 서버에서 돕니다. 그래서 제 노트북에 만든 파일은 그 코드가 볼 수 없어요. 이 한 문장이 네 함정 중 첫 번째이자, 나머지 셋의 배경이에요. 그럼 시리즈 내내 쓰던 그 주방으로 옮겨 볼게요.

오늘은 우리 가게가 아니라 남의 식당 주방을 빌려 하루 장사를 해요. 그런데 특급 재료는 우리 가게 냉장고에 넣어 뒀어요. 빌린 주방을 아무리 뒤져도 안 나오죠. 여기는 우리 가게가 아니니까요.

재료를 들고 와 그 주방 냉장고에 넣었는데도 안 돼요. 냉장고를 열어 꺼내 오는 건 제가 아니라 그 주방의 창고 담당인데, 이 주방엔 창고 담당이 아예 없었어요. 게다가 주방 입구의 안내판은 "담당 없음"을 알려 주는 대신 아무 말 없이 넘어갔고요. 담당자를 앉혔더니 이번엔 조리대에 빈 상자가 이미 놓여 있어요. 규칙상 상자가 이미 있으면 새 재료를 그 위에 안 올린대요. 그리고 영업이 끝나 주방을 청소하면 조리대 위는 싹 치워져요.

비유 속 요소원래 개념
오늘 빌려 쓰는 남의 식당 주방 (우리 가게가 아님)강의 서버 — 셀의 [실행]을 눌러도 코드는 내 노트북이 아니라 이 서버에서 돌아요 (함정 ①)
우리 가게 냉장고에 두고 온 재료내 컴퓨터에 만든 .env — 서버는 이 파일을 볼 수 없어요
"지금 제가 선 조리대가 어디죠?"라고 묻기print(os.getcwd()) — 서버의 작업 폴더 확인
냉장고를 열어 재료를 꺼내 오는 창고 담당python-dotenv — .env 파일을 읽어 주는 패키지 (함정 ②)
안내판이 담당 없음을 말 없이 넘김except ImportError: pass — 미설치 에러를 조용히 삼켜요
조리대에 이미 놓인 빈 상자setdefault가 넣어 둔 빈 문자열 — override=False면 못 덮어써요 (함정 ③)
영업이 끝나 청소하면 조리대가 비워짐커널 재시작 — 환경 변수는 커널이 도는 동안만 메모리에 있어요 (함정 ④)

핵심 한 줄: 키가 안 읽히는 문제는 대부분 "키가 틀렸다"가 아니라 재료를 둔 주방과 요리하는 주방이 다르다는 문제예요 — 그러니 파일을 다시 만들기 전에 "지금 코드가 어디서 도는가"부터 물어야 해요.

다만 여기서 비유가 끊기는 점이 있어요. 사람이 지키는 안내판이라면 "담당이 없습니다"라고 한마디는 해 줄 텐데, except ImportError: pass는 정말로 아무 말도 안 해요. 그래서 원인을 보려면 try 바깥에서 일부러 다시 불러 봐야 해요.

전체 흐름 — 키가 코드에 닿기까지, 그리고 네 함정

.env에 적은 키가 실제 코드에 닿으려면 다섯 칸을 지나요. 읽는 법: 위쪽 줄이 정상 경로이고, 아래 점선 상자가 그 칸에서 막힐 수 있는 함정이에요. 함정 번호는 아래 본문의 번호와 같아요.

네 겹을 순서대로 — 한 겹씩 걷어 내기

4편의 직접 만들기 ③에 키 넣는 방법을 세 가지 적어 뒀는데, 그중 .env 방법을 고른 경우의 이야기예요. "프로젝트 폴더에 .env를 만들라"는데, 강의 화면에서 셀을 돌리는 제 경우엔 그 프로젝트 폴더가 어디인지부터 몰랐거든요. 풀고 보니 막힌 이유가 네 겹이었어요. 같은 데서 막힐 분을 위해 순서대로 적어 둘게요.

① 코드는 내 컴퓨터가 아니라 강의 서버에서 돌아요

모두의연구소 강의 화면에서 셀의 [실행] 버튼을 누르면, 코드는 제 노트북이 아니라 강의 쪽 서버에 떠 있는 주피터에서 돌아요. 화면 아래 막대의 '상세보기'를 누르면 수강 환경 패널에 인스턴스 상태(RUNNING)와 커널2 종류(python3)가 보여요. 그러니 제 컴퓨터 폴더에 .env를 만들어 봐야 서버는 그 파일을 볼 수 없어요. 강의 안내의 "프로젝트 폴더에 .env"는 원래 내 컴퓨터에 주피터를 설치해 돌리는 경우의 이야기였어요.

그럼 서버의 어느 폴더일까요. load_dotenv()를 인자 없이 부르면, 주피터 안에서는 지금 작업 폴더3부터 .env를 찾고, 없으면 한 단계씩 상위 폴더로 올라가며 찾아요. python-dotenv 소스의 find_dotenv() 함수가 그렇게 짜여 있어요. 그래서 셀에 한 줄만 넣어 보면 답이 나와요.

실행: 모두의연구소 강의 화면 코드 셀 — 강의 서버의 주피터에서 돌아요

import os
print(os.getcwd())   # 지금 작업 폴더

제 화면에는 /home/jovyan이 찍혔어요. jovyan은 주피터를 서버에 띄울 때 흔히 쓰는 기본 사용자 이름이고, 이 경로는 그 사용자의 집 폴더예요. .env는 여기, 즉 /home/jovyan/.env에 두면 돼요.

② 파일은 강의 화면의 터미널에서 만들었어요

강의 화면 아래 막대의 터미널 아이콘을 누르면 같은 서버의 터미널이 열려요. 거기서 이렇게 쳤어요.

실행: 모두의연구소 강의 화면 터미널 — 코드 셀과 같은 강의 서버예요

cd /home/jovyan
cat > .env

cat > .env를 치면 커서만 깜빡이며 입력을 기다려요. 여기에 OPENAI_API_KEY=sk-... 한 줄을 붙여 넣고(= 앞뒤에 공백 없이), Enter를 누른 다음 Ctrl+D를 누르면 저장되고 프롬프트가 돌아와요. Ctrl+V로 안 붙으면 Ctrl+Shift+V나 마우스 오른쪽 클릭을 써요. 확인은 두 줄로 했어요.

실행: 모두의연구소 강의 화면 터미널

ls -a             # 이름이 점(.)으로 시작하는 숨김 파일까지 보여 줘요
cut -c1-18 .env   # 파일의 앞 18글자만 보여 줘요

두 번째 줄에 OPENAI_API_KEY=sk-가 나오면 형식이 맞아요. 키 전체를 화면에 띄우지 않고 형식만 보는 요령이라, 터미널 화면을 캡처해 질문할 때도 키가 새지 않아요.

③ 파일을 만들었는데도 '비어 있음' — 조용히 넘어간 두 함정

파일을 만들고 강의의 키 설정 셀을 다시 돌렸는데도 "키 설정 여부: 비어 있음"이 그대로였어요. 셀의 뼈대는 이랬어요.

개념 설명용 코드 — 강의 키 설정 셀에서 흐름만 남기고 줄여 옮겼어요

import os
try:
    from dotenv import load_dotenv
    load_dotenv()
except ImportError:
    pass    # 함정 1: 설치가 안 돼 있어도 조용히 넘어가요

os.environ.setdefault("OPENAI_API_KEY", "")  # 함정 2: 키가 없으면 빈 값을 넣어 둬요
print("키 설정 여부:", "설정됨" if os.environ.get("OPENAI_API_KEY") else "비어 있음")

원인을 가리려고 같은 셀 맨 아래, try 밖에 진단 코드를 붙여 돌렸어요. 키 자체는 화면에 찍지 않아요.

실행: 모두의연구소 강의 화면 코드 셀 — 키 설정 셀 맨 아래에 붙여요

from dotenv import find_dotenv, load_dotenv
print("찾은 경로:", repr(find_dotenv(usecwd=True)))
print("로드 결과:", load_dotenv("/home/jovyan/.env", override=True))
print("키 길이:", len(os.environ.get("OPENAI_API_KEY", "")))

첫 줄에서 바로 ModuleNotFoundError: No module named 'dotenv'가 났어요. .env를 읽어 주는 python-dotenv 패키지가 강의 서버에 아예 없었던 거예요. 강의 셀은 except ImportError: pass로 이 에러를 삼켜서, 파일을 한 번도 읽지 않고 넘어가고 있었어요. 이 진단 코드는 다른 원인일 때도 쓸모가 있어요. 로드 결과가 False면 파일이 비었거나 형식이 틀린 거고, 키 길이가 0보다 크면 키가 들어간 거예요.

설치는 터미널이 아니라 셀에서 했어요.

실행: 모두의연구소 강의 화면 코드 셀 — 설치가 끝나면 이 줄은 지워요

%pip install python-dotenv

맨 앞의 %는 파이썬 문법이 아니라 주피터 전용 명령이라는 표시예요. %pip로 깔면 지금 셀을 돌리는 커널과 같은 파이썬 환경에 설치돼요. 터미널의 pip는 커널과 다른 환경에 깔릴 수도 있거든요. 제 경우엔 python-dotenv 1.2.3이 설치됐고, "커널을 재시작해야 할 수도 있다"는 안내가 떴지만 재시작 없이도 됐어요.

두 번째 함정은 setdefault 줄이에요. "키가 없으면 빈 문자열이라도 넣어 둔다"는 뜻이라, 셀을 처음 돌린 순간 OPENAI_API_KEY 자리에 빈 값이 들어가 버렸어요. 그런데 load_dotenv()는 기본값이 override=False라서 이미 있는 환경 변수4는 덮어쓰지 않아요. 빈 값도 "이미 있는" 걸로 치니까, .env를 만든 뒤 셀을 다시 돌려도 빈 값이 그대로 남아요. 해결책은 둘 중 하나예요.

  • load_dotenv()를 load_dotenv(override=True)로 바꿔요. .env의 값이 이미 있는 값을 이기게 해요.
  • 커널을 재시작해요. 환경 변수는 커널이 도는 동안만 메모리에 있어서, 재시작하면 빈 값도 같이 사라져요.

저는 override=True로 바꾸고 설치까지 마친 뒤 셀을 다시 돌려 "설정됨"을 봤어요. 거꾸로 말하면 커널을 재시작할 때마다 키도 사라지니, 재시작 뒤엔 키 설정 셀부터 다시 돌려야 해요. 수강 환경이 초기화되면 설치한 패키지도 사라질 수 있으니 그땐 %pip install부터 다시 하고요.

④ 남의 서버에 키를 두어도 될까

여기까지 오고 나니 "내 키를 강의 서버에 그냥 넣어도 되나?" 싶었어요. OpenAI를 부르는 코드가 그 서버에서 도니까, 어떤 방법을 쓰든 키는 결국 그 서버에 가야 해요. 다만 .env로 두면 키가 남의 서버 디스크에 저장된다는 건 알고 넣어야 해요. 다른 수강생이 볼 가능성은 낮지만, 서버를 운영하는 쪽은 기술적으로 접근할 수 있어요. 그래서 방법을 이렇게 골랐어요.

나쁜 선택좋은 선택
무엇을 했나: 평소 쓰던 키를 os.environ["OPENAI_API_KEY"] = "sk-..."로 셀에 직접 적었어요.

무슨 일이 생기나: 셀 내용은 저장돼서 다음에 열어도 그대로 있고, 실행 기록이나 제출물에 남을 수도 있어요. 키가 새면 내 계정 요금으로 누군가 계속 쓸 수 있는데, 한도가 없으니 피해가 어디서 멈출지 몰라요.		 무엇을 했나: 이 강의에만 쓸 키를 새로 만들어 사용 한도를 작게 걸고, 터미널의 cat > .env로 파일에만 넣었어요. 셀에는 load_dotenv()만 남겼어요.

무슨 일이 생기나: 셀에도, 터미널 명령 기록에도 키가 보이지 않아요(기록에는 cat > .env 명령만 남고 붙여 넣은 내용은 안 남아요). 새더라도 한도에서 멈추고, 강의가 끝나면 그 키만 폐기(revoke)하면 정리돼요.

디스크에도 남기기 싫다면 실행할 때마다 키를 입력받는 방법이 있어요. 키가 커널 메모리에만 있다가 재시작하면 사라지는 대신, 재시작할 때마다 다시 입력해야 해요. 강의 화면 셀에서 입력창이 뜨는지는 제가 확인하지 못했으니, 안 뜨면 .env 쪽으로 가면 돼요.

실행: 모두의연구소 강의 화면 코드 셀 — 입력창이 뜨는 환경에서만 돼요

import os, getpass
os.environ["OPENAI_API_KEY"] = getpass.getpass("OpenAI API Key: ")

비밀값을 코드와 떼어 두는 원칙은 AI가 짠 백엔드 코드에서 반드시 확인할 것들에서 다룬 것과 같아요. 장소가 내 컴퓨터에서 남의 서버로 바뀌었을 뿐이에요. 막힌 순서대로 한 표에 모으면 이래요.

보이는 증상원인해결
내 컴퓨터에 .env를 만들었는데 안 읽혀요강의 화면 셀은 강의 서버에서 돌아요print(os.getcwd())로 서버 폴더를 확인하고 거기에 만들어요 (제 경우 /home/jovyan)
파일이 있는데 에러 없이 "비어 있음"python-dotenv가 설치돼 있지 않은데 except ImportError: pass가 에러를 삼켰어요try 밖에서 import해 확인하고, 셀에서 %pip install python-dotenv
설치한 뒤에도 "비어 있음"setdefault가 넣은 빈 값을 override=False가 못 덮어써요load_dotenv(override=True)로 바꾸거나 커널 재시작
잘 되다가 다시 "비어 있음"커널을 재시작해서 메모리의 키가 사라졌어요키 설정 셀부터 다시 돌려요 (환경이 초기화됐다면 %pip install부터)

이 글에 나온 숫자 — 제 환경에서 찍힌 값

여기 적힌 건 제 환경에서 나온 값이에요. 그대로 베껴 쓰라는 게 아니라 어디를 직접 찍어 봐야 하는지를 표시해 둔 자리예요. 값이 다르면 그게 정상이고, 확인하는 방법만 가져가면 돼요. 마지막 줄만 예외로, 어느 환경에서나 그대로 지키는 게 좋은 습관이에요.

  • 모델이 다음 길을 고르게 한다 — 도구를 쥐여 주는 루프 — 이 편의 키가 실제로 쓰이는 앞 편이에요.
  1. API 키 — 유료 AI 서비스를 내 계정으로 부를 때 쓰는 비밀 문자열이라, 남에게 보이면 내 요금으로 남이 쓸 수 있어요. ↩
  2. 커널(kernel) — 주피터에서 셀 코드를 받아 실제로 실행하며 그동안 만든 변수를 메모리에 들고 있는 프로그램이라 재시작하면 그 값이 모두 사라지고, 도커 글에 나온 운영체제의 커널과는 이름만 같아요. ↩
  3. 작업 폴더(current working directory) — 프로그램이 파일 이름만 받았을 때 기준으로 삼는 '지금 있는 폴더'로, 호스트에 연결하고 첫 도구 호출 확인하기에서 처음 다뤘어요. ↩
  4. 환경 변수(environment variable) — 코드 바깥에 "이름=값" 꼴로 적어 두고 프로그램이 이름으로 읽어 가는 설정값으로, 인증 코드와 MCP 서버 글에서 처음 다뤘어요. ↩
