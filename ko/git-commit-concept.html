Git 커밋(commit)이란 무엇인가

2026. 7. 12.

※ 이 글은 모두의연구소 AI AIFFEL 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

Git을 처음 배우면서 제일 오래 헷갈렸던 단어 하나만 고르라면 단연 커밋(commit)이에요. (참고로 Git은 파일이 언제 어떻게 바뀌어 왔는지를 통째로 기록해주는 프로그램이에요.) 화면에 "커밋하세요"라는 말이 계속 나오는데, 저는 속으로 계속 이렇게 생각했어요. "그거 그냥 저장하라는 거 아니야? 이미 Ctrl+S 눌렀는데?" 그런데 아무리 Ctrl+S를 눌러도 커밋은 하나도 안 생기더라고요. 그래서 이 둘이 정확히 뭐가 다른지 처음부터 파보기로 했어요.

커밋이라는 단어의 유래, 그리고 저장과 뭐가 다를까

가장 먼저 걸린 건 단어 자체였어요. 저장이면 save라고 하면 될 텐데 왜 하필 commit일까요. 찾아보니 commit은 라틴어 committere에서 온 말인데, "함께(com-) 보내다(mittere)", 그러니까 "맡기다, 위탁하다"라는 뜻이었어요. 일을 여러 사람에게 맡겨두는 기구를 committee(위원회)라고 부르는 것도 같은 뿌리예요.

여기서 뜻이 한 갈래 더 뻗어나가요. 무언가를 남에게 맡긴다는 건 이제 와서 마음대로 무를 수 없다는 뜻이기도 하잖아요. 그래서 commit에는 "확정하다, 되돌리지 않겠다고 약속하다"라는 의미가 함께 붙었어요. 우리가 아는 commitment(헌신, 약속)가 그 뜻이에요.

이 두 뜻을 합치면 Git의 커밋이 뭘 하는 건지 감이 잡혀요. "지금까지 작업한 이 상태를 확정해서, 기록으로 맡겨두는 것." 그러니까 커밋은 파일을 바꾸는 동작이 아니라 기록을 남기는 동작이었어요. 그럼 Ctrl+S와는 정확히 어디서 갈라지는 걸까요?

게임 세이브를 떠올렸더니 단번에 정리됐어요. 이 글에서는 계속 이 비유로 이야기해볼게요.

저장(Ctrl+S)은 지금 상태로 파일을 덮어쓰는 거예요. 방금 전 상태는 그 순간 사라져요. 게임으로 치면 세이브 슬롯 하나만 놓고 계속 그 위에 덮어쓰는 것과 같아요. 한 시간 전으로 돌아가고 싶어도 돌아갈 자리가 없어요.

커밋(commit)은 그때그때 세이브 슬롯을 새로 하나씩 만드는 거예요. 1번 슬롯, 2번 슬롯, 3번 슬롯이 계속 쌓여요. 앞의 슬롯은 하나도 안 지워지기 때문에, 언제든 예전 시점으로 돌아가거나 "3번과 5번 사이에 내가 정확히 뭘 바꿨지?"를 비교해볼 수 있어요.

저장은 원고를 계속 고쳐 쓰는 것이고, 커밋은 "이 버전은 여기까지 확정" 하고 사본을 한 부 떠서 남겨두는 것이에요.

그래서 저장과 커밋은 경쟁하는 관계가 아니었어요. 파일을 고치다가 Ctrl+S를 여러 번 누르고, 어느 정도 한 덩어리가 완성되면 그때 커밋을 한 번 하는 식이에요. 저장은 수시로, 커밋은 "여기까지 한 단락 끝났다" 싶을 때. 그런데 슬롯을 여러 개 만들어두면, 나중에 그게 무슨 슬롯이었는지 어떻게 알아볼까요?

세이브 슬롯에 적히는 것들, 그리고 이름·이메일 등록

Git은 커밋을 하나 남길 때마다 아래 세 가지를 자동으로 같이 붙여둬요.

  1. 누가 바꿨는지 — 이름과 이메일
  2. 언제 바꿨는지 — 날짜와 시각
  3. 무엇을 바꿨는지 — 커밋 메시지

이 중에서 커밋 메시지만 사람이 직접 써야 해요. 나머지 둘은 Git이 알아서 채워요. 메시지는 세이브 슬롯에 붙이는 이름표라고 보면 돼요. "수정"이나 "ㅁㄴㅇㄹ"처럼 대충 적어두면, 나중에 슬롯 스무 개가 전부 "수정"이라고 적혀 있어서 어디로 돌아가야 할지 알 수가 없어요. 그래서 저는 "로그인 버튼 색상 변경"처럼 이 슬롯에서 무슨 일이 끝났는지가 보이게 쓰려고 해요. 나중의 저에게 보내는 메모인 셈이에요.

그런데 1번, "누가"는 Git이 어떻게 알까요? 제 컴퓨터니까 알아서 아는 걸까요? 아니었어요.

Git은 제가 누구인지 처음엔 전혀 몰라요. 그래서 커밋을 시작하기 전에 이름과 이메일을 한 번 등록해줘야 해요. Windows에서는 PowerShell(윈도우에 기본으로 들어 있는, 명령어를 글자로 입력하는 창)을 열고 이렇게 쳐요.

git config --global user.name "내 이름"
git config --global user.email "내메일@example.com"

여기서 --global은 "이 컴퓨터 전체에 적용하라"는 뜻이에요. 폴더마다 매번 다시 등록할 필요 없이, 앞으로 이 컴퓨터에서 만드는 모든 커밋에 "이건 내가 한 거다"라는 서명이 자동으로 붙어요. 여럿이 같이 하는 작업이라면 이 서명이 곧 "이 줄은 누가 건드렸나"를 알려주는 유일한 단서가 되고요.

여기서 저는 또 한 번 착각을 했어요. 이 명령을 치고 나서 "이제 Git 준비가 끝났구나, 커밋할 수 있겠네"라고 생각한 거예요. 그런데 커밋이 안 됐어요.

흔한 오해 — "저장소 초기화"는 아니에요, 그리고 정리

제가 방금 한 건 규칙을 등록한 것일 뿐이었어요. git config는 "이 컴퓨터에서 커밋할 때는 항상 이 이름과 이메일을 쓰라"는 설정이고, 기록을 남길 장소는 아직 하나도 만들지 않은 상태였던 거예요.

그 장소를 저장소(repository, 리포지토리)라고 불러요. repository도 어원이 그대로예요 — 라틴어로 "다시 놓아두는 곳", 즉 보관소라는 뜻이에요. 특정 폴더 하나를 딱 정해서 "여기서부터는 변경 이력을 관리하겠다"고 선언하는 것이고, 그 순간부터 그 폴더 안의 커밋들이 거기에 쌓여요. 선언하는 방법은 두 가지예요.

  • git init — 내 컴퓨터의 빈 폴더에서 새 저장소를 처음 만들 때. init은 initialize(초기화)의 줄임말이에요.
  • git clone — 이미 인터넷에 올라와 있는 남의(또는 내) 저장소를 통째로 복제해 올 때.

정리하면 이래요. git config는 도장을 새로 파서 등록해둔 것이고, 저장소를 만드는 건 그 도장을 실제로 찍을 서류철을 하나 여는 것이에요. 도장만 파두고 서류철은 하나도 안 연 상태에서는, 찍을 데가 없으니 아무 기록도 남길 수 없어요. 반대로 서류철만 열고 도장을 안 팠으면, Git이 "당신 누구세요?"라고 물어보고요. 둘 다 필요하고, 둘은 완전히 다른 일이에요.

이제 처음 질문에 답할 수 있어요. 커밋은 저장이 아니에요. 저장은 지금 파일을 덮어쓰는 일이고, 커밋은 "여기까지의 상태"를 확정해서 되돌아올 수 있는 기록으로 맡겨두는 일이에요. 단어의 뿌리(맡기다·확정하다)가 하는 일을 그대로 말해주고 있었던 거예요.

그리고 그 기록 하나하나에는 누가·언제·무엇을이 같이 붙기 때문에, "누가"를 채워줄 이름·이메일을 git config로 먼저 등록하고, 기록이 쌓일 장소인 저장소를 git init이나 git clone으로 따로 열어줘야 비로소 첫 커밋을 남길 수 있어요. 저는 이 순서를 몰라서 한참을 헤맸는데, 커밋이 "세이브 슬롯을 하나씩 쌓는 일"이라는 걸 이해하고 나니 나머지는 자연스럽게 따라왔어요.
