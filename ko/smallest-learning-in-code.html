가장 작은 학습을 코드로 보기 — 카페 매출 예측 실습

2026. 7. 30.

※ 이 글은 모두의연구소 AI AIFFEL 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 데이터를 숫자로 바꾸기 — 벡터와 텐서

앞 글에서 학습을 "예측 → 오차 → 조정"의 반복이라고 했는데, 말로만 들으면 여전히 추상적이었어요. 그래서 실제로 가장 작은 학습을 직접 돌려봤어요 — 파라미터가 weight 하나, bias 하나뿐인 가장 단순한 모델에게 데이터만 주고 규칙을 스스로 찾게 하는 거예요.

torch, 두 개념만 알면 충분했어요

torch(PyTorch)는 딥러닝에서 가장 널리 쓰는 파이썬 라이브러리예요. 지금 필요한 건 딱 두 가지였어요. 하나는 앞서 본 텐서(tensor), 그 숫자 배열이에요. 고마운 점은 같은 코드가 CPU에서도 GPU에서도 그대로 돈다는 것이었어요 — 데이터를 어느 장치(device)에 올리느냐만 바꿔주면 됐어요. 다른 하나는 autograd(자동 미분)예요. torch는 계산 과정을 속으로 기억해두었다가 loss.backward() 한 줄이면 "각 파라미터가 오차에 얼마나 기여했는지", 곧 기울기(gradient)를 알아서 계산해줘요. 앞서 말한 역전파를 torch가 대신 밟아주는 셈이었어요.

카페 매출을 예측해보기 — 네 단계

작은 카페를 연다고 해봤어요. 하루 방문객 수를 보면 그날 매출을 얼추 예측하고 싶은데, 가진 건 지난 30일치 (방문객 수, 매출) 기록뿐이에요. 방문객이 많은 날은 매출도 높으니 둘 사이에 대략 직선 관계가 있을 것 같지만, 정확한 식(손님이 얼마를 쓰는지, 기본 매출은 얼마인지)은 몰라요. 이 관계식을 데이터만 보고 모델이 찾게 해보는 거예요.

할 일은 네 단계였어요 — ① 숨은 직선 규칙에서 나온 데이터를 만든다 → ② 그 데이터를 눈으로 본다 → ③ 모델에게 규칙을 안 알려준 채 스스로 찾게 한다(예측 → 오차 → 조정) → ④ 찾은 규칙과 줄어든 오차를 그래프로 확인한다. 데이터는 숨은 규칙 매출 = 2 × 방문객 + 1(매출 단위는 만원이라고 해볼게요)에 날마다 다른 잡음을 섞어 만들었는데, 모델은 이 '2'와 '1'을 전혀 모른 채 출발해요.

학습시키기 — 경사하강이 실제로 하는 일

여기가 핵심이었어요. weight·bias를 엉뚱한 값(0)에서 출발시켜 예측 → 오차 → 조정을 600번 반복해요.

w = torch.zeros(1, 1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)

def model(x):
    return x @ w + b  # 예측 매출 = w*방문객 + b

lr = 0.03  # 학습률: 한 걸음의 크기
for step in range(600):
    pred = model(x)
    loss = ((pred - y) ** 2).mean()  # 평균제곱오차(MSE)
    loss.backward()                  # 역전파로 기울기 계산
    with torch.no_grad():
        w -= lr * w.grad             # 경사하강: 기울기 반대 방향으로 한 걸음
        b -= lr * b.grad
        w.grad.zero_(); b.grad.zero_()

실행하면 마지막에 학습된 규칙: 매출 = 2.07 × 방문객 + 0.79처럼 두 숫자가 출력됐어요. 이 값이 숨은 정답(2, 1)에 가까웠어요 — 아무도 규칙을 알려주지 않았는데, 데이터만으로 규칙을 찾아낸 거예요. 결과를 그래프로 보면 두 가지가 보였어요. 흩어진 점들 한가운데를 빨간 직선이 지나가고, 오차(loss)는 급히 떨어졌다가 평평해져요. 학습된 직선의 기울기(약 2.07)는 "방문객이 100명 늘면 매출이 약 207만원 는다"는 뜻이고, 절편(약 0.8)은 방문객이 0명인 날에도 잡히는 기본 매출(배달·포장 매출) 정도로 볼 수 있었어요. 절편이 기울기보다 정답에서 더 흔들리는 건, 절편이 방문객 0명 지점의 값인데 데이터의 중심(평균 방문객 수)에서 멀리 떨어져 있어서 그 먼 지점을 추정하는 일이 잡음에 더 민감하기 때문이었어요.

거대 언어 모델과 다른 점은 오직 규모

거대 언어 모델도 이 카페 실습과 다르지 않았어요. 다른 점은 오직 규모예요 — weight·bias가 2개가 아니라 수십억~수천억 개이고, 예측하는 것이 숫자 하나가 아니라 다음 토큰의 확률분포라는 것. 방식은 똑같이 "예측 → 오차 → 조정"의 반복이에요. 실무에서는 이 갱신 루프를 손으로 쓰지 않고 torch.nn.Linear와 torch.optim.SGD 같은 도구로 짧게 줄이는데, 굳이 손으로 편 이유는 경사하강이 실제로 무엇을 하는지 한 번 보기 위해서였어요. 그리고 이 작은 학습을 웹 전체 규모로 돌린 것이 바로 모델의 사전학습(pretraining)이에요. 다음 글에서는 "매출"처럼 연속된 숫자가 아니라 "어느 쪽인가"를 고르는 분류 문제, softmax와 MNIST 손글씨 분류를 볼게요.
