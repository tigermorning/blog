여덟 편에 걸쳐 개관, PRD, 청크, 임베딩, 검색, 프롬프트, 판정, 실험을 지나왔다. 오늘은 이 전부를 내 도메인으로 바꾸고 실제로 세상에 내놓는 자리다. 결과보다 순서가 중요했던 하루였다.

1. 설계 — PRD의 빈칸을 닫는다

초안으로 남긴 PRD는 제출 직전에 완성본으로 닫는다. 문서의 [결정 필요]를 하나씩 찾아 사용자, 해결하려는 질문, 사용할 자료의 범위, 답변의 근거 표시, 실패했을 때의 안내 문구로 바꿔 적는다. 빈칸을 유지한 채 구현을 시작하면 나중의 코드 선택이 제품 약속을 대신하게 된다. 자료에 없는 질문은 그럴듯하게 넓혀 답하지 않고, 자료 범위 밖임을 밝힌 뒤 관련 자료를 요청하거나 답할 수 없다고 안내한다고 명시한다. 이 기준은 거절 횟수를 줄이려는 장치가 아니라 사용자가 답변의 경계를 이해하게 하는 약속이다.

2. 구현 — 모두콘 구조를 내 자료로 바꾼다

이제 청크 배열을 내 자료의 사실 단위로 교체한다. id, text, url, section, vector 스키마는 유지하고, 소개와 페이지 문구도 PRD에서 확정한 사용자와 질문으로 바꾼다. 임베딩은 embeddinggemma-300m으로 만들어 768차원 벡터 공간을 맞춘다 — 자료 벡터만 바꾸고 질의 임베딩을 다른 모델로 만들면 검색 점수는 비교할 자리를 잃는다. 검색 순서와 답변 프롬프트의 출처·거부 규칙은 그대로 두어, 바뀐 결과를 내 자료의 차이로 읽을 수 있게 한다.

실행: 코딩 에이전트에 붙여넣기 — Claude Code 등

**스키마와 검색·프롬프트 파이프라인은 변경하지 마세요.** 모두콘 예시 코드에서 청크 데이터와 소개·페이지 문구를 [내 도메인]으로 교체해 주세요. 청크는 [자료 경로]를 근거로 만들고 `id`, `text`, `url`, `section`, `vector` 필드를 유지하세요. 임베딩은 embeddinggemma-300m의 768차원으로 통일하고, [도메인 밖 질문 처리 기준]을 문구에 반영하세요.

3. 실험 — 내 루브릭으로 한 바퀴

앞에서 정한 자기 루브릭을 새 챗봇에 그대로 적용한다. 출처를 인용한 답, 도메인 밖 질문의 거부, 판정 배지의 grounded 여부, 짧은 답변에서도 근거 표시가 남는지를 고정 질문 세트로 확인한다. 질문은 자료를 직접 묻는 것, 여러 청크를 잇는 것, 자료 밖을 묻는 것을 함께 넣어 경계를 관찰한다. README.md에는 실행 날짜 대신 실험 이름, 바꾼 변수, 고정 질문, 각 질문의 cited·refusal·grounded 판정, 관찰한 근거, 채택 또는 되돌림 결정을 기록한다. 실패한 답도 지우지 않아야 다음 수정이 무엇을 보존해야 하는지 알 수 있다.

4. 배포 — 내 주소로 세상에 내놓기

npm run build로 정적 결과물을 만들고, 생성된 dist를 GitHub Pages에 올린다. 프로젝트 설정의 base:'./'는 배포 주소 아래에서도 자산 경로를 상대적으로 찾게 한다. 그러나 정적 페이지가 답변을 대신 실행하는 건 아니다. 페이지를 연 사용자의 브라우저가 localhost:11434에 있는 Ollama의 qwen3.5:2b를 직접 호출한다. 그래서 그 사용자 컴퓨터에서 Ollama가 실행 중이어야 하고, Pages 출처의 요청을 허용하도록 OLLAMA_ORIGINS를 설정해야 한다.

배포 주소에서 소개 질문과 도메인 밖 질문을 각각 입력해 자산 로드, 모델 연결, 출처 표시와 거부 안내를 확인한다. 주소가 열리는 것만으로 배포가 끝났다고 판단하지 않고, 사용 조건을 갖춘 브라우저에서 실제 경로를 따라간다. 연결에 실패했을 때는 모델이 없다는 안내와 재시도 방법이 보이는지도 확인해, 사용자가 페이지 오류와 자신의 실행 조건을 구별할 수 있게 한다.

5. 제출 — 저장소와 안내 페이지

제출 저장소에는 README.md, PRD.md, 코드, 배포 주소를 함께 둔다. README.md에는 서비스 소개, 설계 결정 요약, 실험 결과, 배포 주소와 사용 조건을 적는다. 사용 조건은 Ollama 실행, 첫 방문의 임베딩 다운로드 약 200MB, CORS 설정 필요를 숨기지 않는 항목이다. PRD.md는 누구의 어떤 질문을 자료 범위 안에서 다루는지와 도메인 밖 질문 처리 기준을 보여준다. 안내 페이지는 결과를 자랑하는 자리가 아니라 처음 보는 사람이 실행 전에 조건을 판단하는 자리다.

  1. 배포 주소를 열고 서비스가 다루는 자료와 질문을 읽는다.
  2. 자신의 컴퓨터에서 Ollama를 실행하고 qwen3.5:2b를 준비한다.
  3. 첫 방문에는 임베딩 다운로드가 있을 수 있음을 확인하고 기다린다.
  4. Pages 주소에서 호출하려면 OLLAMA_ORIGINS에 해당 출처를 허용한 뒤, 안내한 질문과 자료 밖 질문을 각각 입력한다.

이 순서가 README와 안내 페이지에서 같은 말로 보이는지 마지막으로 대조한다.

정리 — 제출 뒤에 남는 것

오늘 만든 건 자료를 넣고 답을 내는 화면만이 아니다. PRD로 질문의 범위와 거절의 기준을 정하고, 같은 스키마와 임베딩 공간 안에서 자료를 교체하고, 루브릭과 고정 질문으로 답변을 판정하고, 사용 조건까지 안내하는 흐름을 한 번 연결했다. 이제 저장소의 README는 사용자의 출발점이 되고, PRD는 바꿀 수 없는 약속과 다시 검토할 결정을 가르는 기준이 되며, 실험 기록은 다음 변경을 비교할 기준이 된다. 답변 하나가 좋아 보인다는 인상보다 어떤 질문에서 어떤 근거와 판정이 나왔는지를 남긴 기록이 챗봇을 설명 가능하게 한다. 제출은 끝이 아니라, 자기 도메인에서 측정이 계속되는 시작이다.

이럴 때 의심하세요 — 내 자료로 바꾸고 배포한 뒤 챗봇이 이상할 때

자료 교체와 배포를 AI에게 맡기면 이 편의 실수들은 에러보다 증상으로 먼저 만나요. 그리고 대부분 내 컴퓨터에서는 멀쩡해요. Ollama도 켜져 있고, 출처 허용도 해 뒀고, 모델 파일도 이미 받아 뒀으니까요. 그래서 링크를 받은 사람이 먼저 알아채는 경우가 많아요.

증상이 아직 없어도, AI에게 이런 부탁을 한 직후라면 한 번 확인하고 넘어가요.

  • "청크 데이터를 내 자료로 바꿔 줘" — 임베딩 모델 이름과 id, text, url, section, vector 스키마가 그대로인지
  • "GitHub Pages에 배포해 줘" — 빌드 설정의 base 줄, 그리고 README.md에 사용 조건이 적혔는지
이런 증상이 보이면먼저 열어 볼 자리확인 방법
자료를 내 것으로 바꾼 뒤, 자료에 분명히 있는 내용을 물어도 출처로 엉뚱한 조각이 붙거나 유사도 점수가 전부 낮아요. 에러가 나기도 하지만, 벡터 길이가 우연히 같으면 에러 없이 이렇게만 나와요 청크 데이터 파일에 든 vector 하나의 길이, 그리고 문서 벡터를 만든 스크립트와 질문을 임베딩하는 코드에 적힌 모델 이름이에요. 검색 순서나 프롬프트보다 여기가 먼저예요 길이가 768인지, 두 곳의 모델이 모두 embeddinggemma-300m인지 맞춰 봐요. 하나라도 다르면 문서 벡터를 질문과 같은 모델·같은 조건으로 다시 만들어요 (4편)
배포 주소를 열었더니 하얀 빈 화면만 나와요. 내 컴퓨터에서 개발 서버로 띄울 때는 잘 보였어요 브라우저 개발자 도구의 네트워크(Network) 탭, 그리고 빌드 설정 파일(Vite라면 vite.config)의 base 줄이에요 .js·.css 파일이 404(파일 없음)로 떠 있고, 그 파일 주소에 저장소 이름이 빠져 있으면 base 문제예요(아이디.github.io/저장소/처럼 저장소 이름이 붙는 주소에 올렸을 때). base:'./'로 두고 npm run build부터 다시 해서 올려요
배포 주소에서 화면은 뜨는데 질문을 넣어도 답이 안 오고 연결 실패 안내만 보여요. 로컬 개발 서버에서는 같은 질문에 답이 왔어요 페이지 코드보다 내 컴퓨터의 Ollama 설정이에요. 개발자 도구 콘솔에 localhost:11434로 가는 요청이 CORS 때문에 막혔다는 빨간 줄이 있는지 봐요 주소창에 http://localhost:11434를 열어 Ollama is running이 보이면 Ollama는 켜져 있는 거예요. 그렇다면 OLLAMA_ORIGINS에 Pages 주소를 넣고 Ollama를 다시 켜요 (6편, CORS 에러 확인하기)
내 컴퓨터에서는 잘 되는데, 링크를 받은 사람은 "안 된다", "멈춰 있다"고 해요 그 사람 컴퓨터의 조건과 README.md의 사용 조건이에요. 내 컴퓨터는 Ollama와 출처 허용이 이미 갖춰져 있고 모델 파일도 브라우저에 받아 둔 경우가 많아서, 이 문제가 안 보여요 Ollama를 끄고 시크릿 창으로 배포 주소를 열어 봐요. 저장해 둔 파일이 없어서 첫 방문처럼 약 200MB 다운로드부터 겪고, 모델이 없다는 안내와 재시도 방법이 보이는지도 확인돼요. 겪은 순서를 README의 사용 조건과 맞춰 봐요
자료 밖 질문을 넣었는데 거절하지 않고 그럴듯하게 답해요 PRD.md에 남은 [결정 필요], 그리고 답변 프롬프트의 거부 규칙이에요 PRD.md에서 [결정 필요]를 검색해요. 자료 밖 질문 처리 칸이 아직 비어 있으면 지금 동작은 약속이 아니라 AI가 고른 코드라, 그 칸부터 문장으로 닫고 프롬프트와 맞춰요. 빈칸이 없는데도 그렇다면 고정 질문으로 실험해 봐요 (8편)

네 번째 줄이 제일 늦게 드러나요. 내 컴퓨터는 조건을 다 갖췄으니 아무리 눌러 봐도 멀쩡하거든요. 그래서 증상을 기다리지 말고 링크를 보내기 직전에 한 번 확인해요.
