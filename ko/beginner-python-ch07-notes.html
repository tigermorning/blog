7.1 클래스와 인스턴스

왜 필요한가 — 붕어빵을 함수만으로 관리하면

붕어빵 정보를 딕셔너리로 만들고 함수로 소개하는 코드예요. 붕어빵이 한두 개일 때는 잘 돌아가요.

def make_bread(filling, price):           # make_bread 함수를 정의해 주세요
    return {"filling": filling, "price": price}  # 속재료와 가격을 딕셔너리로 만들어 돌려주세요
def describe(b):                          # describe 함수를 정의해 주세요
    return b["filling"] + "붕어빵 " + str(b["price"]) + "원"  # 소개 글자를 만들어 돌려주세요
a = make_bread("팥", 1000)                # a 에 팥 붕어빵 정보를 만들어 담아 주세요
print(describe(a))                        # a 의 소개를 화면에 보여 주세요
팥붕어빵 1000원

붕어빵이 수십 개로 늘면 세 가지 문제가 생겨요.

문제무슨 일이 생기나
빠뜨림딕셔너리를 손으로 만들면 어떤 붕어빵에서 price를 안 적고 넘어가도 아무도 알려 주지 않아요
오타prise처럼 이름을 틀리게 적어도 코드를 돌려 보기 전에는 몰라요
고칠 곳이 많음크기(size)를 모든 붕어빵에 추가하려면 붕어빵을 만드는 곳을 전부 찾아 고쳐야 해요

해결책은 “붕어빵은 이런 모양이야”를 한 곳에 정해 두고, 그 모양대로만 만드는 거예요. 그 한 곳이 클래스예요.

클래스와 인스턴스

클래스(class)는 같은 모양의 객체를 만드는 설계예요. 인스턴스(instance)는 그 설계로 만든 하나하나(객체)예요. 설계 자체는 먹을 수 없고, 먹는 건 설계로 구운 붕어빵이에요. 같은 틀에서 나온 팥붕어빵과 슈크림붕어빵은 서로 다른 붕어빵이라서, 하나를 바꿔도 다른 하나는 그대로예요.

위키독스는 이 관계를 “스케이터”로 설명해요. 김연아와 김동성은 실제로 존재하는 사람(인스턴스)이고, 둘의 공통점인 “스케이트 타는 사람”이 클래스(부류)예요. “스케이터 한 명”은 없고, 김연아처럼 콕 집어 말할 수 있는 한 명이 인스턴스예요.

클래스 읽는 법 — 네 줄이면 돼요

class Bungeoppang:                            # Bungeoppang 이라는 클래스를 정의해 주세요
    def __init__(self, filling, price=1000):  # 만들 때 자동으로 불리는 __init__ 을 정의해 주세요 (가격을 안 주면 1000)
        self.filling = filling                # 이 붕어빵의 filling 칸에 filling 을 담아 주세요
        self.price = price                    # 이 붕어빵의 price 칸에 price 를 담아 주세요
    def describe(self):                       # describe 메서드를 정의해 주세요
        return self.filling + "붕어빵 " + str(self.price) + "원"  # 소개 글자를 만들어 돌려주세요
x = Bungeoppang("팥")                         # x 에 팥 붕어빵을 만들어 담아 주세요
y = Bungeoppang("슈크림", 1500)               # y 에 가격이 1500 인 슈크림 붕어빵을 만들어 담아 주세요
print(x.describe())                           # x 의 소개를 화면에 보여 주세요
print(y.describe())                           # y 의 소개를 화면에 보여 주세요
팥붕어빵 1000원
슈크림붕어빵 1500원
줄하는 일
class Bungeoppang:클래스의 이름을 정하고, 아래에 들여쓴 줄들이 이 클래스의 내용이 돼요 (틀 만들기)
def __init__(self, filling, price=1000)붕어빵을 만들 때 자동으로 한 번 불리는 메서드예요. 주문서에 적힌 속재료와 가격을 받는 자리이고, 가격을 안 적으면 1000이에요
self.filling = filling왼쪽 self.filling은 “이 붕어빵에 달린 filling 칸”이고, 오른쪽 filling은 주문서에서 받은 값이에요. 받은 값을 붕어빵의 칸에 적어 두는 줄이에요
def describe(self)붕어빵에게 시킬 수 있는 동작(메서드)이에요. 소개 글자를 만들어 돌려줘요

Bungeoppang("팥")을 쓰면 무슨 순서로 일어나나요

순서일어나는 일
① 빈 붕어빵 만들기속이 빈 인스턴스가 먼저 생겨요
② __init__ 자동 호출파이썬이 __init__(self=그 인스턴스, filling="팥")을 대신 불러요. 우리가 __init__을 직접 부르지 않아요
③ 칸 채우기self.filling, self.price에 받은 값이 저장돼요
④ 변수에 담기완성된 붕어빵이 x에 담겨요

핵심 한 줄: 클래스이름(값)을 쓰면 빈 인스턴스가 생기고, __init__이 자동으로 불려 값을 칸에 적어 줘요.

7.2 변수와 메서드

제목은 “변수와 메서드”인데, 여기서 변수는 클래스 안에 적은 변수, 메서드는 클래스 안에 적은 함수를 말해요. 그리고 이 둘을 이어 주는 것이 self예요. 이 절에서 가장 많이 막히는 곳이 self라서, 값이 어디에 있는지부터 보고 self로 넘어갈게요.

값이 사는 곳은 두 군데예요

이름직접 설명가게 비유
클래스 변수클래스 안, 메서드 밖에 이름 = 값으로 적은 변수. 이 클래스로 만든 모든 인스턴스가 처음에 읽는 기본값이에요틀에 새겨진 기본 가격표
인스턴스 변수메서드 안에서 self.이름 = 값으로 저장한 변수. 그 인스턴스만 가진 값이에요구운 붕어빵에 붙인 가격 스티커

읽는 규칙은 하나예요. 붕어빵.price를 읽을 때 그 붕어빵에 스티커(인스턴스 변수)가 있으면 스티커 값을, 없으면 틀의 가격표(클래스 변수)를 읽어요.

class Bungeoppang:                  # Bungeoppang 클래스를 정의해 주세요
    price = 1000                    # 클래스 변수 price 에 1000 을 담아 주세요 (틀의 기본 가격표)
    def discount(self, won):        # discount 메서드를 정의해 주세요
        self.price -= won           # 이 붕어빵의 price 에서 won 을 빼 주세요
x = Bungeoppang()                   # x 에 붕어빵을 만들어 담아 주세요
y = Bungeoppang()                   # y 에 붕어빵을 만들어 담아 주세요
print(x.price, y.price)             # x 와 y 의 price 를 화면에 보여 주세요
x.discount(200)                     # x 의 가격을 200 깎아 주세요
print(x.price, y.price, Bungeoppang.price)  # x, y, 틀의 price 를 화면에 보여 주세요
print(x.__dict__)                   # x 가 따로 가진 변수들을 화면에 보여 주세요
Bungeoppang.price = 1500            # 틀의 기본 가격표를 1500 으로 바꿔 주세요
print(x.price, y.price)             # x 와 y 의 price 를 화면에 보여 주세요

self.price -= 200은 “틀의 1000을 읽어 800을 계산한 뒤, 그 결과를 x 자신의 변수로 새로 저장”하는 줄이에요. 그때부터 x는 틀의 가격표를 보지 않고 자기 스티커를 봐요. y는 스티커가 없으니 틀이 바뀌면 같이 바뀌어요.

핵심 한 줄: self.이름 = 값을 하는 순간 그 인스턴스는 클래스 변수 대신 자기 값을 써요.

self는 “지금 시킨 그 붕어빵”이에요

메서드를 정의할 때는 첫 매개변수로 self를 적는데, 부를 때는 x.discount(200)처럼 self를 쓰지 않아요. 이 차이 때문에 많이 헷갈려요. 사실은 x.discount(200)을 부르는 순간 파이썬이 self 자리에 x를 몰래 넣어 줘요. 그래서 self는 “이 메서드를 부른 인스턴스 자신”이에요.

class Bungeoppang:                  # Bungeoppang 클래스를 정의해 주세요
    def me(self):                   # me 메서드를 정의해 주세요
        return self                 # 이 메서드를 부른 인스턴스 자신을 돌려주세요
x = Bungeoppang()                   # x 에 붕어빵을 만들어 담아 주세요
y = Bungeoppang()                   # y 에 붕어빵을 만들어 담아 주세요
print(x.me() is x, x.me() is y)     # x.me() 의 결과가 x 인가요, y 인가요?
print(Bungeoppang.me(x) is x)       # self 자리에 x 를 직접 넘긴 모양도 같은 결과인가요?

x.discount(200)self가 x가 되어 x의 가격이 바뀌어요
y.discount(200)self가 y가 되어 y의 가격이 바뀌어요
Bungeoppang.discount(x, 200)self 자리에 x를 직접 넘긴 모양이에요. x.discount(200)은 이 줄을 줄여 쓴 거예요

가게 비유로는, 점원 매뉴얼에 “이 붕어빵의 가격에서 깎을 금액만큼 빼라”라고 적혀 있고, 손님이 “저 붕어빵 200원 깎아 주세요”라고 가리키면 가리킨 붕어빵이 매뉴얼의 “이 붕어빵”이 되는 거예요. 같은 매뉴얼 한 벌을 모든 붕어빵이 쓰는데, 누구에게 적용할지는 가리킨 붕어빵이 정해 줘요.

핵심 한 줄: self는 정의할 때만 적고, 부를 때는 파이썬이 시킨 인스턴스를 넣어 줘요.

교재 예제로 한 번 더 — 훈련하는 아마존

위키독스는 게임 캐릭터 아마존으로 같은 내용을 보여 줘요. 클래스 변수(strength 등)와 메서드(attack, exercise)가 한 클래스에 있어요.

class Amazon:                       # Amazon 클래스를 정의해 주세요
    strength = 20                   # 클래스 변수 strength 에 20 을 담아 주세요
    dexterity = 25                  # 클래스 변수 dexterity 에 25 를 담아 주세요
    vitality = 20                   # 클래스 변수 vitality 에 20 을 담아 주세요
    energy = 15                     # 클래스 변수 energy 에 15 를 담아 주세요
    def attack(self):               # attack 메서드를 정의해 주세요
        return 'Jab!!!'             # 'Jab!!!' 를 돌려주세요
    def exercise(self):             # exercise 메서드를 정의해 주세요
        self.strength += 2          # 이 인스턴스의 strength 에 2 를 더해 주세요
        self.dexterity += 3         # 이 인스턴스의 dexterity 에 3 을 더해 주세요
        self.vitality += 1          # 이 인스턴스의 vitality 에 1 을 더해 주세요
jane = Amazon()                     # jane 에 Amazon 인스턴스를 만들어 담아 주세요
mary = Amazon()                     # mary 에 Amazon 인스턴스를 만들어 담아 주세요
print(jane.strength, jane.attack()) # jane 의 strength 와 공격 결과를 화면에 보여 주세요
jane.exercise()                     # jane 에게 훈련을 시켜 주세요
print(jane.strength, jane.dexterity, jane.vitality)  # jane 의 힘·기술·체력을 화면에 보여 주세요
print(mary.strength)                # mary 의 strength 를 화면에 보여 주세요

자주 막히는 곳 — self 를 빠뜨리면

7.3 상속

상속(inheritance)은 이미 있는 클래스(부모)의 변수와 메서드를 새 클래스(자식)가 그대로 물려받는 거예요. 자식 클래스는 class 자식(부모):처럼 이름 옆 괄호에 부모를 적어서 만들어요. 가게 비유로는 치즈붕어빵 틀을 처음부터 새로 깎는 대신, 기본 틀을 물려받아 치즈를 넣는 단계만 더하는 거예요.

물려받으면 이렇게 돼요 — 교재의 Person과 Student

class Person:                 # Person 클래스를 정의해 주세요
    eyes = 2                  # 클래스 변수 eyes 에 2 를 담아 주세요
    def eat(self):            # eat 메서드를 정의해 주세요
        print('얌냠...')      # '얌냠...' 을 화면에 보여 주세요
    def sleep(self):          # sleep 메서드를 정의해 주세요
        print('쿨쿨...')      # '쿨쿨...' 을 화면에 보여 주세요
    def talk(self):           # talk 메서드를 정의해 주세요
        print('주절주절...')  # '주절주절...' 을 화면에 보여 주세요
class Student(Person):        # Person 을 상속받는 Student 클래스를 정의해 주세요
    def study(self):          # study 메서드를 정의해 주세요
        print('열공열공...')  # '열공열공...' 을 화면에 보여 주세요
kim = Student()               # kim 에 Student 인스턴스를 만들어 담아 주세요
kim.talk()                    # kim 에게 말을 시켜 주세요
kim.study()                   # kim 에게 공부를 시켜 주세요
print(kim.eyes)               # kim 의 eyes 를 화면에 보여 주세요
print(isinstance(kim, Person))        # kim 은 Person 인스턴스이기도 한가요?
print(issubclass(Student, Person))    # Student 는 Person 의 자식 클래스인가요?
print(hasattr(Person(), 'study'))     # Person 인스턴스에 study 가 있나요?

Student에는 study만 적었는데 talk와 eyes도 써져요. 반대로 부모 Person에는 study가 없어요. 물려주는 방향은 부모 → 자식 한 방향이에요. 교재는 이 관계를 화살표(자식 → 부모)로 그리고 “Student is a Person(학생은 사람이다)”으로 읽으라고 해요.

파이썬이 이름을 찾는 순서

부른 것찾는 순서 (인스턴스 → 자식 → 부모)
kim.talk()kim 인스턴스에 없음 → Student에 없음 → Person에서 찾음 → 실행
kim.study()kim 인스턴스에 없음 → Student에서 바로 찾음 → 실행
kim.eyeskim 에 없음 → Student에 없음 → Person의 클래스 변수를 찾음
나쁜 선택좋은 선택
코드를 복사해 두 클래스에 붙인다 → 나중에 “옷 색깔”을 추가하려면 사람 클래스와 학생 클래스를 각각 고쳐야 해요.class Student(Person):로 상속한다 → 부모 Person 한 곳만 고치면 자식 Student에도 반영돼요.

부모의 __init__도 불러 줘야 해요 — super()

부모에 __init__이 있는데 자식이 자기 __init__을 다시 적으면, 부모의 __init__은 자동으로 불리지 않아요. 부모가 하던 일(예: 속재료와 가격 적기)까지 하려면 자식의 __init__ 안에서 super().__init__(...)으로 부모 것을 직접 불러요. super()는 “지금 클래스의 부모”를 가리켜요. 가게 비유로는 치즈붕어빵 틀이 “기본 레시피를 먼저 따라 하고, 그 다음 치즈를 넣는” 순서예요.

class Bungeoppang:                                  # Bungeoppang 클래스를 정의해 주세요
    def __init__(self, filling, price=1000):        # 만들 때 불리는 __init__ 을 정의해 주세요
        self.filling = filling                      # 이 붕어빵의 filling 에 filling 을 담아 주세요
        self.price = price                          # 이 붕어빵의 price 에 price 를 담아 주세요
    def describe(self):                             # describe 메서드를 정의해 주세요
        return self.filling + "붕어빵 " + str(self.price) + "원"  # 소개 글자를 만들어 돌려주세요
class Cheese(Bungeoppang):                          # Bungeoppang 을 상속받는 Cheese 클래스를 정의해 주세요
    def __init__(self, filling, cheese_g, price=1500):  # Cheese 의 __init__ 을 정의해 주세요
        super().__init__(filling, price)            # 부모의 __init__ 을 불러 속재료와 가격을 적게 해 주세요
        self.cheese_g = cheese_g                    # 이 붕어빵의 cheese_g 에 cheese_g 를 담아 주세요
    def describe(self):                             # describe 메서드를 다시 정의해 주세요
        return super().describe() + " (치즈 " + str(self.cheese_g) + "g)"  # 부모의 소개 뒤에 치즈 양을 붙여 돌려주세요
c = Cheese("팥", 20)                                # c 에 팥, 치즈 20g 붕어빵을 만들어 담아 주세요
print(c.describe())                                 # c 의 소개를 화면에 보여 주세요
print(c.filling, c.price, c.cheese_g)               # c 의 세 칸을 화면에 보여 주세요
팥붕어빵 1500원 (치즈 20g)
팥 1500 20
순서일어나는 일
① Cheese("팥", 20)빈 인스턴스가 생기고 Cheese.__init__이 불려요
② super().__init__(filling, price)부모 Bungeoppang.__init__이 실행돼서 filling, price 칸이 채워져요
③ self.cheese_g = cheese_g다시 자식으로 돌아와 치즈 양 칸이 채워져요
④ describe()자식의 describe가 먼저 쓰이고(덮어쓰기), 안에서 super().describe()로 부모 소개를 받아 치즈 양을 붙여요

교재 흐름대로 작은 예도 하나 더 볼게요. 아래 Baby에서 super().__init__(name) 줄을 지우면 name 칸이 만들어지지 않아 오류가 나요.

class Human:                              # Human 클래스를 정의해 주세요
    def __init__(self, name):             # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                  # 이 인스턴스의 name 에 name 을 담아 주세요
class Baby(Human):                        # Human 을 상속받는 Baby 클래스를 정의해 주세요
    def __init__(self, name):             # Baby 의 __init__ 을 정의해 주세요
        super().__init__(name)            # 부모 Human 의 __init__ 을 name 으로 불러 주세요
        self.cute = True                  # 이 인스턴스의 cute 에 True 를 담아 주세요
    def cry(self):                        # cry 메서드를 정의해 주세요
        return self.name + " 응애"        # 이름과 " 응애" 를 이어서 돌려주세요
b = Baby("아기")                          # b 에 이름이 "아기" 인 Baby 를 만들어 담아 주세요
print(b.name, b.cute, b.cry())            # b 의 name, cute, 울음 결과를 화면에 보여 주세요
아기 True 아기 응애

덮어쓰기 — 같은 이름을 자식이 다시 적으면

자식이 부모와 같은 이름의 메서드를 적으면 자식 것이 먼저 쓰여요(덮어쓰기). 부모 것도 같이 쓰고 싶으면 super().메서드()로 불러요.

class Human:                              # Human 클래스를 정의해 주세요
    def __init__(self, name):             # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                  # 이 인스턴스의 name 에 name 을 담아 주세요
class Teen(Human):                        # Human 을 상속받는 Teen 클래스를 정의해 주세요
    def talk(self):                       # talk 메서드를 정의해 주세요
        return "아 몰라요"                # "아 몰라요" 를 돌려주세요
class Teen2(Teen):                        # Teen 을 상속받는 Teen2 클래스를 정의해 주세요
    def talk(self):                       # talk 메서드를 다시 정의해 주세요
        return super().talk() + "!"       # 부모의 talk 결과에 "!" 를 붙여 돌려주세요
print(Teen2("민수").talk())               # 이름이 "민수" 인 Teen2 의 말을 화면에 보여 주세요
아 몰라요!

핵심 한 줄: 자식은 부모 것을 그대로 쓰고, 같은 이름을 다시 적으면 자기 것이 먼저이며, 부모 것이 필요할 때는 super()로 불러요.

영상은 같은 개념을 “사람 시뮬레이션”으로 말해요. 사람 클래스에 이름·팔·다리를 한 번만 적고, 아기와 십대는 사람을 확장(extend)해서 아기는 울기, 십대는 투덜대기만 더해요.

마무리 — 클래스로 짰을 때 편해지는 점 3가지

장점왜 편한가
1. 데이터와 일이 한 곳에 모인다함수만 쓰면 딕셔너리와 describe 함수가 따로 놀아서 엉뚱한 딕셔너리를 넣어도 막을 수 없어요. 클래스는 x.describe()처럼 “이 붕어빵에게 시킨다”가 되고, 가능한 일이 틀 안에 모여 있어요
2. 모양이 통일돼 빠뜨림·오타가 준다Bungeoppang("팥")은 항상 같은 모양이고, 새 속성이 생기면 __init__ 한 곳만 고쳐요
3. 상속으로 복사 없이 늘린다치즈붕어빵처럼 달라지는 부분만 적고, 나머지는 부모 것을 그대로 써요

※ 작은 프로그램에서는 함수만으로도 충분해요. 같은 종류의 물건이 여러 개 나올 때부터 클래스가 편해져요.
