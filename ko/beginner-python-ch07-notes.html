7.1 클래스와 인스턴스

1. 틀과 결과물 (7.1)

말뜻
클래스(class)같은 종류의 객체가 갖는 공통점을 적어 둔 틀. “부류”. 예: 스케이터, 사과

메서드(method)클래스 안에 정의한 함수
만들기인스턴스 = 클래스()
쓰기인스턴스.메서드()

클래스 만들고 인스턴스 만들기

2. 왜 클래스를 쓰나 — 영상 요약

영상은 게임 플레이어를 예로 들어요. 플레이어를 하나씩 손으로 적으면 세 가지 문제가 생겨요.

문제왜 생기나
틀이 없어서 빠뜨림어떤 플레이어에는 skill 을 안 적고 넘어가도 아무도 알려 주지 않는다
오타helth처럼 속성 이름을 잘못 적어도 찾기 어렵다
고칠 곳이 많음경험치(xp)를 모든 플레이어에게 추가하려면 하나씩 찾아가 고쳐야 한다

해결은 “이름·체력·기술 값만 넣으면 플레이어 하나를 내주는 공장”을 한 곳에 만드는 거예요. 그 공장이 클래스예요. 영상은 클래스를 쿠키 틀, 인스턴스를 그 틀로 찍은 쿠키에 비유해요. 나중에 틀 한 곳만 고치면 이후에 찍는 쿠키가 모두 달라져요.

값을 받아서 만들기 — __init__

말뜻
__init__인스턴스를 만들 때 파이썬이 자동으로 한 번 불러 주는 특별한 메서드. 처음 속성 값을 정한다
self.이름 = 값이 인스턴스가 가질 속성(변수)을 저장한다
클래스(값1, 값2)값들이 __init__의 self 다음 매개변수로 들어간다
class Player:                                  # Player 클래스를 정의해 주세요
    def __init__(self, name, health, skill):   # 만들 때 자동으로 불리는 __init__ 을 정의해 주세요
        self.name = name                       # 이 인스턴스의 name 에 name 을 담아 주세요
        self.health = health                   # 이 인스턴스의 health 에 health 를 담아 주세요
        self.skill = skill                     # 이 인스턴스의 skill 에 skill 을 담아 주세요
        self.xp = 0                            # 이 인스턴스의 xp 에 0 을 담아 주세요
    def say_hello(self):                       # say_hello 메서드를 정의해 주세요
        return "안녕, 나는 " + self.name       # "안녕, 나는 " 과 이름을 이어서 돌려주세요
elon = Player("elon", 100, "coding")           # elon 에 Player 인스턴스를 만들어 담아 주세요
mark = Player("mark", 90, "design")            # mark 에 Player 인스턴스를 만들어 담아 주세요
print(elon.name, elon.xp)                      # elon 의 name 과 xp 를 화면에 보여 주세요
print(mark.say_hello())                        # mark 에게 인사를 시킨 결과를 화면에 보여 주세요
elon 0
안녕, 나는 mark

※ 영상의 자바스크립트 constructor가 파이썬의 __init__에 해당해요. 함수처럼 생겼지만 클래스 안에 있어서 메서드라고 불러요. xp 처럼 값을 받지 않고 항상 0으로 시작하게 정하는 것도 __init__ 안에서 해요.

붕어빵 틀로 보는 클래스와 인스턴스

붕어빵 틀은 하나뿐이고, 그 틀로 붕어빵을 여러 마리 구울 수 있어요.

붕어빵 가게파이썬
붕어빵 틀 (모양을 정해 둔 것)클래스 class Bungeoppang
틀로 구워 낸 붕어빵 한 마리인스턴스 Bungeoppang("팥")
속재료, 가격 (붕어빵마다 다름)속성 self.filling, self.price
붕어빵으로 하는 일 (가격 깎기, 소개하기)메서드 discount, describe

핵심 한 줄: 클래스는 먹을 수 없는 설계, 인스턴스는 그 설계로 만든 실물이에요. 같은 틀에서 나온 팥붕어빵과 슈크림붕어빵은 서로 다른 붕어빵이라서, 하나의 값을 바꿔도 다른 하나는 그대로예요.

※ 비유가 끊기는 곳이 하나 있어요. 실제 틀은 쇳덩이지만 파이썬 클래스는 코드라서, 틀을 고치면 이후에 만드는 인스턴스가 모두 달라져요.

함수만 쓸 때와 클래스로 쓸 때

def make_bread(filling, price):           # make_bread 함수를 정의해 주세요
    return {"filling": filling, "price": price}  # 속재료와 가격을 딕셔너리로 만들어 돌려주세요
def describe(b):                          # describe 함수를 정의해 주세요
    return b["filling"] + "붕어빵 " + str(b["price"]) + "원"  # 소개 글자를 만들어 돌려주세요
a = make_bread("팥", 1000)                # a 에 팥 붕어빵 정보를 만들어 담아 주세요
print(describe(a))                        # a 의 소개를 화면에 보여 주세요
팥붕어빵 1000원
class Bungeoppang:                        # Bungeoppang 클래스를 정의해 주세요
    def __init__(self, filling, price=1000):  # 만들 때 불리는 __init__ 을 정의해 주세요 (가격을 안 주면 1000)
        self.filling = filling                # 이 인스턴스의 filling 에 filling 을 담아 주세요
        self.price = price                    # 이 인스턴스의 price 에 price 를 담아 주세요
    def describe(self):                       # describe 메서드를 정의해 주세요
        return self.filling + "붕어빵 " + str(self.price) + "원"  # 소개 글자를 만들어 돌려주세요
    def discount(self, won):                  # discount 메서드를 정의해 주세요
        self.price -= won                     # 이 인스턴스의 price 에서 won 을 빼 주세요
x = Bungeoppang("팥")                         # x 에 팥 붕어빵을 만들어 담아 주세요
y = Bungeoppang("슈크림", 1500)               # y 에 가격이 1500 인 슈크림 붕어빵을 만들어 담아 주세요
x.discount(200)                               # x 의 가격을 200 깎아 주세요
print(x.describe())                           # x 의 소개를 화면에 보여 주세요
print(y.describe())                           # y 의 소개를 화면에 보여 주세요
팥붕어빵 800원
슈크림붕어빵 1500원

클래스로 짰을 때 편해지는 점 3가지

장점왜 편한가
1. 데이터와 일이 한 곳에 모인다함수만 쓰면 딕셔너리와 describe 함수가 따로 놀아서 엉뚱한 딕셔너리를 넣어도 막을 수 없다. 클래스는 x.describe() 로 “이 붕어빵에게 시킨다”가 되고, 가능한 일이 틀 안에 모여 있다
2. 모양이 통일돼 빠뜨림·오타가 준다딕셔너리는 price 를 빠뜨리거나 prise 로 적어도 실행 전엔 모른다. Bungeoppang("팥") 은 항상 같은 모양이고, 새 속성이 생기면 __init__ 한 곳만 고친다
3. 상속으로 복사 없이 늘린다치즈붕어빵이 필요할 때 코드를 복사하면 가격 계산을 두 곳에서 고쳐야 한다. 상속하면 달라지는 부분만 적는다
class Cheese(Bungeoppang):                # Bungeoppang 을 상속받는 Cheese 클래스를 정의해 주세요
    def describe(self):                   # describe 메서드를 다시 정의해 주세요
        return super().describe() + " (치즈 추가)"  # 부모의 소개 뒤에 " (치즈 추가)" 를 붙여 돌려주세요
print(Cheese("치즈").describe())          # 치즈 붕어빵의 소개를 화면에 보여 주세요
치즈붕어빵 1000원 (치즈 추가)

※ 작은 프로그램에서는 함수만으로도 충분해요. 같은 종류의 물건이 여러 개 나올 때부터 클래스가 편해져요. 이 예제는 파이썬으로 실제로 돌려서 출력을 넣었어요.

7.2 변수와 메서드

1. 변수와 메서드를 가진 클래스 (7.2)

말뜻
클래스 변수클래스 안, 메서드 밖에 적은 변수. 만든 인스턴스가 처음에 그대로 가져다 쓴다
메서드클래스 안의 함수. 첫 매개변수는 항상 self
self그 메서드를 부른 인스턴스. 정의할 때는 적고, 부를 때는 쓰지 않는다 (jane.attack())
self.변수 += 값그 인스턴스의 변수만 바꾼다
class Amazon:                       # Amazon 클래스를 정의해 주세요
    strength = 20                   # 클래스 변수 strength 에 20 을 담아 주세요
    dexterity = 25                  # 클래스 변수 dexterity 에 25 를 담아 주세요
    vitality = 20                   # 클래스 변수 vitality 에 20 을 담아 주세요
    energy = 15                     # 클래스 변수 energy 에 15 를 담아 주세요
    def attack(self):               # attack 메서드를 정의해 주세요
        return 'Jab!!!'             # 'Jab!!!' 를 돌려주세요
    def exercise(self):             # exercise 메서드를 정의해 주세요
        self.strength += 2          # 이 인스턴스의 strength 에 2 를 더해 주세요
        self.dexterity += 3         # 이 인스턴스의 dexterity 에 3 을 더해 주세요
        self.vitality += 1          # 이 인스턴스의 vitality 에 1 을 더해 주세요
jane = Amazon()                     # jane 에 Amazon 인스턴스를 만들어 담아 주세요
mary = Amazon()                     # mary 에 Amazon 인스턴스를 만들어 담아 주세요
print(jane.strength, jane.attack()) # jane 의 strength 와 공격 결과를 화면에 보여 주세요
jane.exercise()                     # jane 에게 훈련을 시켜 주세요
print(jane.strength, jane.dexterity, jane.vitality)  # jane 의 힘·기술·체력을 화면에 보여 주세요
20 Jab!!!
22 28 21

※ 위키독스 예제는 디아블로2 게임의 아마존 캐릭터를 클래스로 만든 거예요. 교재는 이 코드를 diablo2.py로 저장하고 import diablo2 한 뒤 diablo2.Amazon()으로 인스턴스를 만들어요.

2. self 가 왜 필요한가

jane과 mary는 같은 exercise 메서드를 써요. 메서드가 “누구의 힘을 올릴지” 알아야 하니, 부른 인스턴스가 자동으로 첫 매개변수 self에 들어와요.

부르는 모양일어나는 일
jane.exercise()self 가 jane 이 된다 → jane 의 strength 가 올라간다
mary.exercise()self 가 mary 가 된다 → mary 의 strength 가 올라간다
Amazon.exercise()부른 인스턴스가 없어서 self 를 채울 수 없다 → 오류
jane = Amazon()                          # jane 에 Amazon 인스턴스를 만들어 담아 주세요
mary = Amazon()                          # mary 에 Amazon 인스턴스를 만들어 담아 주세요
jane.exercise()                          # jane 에게 훈련을 시켜 주세요
print(jane.strength, mary.strength)      # jane 과 mary 의 strength 를 화면에 보여 주세요
print(Amazon.strength)                   # Amazon 클래스의 strength 를 화면에 보여 주세요
print(jane.__dict__)                     # jane 이 따로 가진 변수들을 화면에 보여 주세요
22 20
20
{'strength': 22, 'dexterity': 28, 'vitality': 21}

※ jane.strength += 2는 클래스 변수 20을 읽어 22로 계산한 뒤 jane 자신의 변수로 따로 저장해요. 그래서 mary와 Amazon 클래스의 값은 20 그대로예요. __dict__에는 jane 이 따로 가진 값만 나와서 energy는 보이지 않아요(jane 이 바꾸지 않았으니 클래스 값을 그대로 읽는 중이에요).

※ 영상은 self(자바스크립트에서는 this)를 “이 플레이어는 xp 라는 속성을 가진다”처럼 읽으면 쉽다고 해요. 그리고 메서드가 있으면 클래스가 데이터만 담는 상자에서 데이터를 읽고 바꾸는 방법까지 정해 둔 틀이 된다고 말해요. 메서드의 예로 인사하기, 공격 받았을 때 체력 줄이기를 들어요.

7.3 상속

1. 물려받기 (7.3)

말뜻
부모 클래스물려주는 클래스. 위키독스는 상위 클래스, 영상은 father class 라고 불러요
자식 클래스물려받는 클래스. 만들 때 class 자식(부모):
is a 읽기자식 → 부모 화살표를 따라 읽는다. “Student is a Person”(학생은 사람이다)
class Person:                 # Person 클래스를 정의해 주세요
    eyes = 2                  # 클래스 변수 eyes 에 2 를 담아 주세요
    def eat(self):            # eat 메서드를 정의해 주세요
        print('얌냠...')      # '얌냠...' 을 화면에 보여 주세요
    def sleep(self):          # sleep 메서드를 정의해 주세요
        print('쿨쿨...')      # '쿨쿨...' 을 화면에 보여 주세요
    def talk(self):           # talk 메서드를 정의해 주세요
        print('주절주절...')  # '주절주절...' 을 화면에 보여 주세요
class Student(Person):        # Person 을 상속받는 Student 클래스를 정의해 주세요
    def study(self):          # study 메서드를 정의해 주세요
        print('열공열공...')  # '열공열공...' 을 화면에 보여 주세요
kim = Student()               # kim 에 Student 인스턴스를 만들어 담아 주세요
kim.talk()                    # kim 에게 말을 시켜 주세요
kim.study()                   # kim 에게 공부를 시켜 주세요
print(kim.eyes)               # kim 의 eyes 를 화면에 보여 주세요
print(isinstance(kim, Person))        # kim 은 Person 인스턴스이기도 한가요?
print(issubclass(Student, Person))    # Student 는 Person 의 자식 클래스인가요?
print(hasattr(Person(), 'study'))     # Person 인스턴스에 study 가 있나요?

왜 복사해 붙이지 않고 상속하나

방법나중에 고칠 때
복사해 붙임나중에 “옷 색깔” 같은 것을 넣으려면 사람 클래스와 학생 클래스를 각각 고쳐야 한다
상속부모 한 곳만 고치면 자식에게도 반영된다

영상의 예도 같아요. 사람 시뮬레이션에 아기, 십대 클래스가 있으면 둘 다 이름·팔·다리를 갖는 “사람”이에요. 이 공통 부분을 사람 클래스에 한 번만 적고, 아기와 십대는 사람을 extend(확장)해서 자기만의 것(아기는 울기, 십대는 투덜대기)만 더해요. 영상은 이것으로 코드 중복을 줄이고 코드를 다시 쓸 수 있는 조각으로 나눈다고 말해요.

2. 부모의 __init__ 부르기 — super()

부모에 __init__이 있는데 자식이 자기 __init__을 다시 적으면, 부모의 __init__은 자동으로 불리지 않아요. 부모의 속성도 만들고 싶으면 자식의 __init__ 안에서 super().__init__(...)으로 부모 것을 불러 줘요. 영상은 이 줄이 빠지면 “사람의 이름을 정하는 부분이 실행되지 않아서” 코드가 동작하지 않는다고 설명해요(자바스크립트는 super()).

class Human:                              # Human 클래스를 정의해 주세요
    def __init__(self, name):             # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                  # 이 인스턴스의 name 에 name 을 담아 주세요
class Baby(Human):                        # Human 을 상속받는 Baby 클래스를 정의해 주세요
    def __init__(self, name):             # Baby 의 __init__ 을 정의해 주세요
        super().__init__(name)            # 부모 Human 의 __init__ 을 name 으로 불러 주세요
        self.cute = True                  # 이 인스턴스의 cute 에 True 를 담아 주세요
    def cry(self):                        # cry 메서드를 정의해 주세요
        return self.name + " 응애"        # 이름과 " 응애" 를 이어서 돌려주세요
b = Baby("아기")                          # b 에 이름이 "아기" 인 Baby 를 만들어 담아 주세요
print(b.name, b.cute, b.cry())            # b 의 name, cute, 울음 결과를 화면에 보여 주세요
아기 True 아기 응애

메서드 덮어쓰기와 super()

자식이 부모와 같은 이름의 메서드를 적으면 자식 것이 우선해요(덮어쓰기). 부모 것도 같이 쓰고 싶으면 super().메서드()로 불러요.

class Teen(Human):                          # Human 을 상속받는 Teen 클래스를 정의해 주세요
    def talk(self):                         # talk 메서드를 정의해 주세요
        return "아 몰라요"                  # "아 몰라요" 를 돌려주세요
class Teen2(Teen):                          # Teen 을 상속받는 Teen2 클래스를 정의해 주세요
    def talk(self):                         # talk 메서드를 다시 정의해 주세요
        return super().talk() + "!"         # 부모의 talk 결과에 "!" 를 붙여 돌려주세요
print(Teen2("민수").talk())                 # 이름이 "민수" 인 Teen2 의 말을 화면에 보여 주세요
아 몰라요!

※ 이 예제의 Human은 위 __init__ 예제의 것을 그대로 써요. 덮어쓰기는 위키독스 7.3에는 없고, 영상의 “자식은 부모 것 + 자기 것” 설명을 이어서 이 글이 덧붙인 내용이에요.
