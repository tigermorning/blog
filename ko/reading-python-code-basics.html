파이썬 코드 눈으로 읽기 — 함수·변수·반복·오류·async

2026. 9. 3.

이 블로그에는 파이썬 코드 블록이 종종 나와요. 그런데 저도 처음엔 코드가 나오면 눈이 미끄러졌어요. 그래서 이 글을 따로 썼어요. 목표는 파이썬을 "쓰는" 게 아니라 "읽는" 것이에요. 바이브 코딩 시대에는 코드를 AI가 쓰고 사람은 그 코드가 뭘 하는지 확인하는 일이 훨씬 많거든요. 여기서 다루는 열 가지만 알면 이 블로그의 코드 블록은 전부 "아, 이런 뜻이구나" 하고 넘어갈 수 있어요. 마지막에는 실제 실험 코드 한 덩어리를 한 줄씩 같이 읽어요.

먼저 파이썬이 뭔지 한 줄로요. 파이썬은 사람이 읽기 쉽게 만든 프로그래밍 언어예요. 컴퓨터에게 시킬 일을 영어 비슷한 문장으로 적으면, 파이썬이라는 프로그램이 그걸 한 줄씩 읽어 실행해요. 코드 파일은 확장자가 .py예요.

1. 변수 — 값에 이름표를 붙인다

last = None
name = "locator"
count = 25

=는 수학의 "같다"가 아니라 "오른쪽 값을 왼쪽 이름에 담아라"예요. 상자에 이름표를 붙이는 거죠. 그 뒤로는 이름만 부르면 값이 나와요. 값의 종류는 이 정도만 알면 돼요.

코드에서한국어로
"locator", 'A'글자. 따옴표로 감싸요. 큰따옴표·작은따옴표 같은 뜻
25, 1500숫자
None"아직 아무것도 없음". 빈 상자
True, False참·거짓
["Read", "Grep", "Glob"]리스트. 대괄호 안에 여러 값을 순서대로 나열
{"locator": locator}딕셔너리. 중괄호 안에 "이름표: 값" 짝. 사전처럼 이름표로 값을 찾아요

딕셔너리에 값을 넣는 모양도 자주 나와요. extra["error"] = err는 "extra라는 사전에 error라는 이름표로 err의 값을 넣어라"예요.

2. 함수 — 이름 붙인 작업 묶음

def greet(name):
    return "안녕, " + name

greet("서연")   # 결과: "안녕, 서연"

def는 "지금부터 함수를 정의한다"는 신호예요. 함수는 여러 줄의 작업에 이름을 붙여 둔 거고, 이름 뒤에 괄호를 붙여 부르면 실행돼요. 괄호 안의 name은 인자, 함수에 넘겨주는 재료예요. return은 "이 값을 돌려주고 끝"이에요.

두 가지를 꼭 봐 두세요. 첫째, 들여쓰기. 파이썬은 줄 앞의 빈칸으로 "이 줄들이 함수 안에 속한다"를 표시해요. 괄호로 감싸지 않아요. 둘째, # 뒤는 주석이에요. 컴퓨터는 무시하고 사람만 읽어요. 함수 첫 줄에 """..."""로 감싼 긴 문장이 있으면 그것도 설명문(docstring)이라 무시해도 돼요.

함수를 부를 때 greet(name="서연")처럼 이름표를 붙여 재료를 넘기는 모양도 많아요. 이걸 키워드 인자라고 하는데, 재료가 많을 때 순서를 안 외워도 되니 편해요. 이 블로그의 코드는 대부분 이 모양이에요.

ClaudeAgentOptions(cwd=str(repo), model=MODEL, max_turns=25)

읽는 법: "ClaudeAgentOptions라는 설정 묶음을 만드는데, 작업 폴더는 repo, 모델은 MODEL, 최대 턴은 25로." 대문자로 시작하는 이름은 보통 "무언가를 만드는 틀"이라고 보면 돼요.

3. 반복과 분기 — for, if

for tool in ["Read", "Grep", "Glob"]:
    print(tool)

if arm == "A":
    run_single()
elif arm == "B":
    run_workflow()
else:
    run_orchestration()
코드에서한국어로
for x in 목록:목록의 값을 하나씩 꺼내 x에 담고, 아래 들여쓴 줄을 반복
if 조건:조건이 참이면 아래 들여쓴 줄 실행
elif 조건:"아니면 혹시 이 조건이면"
else:"다 아니면"
=="같은가?" 비교. 등호 하나(=)는 담기, 둘(==)은 비교
or, and"또는", "그리고"

4. 오류 잡기 — try, except

try:
    result = risky_job()
except Exception as e:
    print("실패:", e)

"try 아래를 시도해 보고, 도중에 오류가 나면 죽지 말고 except 아래로 와라. 그 오류를 e라는 이름에 담아 둬라." 이 구조가 있으면 프로그램이 오류로 멈추는 대신 오류 내용을 기록하고 계속 갈 수 있어요. ValueError 같은 이름은 오류의 종류예요. "값이 이상하다"는 뜻이고요.

5. 문자열 다루기 — f-string, 줄바꿈, 자르기

problem = "단위가 사라짐"
prompt = f"Fix this bug:\n\n{problem}"
short = str(e)[:200]
  • f"...{이름}..." — 따옴표 앞에 f가 붙으면, 중괄호 안의 이름이 그 값으로 바꿔치기돼요. 위 예에서 prompt는 "Fix this bug: (빈 줄) 단위가 사라짐"이 돼요.
  • \n — 줄바꿈 기호예요. 두 개면 빈 줄 하나.
  • str(e) — 오류 e를 글자로 바꿔요. [:200]은 앞에서 200글자까지만 잘라요. [:2000]이면 2000글자.

6. 점(.)과 import — "누구의 무엇"

import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions

msg.result
repo.name
type(m).__name__

import는 "남이 만들어 둔 도구 상자를 가져와라"예요. from A import B는 "A 상자에서 B만 꺼내라". API나 SDK(개발용 도구 모음)를 쓴다는 건 대개 이 한 줄로 시작해요.

점은 "~의"예요. msg.result는 "msg의 result". 점 뒤에 괄호가 붙으면(text.strip()) "text가 가진 strip이라는 동작을 실행"이에요. strip()은 앞뒤 공백 지우기. 낯선 것 두 개만 미리 풀어 둘게요.

  • getattr(m, "subtype", None) — "m에 subtype이라는 칸이 있으면 그 값을, 없으면 None을 줘라." m.subtype과 같은데 칸이 없어도 오류가 안 나는 버전이에요.
  • type(m).__name__ — "m의 종류 이름". 이 값이 "ResultMessage"면 "결과 메시지"라는 종류라는 뜻이에요.

7. async와 await — 기다리는 동안 다른 일

식당 주방을 떠올려 보세요. 국을 끓이는 20분 동안 가만히 서 있지 않고 다른 반찬을 만들죠. 컴퓨터도 AI 서버의 답을 기다리는 몇 초 동안 다른 일을 할 수 있는데, 그걸 가능하게 하는 문법이 async/await예요. (컴퓨터가 여러 일을 번갈아 처리하는 원리는 CPU·코어·프로세스·스레드란?에서 다뤘어요.)

코드에서한국어로
async def f():"기다림이 들어 있는 함수"를 정의. 그냥 def와 읽는 법은 같아요
await 무언가"이게 끝날 때까지 기다려라(그동안 다른 일 해도 됨)"
async for m in query(...):"query가 메시지를 하나씩 보내 줄 때마다 받아서 m에 담고 반복". 일반 for에 기다림이 섞인 것
asyncio.wait_for(작업, 1500)"이 작업을 기다리되 1500초 넘으면 포기". 시간제한
asyncio.run(main())"main이라는 async 함수를 실제로 시작". 프로그램의 출발 버튼

읽을 때 요령: async와 await는 지우고 읽어도 뜻이 통해요. "기다린다"는 표시일 뿐이니까요.

8. 파일 실행과 가상 환경 — 터미널 한 줄

.venv/bin/python arms.py A sympy__sympy-24909

이 줄은 파이썬이 아니라 터미널에 치는 명령이에요. 읽는 법: ".venv/bin/ 안에 있는 파이썬으로 arms.py 파일을 실행하되, A와 sympy__sympy-24909를 덧붙여 넘겨라." 뒤에 붙는 두 단어는 명령행 인수라고 하는데, 함수의 인자와 같은 역할이에요. 프로그램이 시작하면서 "어느 실행? 어느 문제?"를 이걸로 받아요.

.venv는 가상 환경이에요. 프로젝트 폴더 안에 파이썬과 부품(패키지)을 따로 담아 두는 작은 방이죠. 컴퓨터 전체의 파이썬에 이것저것 설치하면 프로젝트끼리 부품 버전이 충돌하기 때문에, 프로젝트마다 방을 하나씩 만들어요. 윈도우에서는 경로가 .venv\Scripts\python으로 조금 달라요.

10. 실전 — 실험 코드 한 덩어리를 줄별로 읽기

이제 같은 버그를 세 방식으로에 나오는 함수를 그대로 가져와 읽어 볼게요. 처음 보면 어렵지만, 위 아홉 가지만으로 전부 풀려요.

async def _run_once(prompt, options):
    """(마지막 ResultMessage, 오류문) 반환."""
    last = None
    try:
        async for m in query(prompt=prompt, options=options):
            t = getattr(m, "subtype", None) or type(m).__name__
            if t == "result" or type(m).__name__ == "ResultMessage":
                last = m
    except Exception as e:
        return last, f"{type(e).__name__}: {str(e)[:200]}"
    return last, None
줄한국어로
async def _run_once(prompt, options):"한 번 실행" 함수를 정의. 재료는 질문(prompt)과 설정(options). 기다림이 들어 있음
"""(마지막 ResultMessage, 오류문) 반환."""설명문. "마지막 결과 메시지와 오류 문장, 둘을 돌려준다"
last = None"마지막 결과"를 담을 빈 상자 준비
try:아래를 시도. 오류 나면 except로
async for m in query(...):AI에게 질문을 보내고, 돌아오는 메시지를 하나씩 m에 받으며 반복
t = getattr(m, "subtype", None) or type(m).__name__메시지의 세부 종류가 있으면 그걸, 없으면 메시지의 종류 이름을 t에 담음
if t == "result" or ...:그 종류가 "결과"라면
last = m이 메시지를 "마지막 결과" 상자에 넣음 (다음 결과가 오면 덮어씀)
except Exception as e:도중에 오류가 났다면
return last, f"{type(e).__name__}: {str(e)[:200]}"지금까지의 마지막 결과와, "오류종류: 오류내용(200자까지)" 문장을 돌려주고 끝
return last, None오류 없이 끝났으면 마지막 결과와 "오류 없음"을 돌려줌

한 문장으로 줄이면 이래요. "AI에게 한 번 물어보고, 돌아온 메시지 중 마지막 결과만 챙기되, 중간에 오류가 나도 죽지 말고 오류 문장을 같이 돌려줘라." 코드 열한 줄이 결국 이 한 문장이에요. 이 블로그의 다른 코드 블록도 같은 방식으로 읽으면 돼요. 한 줄씩 한국어로 바꾸고, 마지막에 한 문장으로 뭉쳐요.
