"API를 활용해서 뭘 한다"는 말을 처음 들었을 때, 저는 순간 "그거 AI 얘기 아니야?"라고 생각했어요. 발음이 비슷하니까요. 찾아보니 AI와는 전혀 다른 개념이더라고요. 그런데 사전을 찾아봐도 "응용 프로그램 프로그래밍 인터페이스"라는 번역만 나올 뿐, 이 말로는 하나도 이해가 안 됐어요. 결국 API가 정확히 뭐냐는 질문에 제대로 답하려면 단어를 하나씩 뜯어보는 것부터 시작해야 했어요.

"인터페이스"의 원래 뜻, 그리고 식당에 비유해보면

API는 Application Programming Interface의 앞글자예요. 이 중에서 뜻을 제대로 잡아야 하는 건 마지막 인터페이스(interface)인데, 이 단어는 원래 컴퓨터와 아무 상관이 없었어요.

inter(사이)와 face(면)를 붙인 말로, 19세기 과학에서 물과 기름처럼 서로 다른 두 물질이 맞닿는 경계면을 가리키던 용어였어요. 지금도 일상에서 그대로 쓸 수 있는 뜻이에요. 자동차의 운전대와 페달은 사람과 엔진이 맞닿는 면이에요. 엔진이 어떻게 연료를 태우는지 하나도 몰라도, 운전대를 돌리고 페달을 밟는 정해진 방식만 알면 자동차를 움직일 수 있어요.

여기에 앞의 두 단어를 붙여볼게요. 애플리케이션(application)은 우리가 쓰는 프로그램 하나하나(카카오톡, 크롬, 엑셀 같은 것)를 가리키는 말이고, 프로그래밍은 그 프로그램을 만드는 일이에요. 그러니까 API는 "프로그램과 프로그램이 맞닿아서 주고받는 지점"이라는 뜻이 돼요.

여기까지 정리하고 나서도 저는 여전히 손에 안 잡혔어요. "맞닿는 지점"이 실제로 어떻게 생겼는지, 뭐가 오가는지가 하나도 그려지지 않았거든요. 그래서 실제로 어떤 일이 벌어지는지를 따라가 봤어요.

제일 잘 맞아떨어진 그림은 식당이었어요. 등장인물은 셋이에요.

  • 손님 = 내가 만든 프로그램
  • 주방 = 남의 회사 컴퓨터에서 24시간 돌아가고 있는 프로그램. 이 "남의 컴퓨터"를 서버(server)라고 불러요. 요청을 받아서 답을 내주는 일만 하는 컴퓨터예요.
  • 웨이터 = API

손님은 주방에 직접 들어가지 않아요. 들어갈 수도 없고, 들어가 봐야 요리법도 모르죠. 대신 웨이터에게 정해진 방식으로 주문하면, 웨이터가 그걸 주방에 전달하고 완성된 요리를 다시 들고 나와요. 손님과 주방이 맞닿는 유일한 지점이 웨이터인 거예요. 아까 말한 "맞닿는 면", 그게 정확히 웨이터의 자리예요. 이 대응 관계를 표로 정리해봤어요.

식당에서API에서는
손님은 주방에 못 들어가고, 웨이터에게 정해진 방식으로만 주문한다내 프로그램은 남의 서버 내부를 몰라도, 정해진 형식으로 API에 요청한다
주방이 셰프를 바꾸거나 조리 도구를 바꿔도, 주문 방식만 같으면 손님은 아무 영향 없다서버 안쪽 코드가 통째로 바뀌어도, API 형식만 그대로면 내 프로그램은 한 줄도 안 고쳐도 된다
아무나 주방에 들어와 냄비를 뒤질 수 없다API를 거치지 않고는 남의 서버 내부 데이터에 함부로 접근할 수 없다

핵심: 웨이터가 손님과 주방 사이에 선 유일한 통로이듯, API는 내 프로그램과 남의 서버 사이에 선 유일한 통로예요. 통로가 하나로 고정돼 있어서, 안쪽이 바뀌어도 바깥은 그대로 쓸 수 있는 거예요.

그런데 여기서 걸리는 게 하나 있어요. 손님이 웨이터에게 "아무거나 맛있는 거"라고 말하면 주문이 안 되잖아요. 정해진 방식으로 주문해야 한다면, 그 방식은 어디에 적혀 있을까요.

메뉴판이 없으면 주문할 수가 없어요 — 국립국어원 오픈API로 확인하기

식당에서 그 역할을 하는 게 메뉴판이에요. 뭘 시킬 수 있는지, 뭐라고 불러야 하는지, 옵션은 뭐가 있는지가 다 적혀 있죠. API에도 똑같은 게 있고, 그걸 API 문서라고 불러요.

API 문서에는 대략 이런 게 적혀 있어요. 어느 주소로 요청을 보내야 하는지, 요청할 때 뭘 같이 적어 보내야 하는지(예: 찾을 단어), 그리고 답이 어떤 모양으로 돌아오는지. 한마디로 "이렇게 물어보면 이렇게 답해줄게"라는 약속을 적어둔 문서예요. 이 약속이 없으면 아무리 좋은 API도 쓸 수가 없어요. 메뉴판을 안 주는 식당에서 주문할 수 없는 것과 같아요.

이 약속이라는 게 말로만 들으면 여전히 추상적인데, 제가 실제로 들여다본 API가 하나 있어요.

국립국어원은 표준국어대사전 오픈API라는 걸 제공해요. 여기서 오픈API는 그 회사·기관 안에서만 쓰는 게 아니라, 신청만 하면 누구나(대개 무료로) 쓸 수 있게 공개해둔 API를 말해요.

쓰는 방식은 식당 그대로예요. 제 프로그램(손님)이 웨이터에게 "이 단어, 표준국어대사전에 어떻게 실려 있나요"라고 문서에 적힌 형식으로 주문하면, 국립국어원 서버(주방)가 사전을 검색해서 표제어와 뜻풀이 같은 결과를 돌려줘요.

제가 여기서 가장 크게 느낀 건 따로 있어요. 사전 전체를 제 컴퓨터에 복사해둘 필요가 전혀 없다는 거예요. 원본 사전은 국립국어원에 그대로 있고, 저는 필요할 때마다 물어보기만 해요. 그래서 사전 내용이 개정되면 제 프로그램은 아무것도 안 고쳐도 그날부터 최신 답을 받아요. 남의 주방을 빌려 쓴다는 게 단순히 "만들기 귀찮아서"가 아니라, 원본을 가진 쪽이 계속 관리해주는 상태로 쓴다는 뜻이라는 걸 이때 알게 됐어요.

여기까지 오니 처음의 헷갈림으로 돌아갈 준비가 됐어요. 그럼 이 그림 어디에 AI가 있는 걸까요.

그래서 AI는 이 식당 어디에 있는 걸까 — 정리하며 마무리

AI(인공지능)는 데이터를 학습해서 스스로 판단하고 결과를 만들어내는 능력이에요. 식당으로 치면 주방에서 일하는 요리사의 실력에 해당해요. 반면 API는 그 실력을 손님이 받아 갈 수 있게 이어주는 웨이터예요. 하나는 주방 안의 능력이고, 하나는 주방 밖으로 나오는 통로라서 애초에 층이 달라요.

그래서 API는 AI와 아무 상관 없는 곳에 훨씬 더 많이 쓰여요. 날씨 API, 지도 API, 결제 API 전부 AI가 한 톨도 안 들어가 있어요. 그냥 남의 주방에 주문을 넣는 거예요. 반대로 "AI API를 쓴다"는 건 주방에 AI 요리사가 있는 식당에 주문을 넣는다는 뜻이고요.

제가 처음에 둘을 헷갈린 이유도 이제 설명이 돼요. 요즘은 AI 기능을 갖다 쓸 때 거의 항상 API를 통해 쓰다 보니, 두 단어가 늘 붙어 다니거든요. 하지만 붙어 다닌다고 같은 말은 아니었어요.

API가 뭔가요. 이제 한 문장으로 답할 수 있어요. 남의 프로그램 속을 하나도 몰라도, 정해진 형식으로 물어보기만 하면 원하는 결과를 받아올 수 있게 열어둔 창구예요. inter+face, 서로 다른 둘이 맞닿는 면이라는 원래 뜻 그대로예요. 웨이터가 손님과 주방 사이에 서 있듯, API는 내 프로그램과 남의 서버 사이에 서 있고, 그 주문 방식을 적어둔 메뉴판이 API 문서예요.

그리고 AI와 헷갈리지 않는 법도 간단해졌어요. AI는 주방의 실력, API는 주방 밖으로 나오는 통로. 통로 너머에 AI가 있을 수도 있고, 날씨 정보가 있을 수도 있고, 국어사전이 있을 수도 있는 거예요.

저는 번역 감수(맞춤법·띄어쓰기·외래어 표기 검토) 자동화에 관심이 있는데, 이런 API를 활용하면 사람이 매번 사전을 찾아보는 반복 작업을 프로그램이 대신할 수 있어요. 이 프로젝트 이야기는 다음 글에서 자세히 다뤄볼게요.

직접 해보기: 브라우저 주소창에 https://jsonplaceholder.typicode.com/users/1을 쳐보세요. 로그인도 설치도 필요 없는 연습용 오픈API예요. 화면에 이름·이메일·주소 같은 값이 텍스트로 쭉 나오는데, 그게 바로 "메뉴판(API 문서)에 적힌 대로 주문했더니 웨이터가 들고 나온 요리"예요. 주소 끝의 1을 2로 바꿔보면 다른 사람 정보가 나오는데, 이게 "몇 번 손님 정보 주세요"라고 정해진 형식으로 다시 주문한 것과 같아요.
