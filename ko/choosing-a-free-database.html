무료로 쓸 수 있는 데이터베이스 고르기

2026. 7. 24.

※ 이 글은 모두의연구소 AI AIFFEL 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 Little Bobby Tables — SQL 주입과 백업

"무료로 시작하고 싶은데 뭘 골라야 하지?" 서비스마다 다른 제한을 비교하다 보면 머리가 아파지는데, 가입은 쉬워도 저장 용량이나 사용량 제한을 놓치면 발표 직전에 앱이 멈출 수 있어요. 그래서 목적과 제한을 함께 보고 고르는 기준이 필요했어요. 비전공자도 무료로 진짜 데이터베이스를 쓸 수 있지만, 시작하기 전에 한 가지만 기억하면 됐어요 — 무료 티어는 배우기·MVP(초기 버전)용이지, 큰 규모의 운영용은 아니다.

무료 데이터베이스 비교

내 서비스가 SQL 표와 로그인·파일저장을 한 번에 원하는지, 아니면 DB만 필요한지부터 적어보면 고르기 쉬워졌어요. 무료 한도는 가입 직전에 공식 가격 페이지에서 다시 확인하는 습관이 안전해요.

서비스종류확인한 점비전공자에게
SupabasePostgreSQL (SQL)Free 프로젝트당 DB 500MB, 스토리지 1GB. 자동 백업 미포함, 1주 미사용 시 일시정지 가능로그인·파일까지 한 번에 실습할 때
NeonPostgreSQL (SQL)Free는 개발·프로토타이핑용, 유휴 컴퓨트가 scale-to-zero될 수 있음순수 Postgres와 브랜치를 써보고 싶을 때
TursoSQLiteFree: DB 100개, 저장소 5GB, 월 읽기 5억 행·쓰기 1천만 행SQLite 기반의 가벼운 서비스를 실험할 때
PlanetScaleMySQL (Vitess 기반)개발용 단일 노드 월 $5부터, 무료 티어 없음. 별도 상품으로 PostgreSQL도 제공무료만이 조건이면 다른 후보부터 검토

이 표를 보면서 지난 글에서 본 "공짜의 세계는 계속 줄어드는 중"이라던 배포 시리즈의 무료 호스팅 이야기가 다시 떠올랐어요. 정책은 언제든 바뀔 수 있으니, 가입 직전 공식 가격 페이지 확인은 매번 거치는 습관으로 삼기로 했어요.

클라우드 말고, 내 컴퓨터에 직접 설치해서 무료로

지금까지는 '남의 컴퓨터(클라우드)'를 빌리는 무료 티어를 봤는데, DB는 내 컴퓨터에 직접 설치해서도 무료로 쓸 수 있었어요. 대부분 오픈소스라 설치도 사용도 공짜예요. SQLite는 설치도 서버도 필요 없어요 — DB 전체가 파일 하나라서, 서버를 따로 켤 필요 없이 그 파일을 앱이 직접 읽고 써요. 가장 가볍게 시작하기 좋아서 작은 앱·프로토타입·모바일 앱이 즐겨 써요. PostgreSQL·MySQL은 회사들이 실제로 쓰는 진짜 오픈소스 DB를 내 컴퓨터에 무료로 설치하는 방법이에요. 클라우드에서 빌리던 것과 같은 걸 내 손안에서 돌리는 셈이죠. Docker를 쓰면 설치가 번거로울 때 DB를 '컨테이너'로 명령 한 줄에 띄울 수 있어요. 내 컴퓨터를 어지럽히지 않고 켜고, 필요 없으면 통째로 지울 수 있어요.

로컬(내 컴퓨터)은 완전 무료, 오프라인에서도 되고, 내 데이터가 내 손안에 있어서 개발·학습·실험에 최고였어요. 단, 남에게 열려면 결국 배포하거나 터널이 필요하고, 내 컴퓨터가 꺼지면 멈춰요. 클라우드는 24시간 켜져 있고 남에게 안정적으로 열리니 실제 서비스엔 이쪽이 맞았어요. 그래서 흔한 흐름은 내 컴퓨터(로컬)에서 만들고 → 세상에 낼 때 클라우드로 옮기는 거였어요. 실제로 이 노드의 실습에서도 똑같은 순서로 Todo 앱을 만들어봤어요 — 먼저 로컬 SQLite 파일 하나(todo.db)에 저장하는 앱을 완성해서 껐다 켜도 데이터가 남는 걸 확인하고, 그다음 같은 앱을 Supabase(클라우드 Postgres)로 옮겨 RLS를 켜는 순서였어요. 할 일 추가·완료·삭제라는 CRUD 네 동작을 손으로 직접 눌러보니, 지금까지 글로만 읽었던 표·행·해시·RLS가 훨씬 실감 났어요.

무료 티어, 시작 전에 확인할 것

확인할 건 다섯 가지였어요. 용량 한도(예: 500MB — 이미지 같은 큰 파일을 많이 넣으면 금방 차요), 미사용 시 일시정지(예: Supabase는 1주일 안 쓰면 프로젝트가 잠깐 멈추지만 다시 켜면 돼요), 백업 방법(앞서 본 참사를 피하려면 자동 백업이 되는 요금제인지 꼭 확인), 정책 변경(PlanetScale처럼 무료가 사라질 수 있어요), 트래픽이 늘면 유료(서비스가 커지면 자연스럽게 유료로 넘어가니 요금·용량 알림을 켜둬요).

문법을 몰라도, 무엇을 저장할지와 조건만 주면 AI가 스키마 설계부터 연결·보안까지 도와줬어요. 저는 이렇게 요청했어요 — "내 서비스에 데이터를 저장하려고 해. 나는 비전공자고 무료로 시작하고 싶어. 내가 저장할 것은 [상품, 주문]인데 어떤 표와 항목이 필요할지 스키마를 제안해줘. 무료 SQL 데이터베이스 기준으로 이 스키마를 만드는 방법을 알려줘. 접속 정보(비밀번호·키)는 코드에 넣지 말고 환경변수로 빼줘. DB에 값을 넣을 때는 파라미터화 쿼리로 처리하고, 비밀번호는 해시로 저장해줘." 뒤의 두 조건은 배포 시리즈에서 배운 환경변수·보안, 그리고 이번 시리즈에서 배운 SQL 주입 방어와 그대로 이어졌어요.

여기까지가 데이터베이스의 전체 그림이었어요. 왜 필요한지에서 시작해서, 60년의 역사, SQL과 표 설계, 트랜잭션과 정규화, 회원가입·로그인의 데이터 관점, 보안과 백업, 그리고 무료로 시작하는 법까지 — 일곱 편에 걸쳐 정리해봤어요. 백엔드 시리즈와 이번 데이터베이스 시리즈를 합치면, 화면 뒤에서 데이터가 어떻게 오가고 어디에 쌓이는지 전체 그림이 잡혀요. 다음엔 이 위에서 AI 에이전트가 직접 도구를 쓰는 하네스 엔지니어링 이야기로 이어져요.
