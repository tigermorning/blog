2026. 11. 19.

※ 이 글은 위키독스 『왕초보를 위한 Python』 7.1~7.3절의 내용을 한 프로그램 안에서 이어서 써 보도록 만든 실습입니다. 게임 플레이어를 예로 드는 방식은 노마드 코더의 「객체지향 프로그래밍? 문과도 이해쌉가능. 10분컷.」(영어 자동 자막 전체를 읽음, 화면은 보지 못함)을 참고했어요. 코드 실행 결과는 파이썬으로 실제로 돌려서 넣었어요.

작은 게임 하나를 5단계로 키우면서, 클래스와 인스턴스, self, 상속, super()를 한 프로그램 안에서 이어서 써 봐요.

시작하기 전에

앞 글의 문제는 코드 조각 하나씩 읽고 푸는 방식이었어요. 이 글은 같은 프로그램에 단계마다 코드를 더해 가는 방식이에요. 실제 프로그램도 이렇게 자라요. 문법은 7장 객체지향 정리(7.1~7.3)에 있어요.

  • 준비: 파이썬 파일 하나(예: game.py)를 만들어 두고, 단계마다 코드를 더한 뒤 실행해서 기대 출력과 비교해요.
  • 정답 코드는 그 단계까지의 전체 코드예요. 앞 단계를 풀지 못했어도 이어서 할 수 있어요.

각 단계는 아래 세 부분으로 이뤄져 있고, 정답은 모두 접혀 있어서 눌러야 보여요.

단계 1 — 플레이어 만들기

문제 — 코드 쓰기

아래 조건에 맞게 코드를 직접 써 보세요.

  • Player(name, health) 클래스를 만들어요. 이름과 체력을 저장하고, 경험치 xp는 항상 0으로 시작해요.
  • say_hello()는 "안녕, 나는 이름" 글자를 돌려줘요.

코드를 다 쓴 뒤 확인용 실행 줄을 클래스 정의 아래에 붙여 실행해요. 아래 기대 출력과 같게 나오면 성공이에요.

    pass

세 값은 __init__에서 self.이름 = 값으로 저장해요. xp는 받지 않고 __init__ 안에서 0으로 정해요. 메서드의 첫 매개변수는 self예요.

정답 코드 보기 (이 단계까지의 전체 코드) 
class Player:                                 # Player 클래스를 정의해 주세요
    def __init__(self, name, health):         # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 플레이어의 name 에 name 을 담아 주세요

    def say_hello(self):                      # say_hello 메서드를 정의해 주세요

단계 2 — 피해 받기

문제 — 코드 쓰기

아래 조건에 맞게 코드를 직접 써 보세요.

코드를 다 쓴 뒤 확인용 실행 줄을 클래스 정의 아래에 붙여 실행해요. 아래 기대 출력과 같게 나오면 성공이에요.

상태를 바꾸는 일은 메서드가 self.health를 직접 바꿔서 해요. max(0, 값)은 0과 값 중 큰 쪽을 돌려줘서 음수를 막아요.

정답 코드 보기 (이 단계까지의 전체 코드) 
class Player:                                 # Player 클래스를 정의해 주세요
    def __init__(self, name, health):         # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 플레이어의 name 에 name 을 담아 주세요
        self.health = health                  # 이 플레이어의 health 에 health 를 담아 주세요
        self.xp = 0                           # 이 플레이어의 xp 에 0 을 담아 주세요
    def say_hello(self):                      # say_hello 메서드를 정의해 주세요
        return "안녕, 나는 " + self.name      # 인사말을 만들어 돌려주세요
    def take_hit(self, damage):               # take_hit 메서드를 정의해 주세요

        return self.health                    # 줄어든 health 를 돌려주세요
    def is_alive(self):                       # is_alive 메서드를 정의해 주세요
        return self.health > 0                # health 가 0 보다 크면 True 를 돌려주세요

단계 3 — 몬스터 만들기 — 공통 부분을 부모로

문제 — 코드 쓰기

아래 조건에 맞게 코드를 직접 써 보세요.

  • 플레이어와 몬스터가 모두 가진 name, health, take_hit, is_alive를 부모 클래스 Character로 옮겨요.
  • Player는 Character를 물려받고 xp와 say_hello만 자기 것으로 가져요. __init__에서 super().__init__(...)을 써요.
  • Monster(name, health, power)도 Character를 물려받고, attack(target)은 상대에게 power만큼 take_hit를 시키고 상대의 남은 체력을 돌려줘요.

코드를 다 쓴 뒤 확인용 실행 줄을 클래스 정의 아래에 붙여 실행해요. 아래 기대 출력과 같게 나오면 성공이에요.

# Character, Player, Monster 세 클래스를 만드세요.

힌트 보기

같은 코드를 두 클래스에 복사하지 말고 부모에 한 번만 적어요. 자식의 __init__은 먼저 super().__init__(name, health)로 부모 몫을 맡기고 자기 몫을 저장해요. attack은 target.take_hit(...)를 부르면 돼요.

정답 코드 보기 (이 단계까지의 전체 코드) 
class Character:                              # Character 클래스를 정의해 주세요 (플레이어와 몬스터의 공통 부분)
    def __init__(self, name, health):         # 만들 때 불리는 __init__ 을 정의해 주세요
        self.name = name                      # 이 캐릭터의 name 에 name 을 담아 주세요
        self.health = health                  # 이 캐릭터의 health 에 health 를 담아 주세요
    def take_hit(self, damage):               # take_hit 메서드를 정의해 주세요
        self.health = max(0, self.health - damage)  # health 를 damage 만큼 줄이되 0 밑으로는 안 내려가게 해 주세요
        return self.health                    # 줄어든 health 를 돌려주세요
    def is_alive(self):                       # is_alive 메서드를 정의해 주세요
        return self.health > 0                # health 가 0 보다 크면 True 를 돌려주세요
class Player(Character):                      # Character 를 상속받는 Player 클래스를 정의해 주세요
    def __init__(self, name, health):         # Player 의 __init__ 을 정의해 주세요
        super().__init__(name, health)        # 부모의 __init__ 을 name, health 로 불러 주세요
        self.xp = 0                           # 이 플레이어의 xp 에 0 을 담아 주세요
    def say_hello(self):                      # say_hello 메서드를 정의해 주세요
        return "안녕, 나는 " + self.name      # 인사말을 만들어 돌려주세요
class Monster(Character):                     # Character 를 상속받는 Monster 클래스를 정의해 주세요
    def __init__(self, name, health, power):  # Monster 의 __init__ 을 정의해 주세요
        super().__init__(name, health)        # 부모의 __init__ 을 name, health 로 불러 주세요
        self.power = power                    # 이 몬스터의 power 에 power 를 담아 주세요
    def attack(self, target):                 # attack 메서드를 정의해 주세요
        return target.take_hit(self.power)    # 상대에게 power 만큼 피해를 주고 상대의 남은 체력을 돌려주세요
hero = Player("elon", 100)                    # hero 에 체력 100 인 Player 를 만들어 담아 주세요
slime = Monster("슬라임", 30, 12)             # slime 에 체력 30, 힘 12 인 Monster 를 만들어 담아 주세요
print(hero.say_hello())                       # hero 의 인사말을 화면에 보여 주세요
print(slime.attack(hero))                     # slime 이 hero 를 공격한 뒤 hero 의 체력을 화면에 보여 주세요
print(slime.attack(hero))                     # slime 이 hero 를 한 번 더 공격한 뒤 hero 의 체력을 화면에 보여 주세요
print(slime.is_alive(), hero.is_alive())      # slime 과 hero 는 각각 살아 있나요?

방금 쓴 코드를 떠올리며 먼저 머릿속으로(또는 종이에) 답해 보고, 각 질문 아래 “답 보기”를 열어 비교해요.

질문 3-1. Player와 Monster에는 take_hit를 적지 않았는데 hero.take_hit(...)이 되는 이유는? 파이썬은 어디를 어떤 순서로 찾나요?

답 보기

이름을 찾을 때 인스턴스 → 자기 클래스(Player) → 부모 클래스(Character) 순서로 올라가고, Character에서 take_hit를 찾아 실행해요. 공통 코드를 부모에 한 번만 적은 덕분이에요.

질문 3-2. Monster.__init__에서 super().__init__(name, health) 줄을 지우면 slime.attack(hero)와 slime.is_alive()는 각각 어떻게 될까요?

답 보기

돌려 보면 88(공격은 self.power만 쓰니 성공), 다음 줄에서 AttributeError: 'Monster' object has no attribute 'health'예요. 부모 __init__이 불리지 않아 health가 만들어지지 않았기 때문이에요. 오류는 만드는 줄이 아니라 health를 읽는 줄에서 나요.

hero = Player("elon", 100)                    # hero 에 체력 100 인 Player 를 만들어 담아 주세요
tank = Warrior("mark", 100)                   # tank 에 체력 100 인 Warrior 를 만들어 담아 주세요
dragon = Boss("드래곤", 200, 20)              # dragon 에 체력 200, 힘 20 인 Boss 를 만들어 담아 주세요
for target in [hero, tank]:                   # hero 와 tank 를 하나씩 target 으로 꺼내 주세요
    print(target.name, dragon.attack(target)) # dragon 이 target 을 공격한 뒤 이름과 남은 체력을 화면에 보여 주세요
elon 60
mark 80

일반 플레이어는 20을 두 번 맞아 60, 전사는 10을 두 번 맞아 80이에요. Boss를 더하려고 Monster나 Player 코드는 하나도 고치지 않았어요.
