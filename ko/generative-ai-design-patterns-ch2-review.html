2.1 · 로짓 마스킹
Q1

로짓 마스킹이 정확히 어느 시점에, 무엇을 하는 건가?

모델이 다음 토큰을 고르기 직전, 후보 토큰마다 매겨진 점수(로짓) 중에서 규칙을 어기는 후보의 점수를 음의 무한대(선택 확률 0)로 떨어뜨린다. 전체 글이 다 만들어진 뒤 검사하는 게 아니라, 토큰이 하나씩 나올 때마다 실시간으로 개입한다는 점이 핵심이다.

추가문제

규칙을 만족하는 후보가 하나도 안 남으면 어떻게 되나?

한 걸음 물러나(역추적) 방금 만든 토큰을 취소하고 그 이전 지점에서 다시 시도한다. 그래도 안 되면 최대 시도 횟수를 넘겼는지 확인하고, 넘겼으면 거절 메시지를 낸다.

📓 examples/01_logits_masking/0_logits_masking.ipynb 
class BrandLogitsProcessor(LogitsProcessor):
    def __call__(self, input_ids, input_logits):
        output_logits = input_logits.clone()
        for idx, seq in enumerate(input_ids):
            decoded = self.tokenizer.decode(seq)
            num_matches[idx] = evaluate(decoded, self.positives, self.negatives)
        max_matches = np.max(num_matches)
        for idx in range(len(input_ids)):
            if num_matches[idx] != max_matches:
                output_logits[idx] = -10000
        return output_logits
직접 검증해볼 것

evaluate() 함수 정의를 찾아보라 — positives·negatives 판정이 의미(semantic)를 보는가, 다른 방식인가? 이걸로 "특정 토큰을 막아도 모델이 동의어로 우회할 수 있는가"에 답해보라.

확인 포인트: num_positive = np.sum([1 for phrase in positives if phrase in descr]) — 문자열이 그대로 포함되는지(리터럴 매칭)만 본다. 실제로 책 예제에서 모델은 금지어 "품질(quality)"을 피하려 목록에 없는 "프리미엄(premium)"으로 우회했다 — 의미는 같지만 리스트에 없는 동의어라면 걸러지지 않는다는 뜻이다.

Q2

"될 때까지 재시도" 방식은 왜 안티패턴인가?

성공률이 낮아질수록 재시도 횟수가 기하급수적으로 늘어난다. 성공률 90%면 평균 1.1회로 괜찮지만, 30%로 떨어지면 평균 3.3회(지연시간 +230%), 운 나쁘면 13회까지 필요할 수 있다. 게다가 언젠가 반드시 성공한다는 보장도 없다. 성공률이 아주 높을 때만 봐줄 만한 방식이다.

2.2 · 문법
Q3

문법 패턴은 로짓 마스킹과 원리가 같다는데, 실질적으로 뭐가 다른가?

원리(토큰 후보의 확률을 0으로 만든다)는 완전히 같다. 다른 건 그 검열을 누가 실행하느냐다. 로짓 마스킹은 우리가 직접 만든 코드가 클라이언트 쪽에서 감시하고, 문법 패턴은 우리가 규칙(BNF나 스키마)만 넘기면 모델 제공업체의 서버가 알아서 감시해준다.

📓 두 방식의 코드 비교 — 02_grammar/1_applying_grammar.ipynb 
# 로짓 마스킹: 텍스트로 되돌린 뒤 검사 (모델 교체에 비교적 안전)
decoded = self.tokenizer.decode(seq)

# 문법: 토크나이저 어휘집에 직접 묶어서 매핑을 미리 계산 (모델 교체 시 재계산 필요)
grammar = IncrementalGrammarConstraint(grammar_str, "root", pipe.tokenizer)
직접 검증해볼 것

모델(그래서 tokenizer도)을 바꾸면 이 두 패턴 중 뭐가 먼저 깨지는지, 위 두 줄만 보고 판단해보라.

확인 포인트: 문법(BNF)이 먼저 깨진다. IncrementalGrammarConstraint는 문법 상태별 허용 토큰 ID를 그 tokenizer 어휘집 기준으로 미리 계산해두므로, 모델을 바꾸면 이 매핑을 처음부터 다시 만들어야 한다. 로짓 마스킹은 decode()로 텍스트를 되돌린 뒤 검사하므로 tokenizer가 바뀌어도 apply_rules 로직 자체는 거의 재사용된다 — 텍스트 레벨 vs 토큰 레벨의 차이가 이식성 차이로 이어진다.

Q4

BNF 문법과 파이썬 데이터클래스, 언제 뭘 골라야 하나?

상황선택
단순 표현 수준을 넘는 복잡한 검증 로직이 필요할 때BNF 문법
규칙이 동적이거나 DB·규칙엔진에서 가져와야 할 때BNF 문법
빠르게 작성하고, 서버 쪽에서 처리해 지연시간을 줄이고 싶을 때데이터클래스
로그 확률 접근이 안 되는 모델을 써야 할 때데이터클래스
📓 examples/02_grammar/1_applying_grammar.ipynb — 실제 실행 결과 
# 문법: root ::= (expr "=" ws term "\n")+   (등호만 허용, 부등호 없음)
# 질문: "Bill·Mae 중 누가 사과가 오렌지보다 많은가?" (원래 > 비교가 필요)
1 +2 = 3 2 +4 = 6 3 = 3 6 = 6 3 = 6 3 = 6 3 = 6 ... ("3 = 6" 무한 반복)
직접 검증해볼 것

이 결과가 왜 나왔는지 문법 정의에서 찾아보라. 그리고 "문법 제약을 걸면 정확도도 같이 오르는가?"에 답해보라.

확인 포인트: 문법이 ">" 기호를 아예 안 열어줘서, 모델은 정답 (3+2)>(2+4)를 구조적으로 쓸 수 없다 — 형식은 끝까지 완벽하게 지켜지면서 내용은 "3=6"이라는 명백히 틀린 문장을 반복한다. 형식 100% 보장이 정확도 향상을 보장하지 않는다. 그래서 형식이 완벽해 보인다고 다운스트림 검증 로직(값의 논리적 타당성 확인)까지 지우면 안 된다 — 그 방심 자체가 새로운 위험(자동화 편향)이다.

2.3 · 스타일 전이
Q5

퓨샷 학습과 미세조정, 트레이드오프는?

퓨샷은 구현이 간단하지만 예시가 늘수록 프롬프트가 길어져 지연시간·컨텍스트 한계에 부딪히고, 스타일 강제력도 암묵적이다. 미세조정은 더 많은 예시(보통 100개 이상)로 더 정교하고 빠르고 저렴하게 실행되지만, 데이터 큐레이션·훈련 비용·전문 역량이라는 부담이 따른다.

Q6

스타일 전이를 쓸 수 있으려면 어떤 세 조건이 맞아야 하나?

① 바꾸고 싶은 원본 콘텐츠는 이미 있거나 쉽게 구할 수 있고(가용 콘텐츠), ② 원하는 스타일이 규칙으로 표현하기 어려울 만큼 미묘하며(미묘한 스타일), ③ 전문가가 실제로 변환한 입력-출력 예시를 몇 개라도 갖고 있어야(전이 예시 확보) 한다. 이 중 ③이 없다면 다음 절의 역중립화를 대신 써야 한다.

2.4 · 역중립화
Q7

역중립화는 스타일 전이와 근본적으로 뭐가 다른가?

스타일 전이는 사람이 직접 만든 입력-출력 예시 쌍이 있어야 한다. 역중립화는 그런 쌍이 없어도 된다 — 대신 AI로 중립 버전을 먼저 만들고, 그 과정의 입력· 출력을 뒤집어서 훈련 데이터를 스스로 만들어낸다.

Q8

역중립화의 세 단계는? "역"이라는 이름은 어디서 왔나?

① 중립 콘텐츠 생성(개인 스타일 글 → 중립 버전으로 재작성), ② 입력·출력을 뒤집어 훈련 데이터셋 생성(중립 버전이 입력, 원래의 개인 스타일이 출력), ③ 그 데이터셋으로 미세조정. 1단계의 입력·출력을 2단계에서 거꾸로 뒤집기 때문에 "역"중립화라고 부른다.

Q9

과다 중립화란 무엇이고 왜 문제인가?

중립화를 지나치게 강하게 걸어서, 스타일뿐 아니라 콘텐츠의 내용이나 명확성 자체까지 사라지는 현상이다. 내용이 스타일과 너무 얽혀 있는 텍스트일수록 위험이 크므로, 여러 중립 형태를 실험해서 의미가 가장 잘 보존되는 것을 골라야 한다.

2.5 · 콘텐츠 최적화
Q10

전통적 A/B 테스트의 세 가지 문제를, 콘텐츠 최적화는 각각 어떻게 우회하나?

구별 불가는 "매번 두 개를 직접 비교해서 이긴 쪽을 그때그때 A로 부르는" 방식으로, 불확실한 테스트는 "테스트 = 한 번의 비교"로 통계적 유의성 요구 자체를 없애는 방식으로, 결과 적용 불가는 "프롬프트는 그대로 두고 모델 가중치 자체를 선호도 조정으로 바꿔버리는" 방식으로 우회한다.

Q11

DPO 훈련 데이터셋 한 줄은 어떤 세 정보로 구성되나?

prompt(같은 프롬프트, 재작성한 경우 원본), chosen (승자로 판정된 콘텐츠), rejected(패자로 판정된 콘텐츠). 이 세 필드로 이루어진 예시를 수십~수백 개 모은 것이 훈련 데이터셋이다.

Q12

"분포 내 요구사항"이 왜 중요한가?

선호도 조정은 어디까지나 이미 낼 수 있는 답들 중 어느 쪽을 더 자주 내느냐를 바꾸는 것이지, 모델에 새로운 사실이나 새 토큰을 가르치지는 못한다. 그래서 콘텐츠를 생성하는 모델이 만든 결과물은, 반드시 선호도 조정으로 훈련될 모델이 이미 낼 수 있는 범위 안에 있어야 한다.

후속질문

소규모 모델이 애초에 그런 수준의 콘텐츠를 못 낸다면?

더 큰 모델로 콘텐츠를 만든 뒤, 소규모 모델을 그 콘텐츠를 낼 수 있는 수준까지 먼저 지도학습(지시사항 조정)으로 끌어올리고, 그다음에 DPO를 수행하는 "어려운 방법"을 쓴다.

Q13

DPO는 왜 예시 100개 정도의 적은 데이터로도 충분한가?

통상적인 딥러닝은 데이터의 양이 중요하지만, 선호도 조정은 데이터의 질이 훨씬 중요하다. 책의 예제에서도 예시 100개로 GPU 한 장에서 약 3분 만에 훈련이 끝났다. 그래서 평가만 자동화돼 있다면 네 단계 전체를 빠르게 반복해서, 매번 더 나아진 모델로 훈련 데이터셋 자체를 계속 개선해나갈 수 있다.

2장 전체
Q14

다섯 패턴 중 실제로는 뭘 기준으로 골라야 하나?

규정 준수가 필수라면 강제력이 확실한 로짓 마스킹·문법을 먼저 고려한다. 스타일을 규칙으로 못 박기 어렵지만 예시는 있다면 스타일 전이를, 예시(원본)조차 없다면 역중립화를 쓴다. 무엇이 좋은 스타일인지 아무도 설명 못 한다면 콘텐츠 최적화로 "이겼다/졌다"만 계속 판정시켜 모델이 스스로 찾아가게 한다. 실무에서는 이 다섯을 섞어 쓰는 경우가 많다 — 예를 들어 문법으로 형식을 강제한 콘텐츠끼리 콘텐츠 최적화로 문체를 겨루게 할 수도 있다.

한 장 지도로 정리하면 — 실시간 검열(2.1)·정해진 서식(2.2)·견습(2.3)·뒤집기 요령(2.4)·서바이벌 오디션(2.5). 앞으로 갈수록 사람이 규칙을 덜 적어주고, 모델이 예시나 판정 결과로부터 스스로 더 많이 알아내야 하는 방향으로 나아간다는 게 이 다섯 칸의 숨은 순서예요.
