채널은 메신저와 게이트웨이를 잇는 입구이고, 텔레그램을 붙일 때는 봇 토큰으로 입구를 열되 페어링 승인으로 "누가 말을 걸 수 있는지"를 따로 잠근다.

여기까지는 컴퓨터 앞에 앉아 WebChat으로만 대화했어요. 이번 편에서는 폰의 텔레그램에서 메시지를 보내면 1편에서 본 게이트웨이에 도착하게 만들어요. 강의는 텔레그램만 실제로 연결했고, 디스코드와 슬랙은 "같은 순서로 열린다"는 것만 보여 줬어요. 저도 그 순서를 따라요.

비유 — 아파트 현관과 인터폰

아파트 1층 현관은 아무나 밀고 들어올 수 없어요. 방문객이 인터폰으로 호수를 누르면, 집 안에서 화면으로 얼굴을 보고 "열어 줄게"를 눌러야 문이 열려요. 한 번 등록한 가족은 카드로 그냥 들어오고요. 현관 자체는 늘 거기 있지만, 문은 잠겨 있고 열쇠는 집 안에 있어요.

핵심 한 줄: 입구를 여는 일(토큰)과 누구를 들일지 정하는 일(페어링)은 별개의 두 열쇠예요.

전체 흐름

읽는 법: 세로 점선 왼쪽이 폰에서 하는 일, 오른쪽이 컴퓨터 터미널에서 하는 일이에요. 화살표가 좌우를 오가는 게 이 흐름의 특징이에요. 굵은 상자 ④가 문을 여는 열쇠 단계라, 여기를 안 하면 ③에서 보낸 메시지에 봇이 답하지 않아요.

① 봇 만들기 — BotFather

텔레그램에는 BotFather라는 공식 서비스가 있어요. 사용자가 봇을 손쉽게 만들 수 있게 텔레그램이 제공하는 "봇을 만드는 봇"이에요. 텔레그램에서 @BotFather를 찾아 대화창에 /newbot을 보내고, 화면 안내에 따라 표시 이름과 bot으로 끝나는 봇 이름을 입력해요. 그러면 토큰이 발급돼요.

토큰1은 봇을 대신해 텔레그램에 접속하는 비밀값이에요. 이걸 가진 사람은 누구든 내 봇 행세를 할 수 있어요. 그래서 채팅창, 화면 공유, 메모에 적지 않고 안전한 비밀 보관 위치에 둬요. 만약 대화에 남겼다면 BotFather에서 새 토큰을 발급하고 이전 토큰은 버려요. "지우면 되지"가 아니라 "바꿔야" 해요. 이미 본 사람이 있을 수 있으니까요. 비밀값을 다루는 감각은 프록시 서버란 무엇인가 — API 키를 대신 들어주는 서버에서 다뤘던 것과 같아요.

② 게이트웨이에 토큰 연결

텔레그램은 다른 채널과 달리 channels login 같은 로그인 명령이 없어요. 설정에 토큰을 넣고 게이트웨이를 시작하는 방식이에요. 큰따옴표 안을 방금 보관한 토큰으로 바꿔요.

openclaw config set channels.telegram.botToken "여기에_봇_토큰"
openclaw gateway

config set은 3편에서 본 설정 파일 openclaw.json의 한 항목을 바꾸는 명령이에요. channels.telegram.botToken은 "채널 중 텔레그램의 봇 토큰"이라는 항목 경로예요. 게이트웨이가 이미 실행 중이면 재시작해요. 그다음 폰에서 새 봇 대화창을 열어 짧은 인사말 하나를 보내요.

③ ④ 누가 말 걸었는지 구분한다 — 페어링

채널이 열렸다고 바로 누구나 대화할 수 있는 건 아니에요. 텔레그램의 기본 DM2 정책인 페어링(pairing)은 첫 메시지를 보낸 계정을 승인 대기 목록에 올리고, 승인된 계정만 봇과 대화하게 하는 규칙이에요. 입구는 열려 있지만 문은 잠긴 상태이고, 페어링 승인이 열쇠예요. 첫 메시지를 보낸 뒤 터미널에서 대기 코드를 읽고 승인해요.

openclaw pairing list telegram
openclaw pairing approve telegram <코드>

규칙이 몇 가지 있어요. 승인 전 대기 중인 코드만 1시간 뒤 만료돼요. 한 번 승인하면 이후에는 코드 없이 대화가 이어지고요. 승인이 안 된 채 시간이 지난 경우에만 새 코드를 받아 다시 승인해요. 승인하지 않은 계정의 메시지에는 봇이 답하지 않아요. 그리고 강의가 특히 강조한 것 하나. 텔레그램 계정을 사람 이름으로 추측하지 말고, 승인 목록에 뜬 계정으로 구분해요. 이름은 누구나 바꿀 수 있어서요.

다른 입구도 같은 문을 둔다 — 디스코드·슬랙

오늘은 텔레그램만 연결했지만, 디스코드와 슬랙도 같은 순서예요. 토큰은 비밀로 보관하고, 대화할 계정의 범위를 먼저 제한해요. 세부 절차만 조금 달라요.

표를 보면서 제가 느낀 건, 세부 명령은 달라도 "비밀값을 받아 설정에 넣고, 게이트웨이를 켜고, 누가 말할 수 있는지 제한한다"는 뼈대는 셋이 똑같다는 거예요. 2편에서 Tailscale 이야기를 했는데, 그건 이미 떠 있는 WebChat 화면을 다른 기기에서 보는 길이고, 여기 세 채널은 에이전트가 메시지를 받을 새 입구를 여는 길이에요. 서로 다른 일이에요.

나쁜 선택 vs 좋은 선택 — 현관에서

나쁜 선택좋은 선택
봇 토큰을 실수로 단체 채팅방에 붙여 넣고, 메시지만 삭제한 뒤 그 토큰을 계속 쓴다 → 이미 본 사람이 내 봇 행세를 할 수 있고, 삭제는 그걸 막지 못한다. BotFather에서 새 토큰을 발급받아 설정을 바꾸고, 옛 토큰은 다시는 쓰지 않는다 → 노출된 열쇠가 무효가 된다.
"내 친구 이름이네" 하고 승인 목록의 계정을 이름만 보고 승인한다 → 텔레그램 표시 이름은 누구나 바꿀 수 있어서, 모르는 사람이 내 에이전트에 말을 걸게 된다. 승인 목록의 계정 ID를 본인에게 직접 확인한 뒤 승인하고, 혼자 쓰는 봇이면 allowlist로 내 ID만 남긴다 → 입구가 내가 아는 계정으로만 좁혀진다.

승인하지 않은 다른 계정(가족 폰 등, 동의를 받고)으로 봇에게 메시지를 보내 보세요. 봇이 답하지 않는 것, 그리고 openclaw pairing list telegram에 새 대기 코드가 뜨는 것을 확인해요. 그 코드를 승인하지 않고 1시간 뒤 다시 목록을 보면 사라져 있어요. "입구는 열려 있고 문은 잠겨 있다"를 몸으로 확인하는 실험이에요.

  1. 토큰 — 여기서는 서비스 접속을 허가하는 비밀 문자열을 뜻하며, AI가 글을 세는 단위인 토큰은 AI 토큰이란에서 다뤘어요. ↩
  2. DM — 단체방이 아니라 1:1로 보내는 직접 메시지(Direct Message). ↩
  3. numeric Telegram ID — 표시 이름과 달리 바꿀 수 없는, 텔레그램이 계정마다 붙여 둔 숫자 식별자. ↩
  4. 환경 변수 — 프로그램이 시작할 때 읽는 "이름=값" 꼴의 설정으로, 비밀값을 코드나 설정 파일에 직접 적지 않기 위해 자주 써요. ↩
