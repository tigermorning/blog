에이전트에게 컴퓨터를 맡길 때 — 안전과 권한

에이전트는 단순 답변기가 아니라 실제로 파일을 지우고, 명령을 실행하고, 외부에 요청을 보낼 수 있는 존재였어요. 그래서 좋은 도구는 위험한 행동 전에 "이거 해도 될까요?"를 물어요. 문제는 이게 반복되면 사람이 무심코 "예"만 누르게 된다는 거였어요 — 실제로 사용자들이 권한 요청의 약 93%를 그냥 승인한다는 조사가 있대요. 권한 방식은 도구마다 이름은 달라도 개념은 같았어요.

모드동작위험도
매번 확인모든 행동 전에 승인을 물음가장 안전, 대신 느림
편집만 자동파일 편집은 자동, 명령 실행 등은 확인낮음
위험한 것만 막고 나머지 자동삭제·배포 같은 되돌리기 어려운 행동만 확인중간
아무것도 안 물어봄전부 자동 승인공식적으로 폐기 가능한 실험 환경 전용

제가 챙기기로 한 안전 습관은 셋이었어요 — 중요한 폴더에서 '자동 수락'을 켜지 않기(문서·사진이 든 폴더, 회사 자료 폴더에선 매번 확인 모드로), 되돌릴 지점을 먼저 만들기(위험한 작업 전 커밋해두면 잘못돼도 그 지점으로 롤백할 수 있어요), 그리고 핵심 원칙 한 문장 — "아무것도 안 물어봄"과 "중요한 것에 대한 전체 접근"을 동시에 켜지 않기. 앞서 백엔드에서 본 'AI 코드의 45% 보안 결함'과도 통했어요 — 편함과 위험은 같이 온다는 것. 편해질수록 "이 작업이 뭘 건드리지?"를 한 번 더 보는 게 사람의 몫이었어요.

한 걸음 더: 에이전트를 여럿으로 나누면 토큰 비용이 어떻게 달라지는지(Anthropic 사례의 "채팅 대비 약 15배"를 어떻게 읽어야 하는지)는 나누면 좋아질까 — 멀티 에이전트의 득실과 판정표에서 다뤄요.

한 걸음 더: 여기서 다룬 "승인 방식"을 실제 연구 수치와 도구 설정으로 훨씬 깊게 판 글이 덜어내기와 경계 긋기 — 미니멀과 권한·보안이에요. 프롬프트 인젝션 방어 수치(Spotlighting), 고위험 도구의 실제 실패율(ToolEmu), 그리고 OpenClaw·Claude Code·opencode가 승인 범위를 실제로 어떻게 설정으로 나누는지까지 다뤄요.

내 컴퓨터에서 도는 AI — 로컬 모델과 오픈웨이트 판세

지금 쓰는 클라우드 AI는 회사 서버에서 돌지만, Ollama 같은 도구를 쓰면 오픈 모델을 내 컴퓨터에서 직접 돌릴 수도 있었어요. 좋은 점은 사생활과 비용이에요 — 입력한 내용이 기기 밖으로 안 나가고("클라우드 AI는 정책으로 사생활을 지키고, 로컬 AI는 구조로 지킨다"는 말이 인상 깊었어요), 사용료가 없고 오프라인에서도 돼요. 아쉬운 점은 성능과 사양이에요 — 집 컴퓨터에서 돌릴 수 있는 모델은 최신 클라우드 모델보다 대체로 뒤처지고, 어려운 추론엔 약해요. 결론은 아직은 클라우드 모델이 무난하되, "계약서·개인정보처럼 민감한 자료를 다룰 땐 로컬, 어려운 작업엔 클라우드"라는 섞어 쓰기 감각이었어요.

'모델 + 하네스'에서 모델 쪽에도 요즘 큰 판이 벌어지고 있었어요. Anthropic(Claude)은 모델의 가중치(모델의 '두뇌'에 해당하는 수치 뭉치)를 공개하지 않고, "최고 성능을 유지하며 값을 받는다"는 전략으로 반드시 자기 서버(API)로만 써요. OpenAI는 절충이에요 — 최상위는 닫아 두되, 한 급 낮은 모델은 가중치를 풀어 "AI를 자기 컴퓨터에서 돌려야 하는 곳(병원·은행·정부)"을 붙잡아요. 반전은, 정작 가장 센 '열린(오픈웨이트) 모델'은 중국에서 나오고 있다는 거였어요 — DeepSeek, 알리바바의 Qwen, Moonshot의 Kimi, Z.ai의 GLM이 자유 라이선스로 가중치를 공개하는데, 코딩 실력이 최상위 모델과 몇 점 차로 바짝 붙었고 일부 항목은 앞선대요. 다만 가장 어려운 표준 벤치마크의 최상단은 아직 폐쇄 모델이 지키고 있고, '오픈웨이트 = 공짜'도 아니라는 것도 함께 기억해야 했어요 — 큰 모델을 직접 돌리려면 고성능 GPU가 잔뜩 필요하니까요. 요점은, 이제 모델은 갈아 끼우는 부품이고 실력 격차가 좁혀지면서 값·자체 실행(사생활)·특정 회사 종속이 진짜 선택 기준이 된다는 거였어요.

에이전트는 왜 '비쌀' 수 있나 — 토큰과 컨텍스트

에이전트가 강력한 데는 비용이 따라와요. 앞서 본 계획-실행-관찰-반성 루프를 여러 번 도는 동안 AI는 매번 상황을 다시 읽고 생각해요. 그래서 에이전트는 보통의 채팅보다 사용량(토큰)을 약 4배, 여러 에이전트가 협업하면 약 15배까지 쓴대요. 요금은 보통 입력 토큰(지시문·파일·이전 대화·도구 결과)과 출력 토큰(모델이 새로 쓰는 양)을 따로 계산하고, 한 번의 호출에서 모델이 참고할 수 있는 총량에는 한도(컨텍스트 창)가 있어요.

여기서 에이전트 비용이 왜 눈덩이처럼 커지는지가 보였어요. 에이전트는 한 작업도 여러 번 호출하고, 매 단계에 앞선 대화와 도구 결과를 통째로 다시 포함해요. 그러면 단계 수가 늘수록 입력량은 선형보다 빠르게 커질 수 있어요. 예를 들어 매 단계마다 5천 토큰짜리 대화 이력을 통째로 다시 보내면, 3번째 단계에선 그 이력이 세 번 겹쳐 들어가 이미 1만 5천 토큰이 반복분으로 쌓여요. 그래서 실전 규율은 하나였어요 — 한 번에 거대한 작업을 통째로 시키지 말고 작게 쪼개기. 큰 파일·긴 로그는 필요한 부분만 주고, 작업이 끝나면 짧은 요약만 남기는 거예요. "토큰을 무조건 적게"가 아니라 다음 판단에 필요한 증거만 남기는 게 목표였어요.

대화가 길어져 컨텍스트 창이 꽉 차기 시작하면 이상한 일이 벌어져요 — 아까 정한 걸 잊고, 앞뒤가 안 맞고, 없는 파일명을 지어내기도 해요. 이걸 반쯤 농담으로 '컨텍스트 부패(context rot)'라고 부른대요. 그래서 실용 팁은 "작업 단위로 대화를 정리하라"였어요 — 한 작업이 끝나면 요약해 압축하거나, 전혀 다른 작업으로 넘어갈 땐 완전히 새 대화로 리셋하는 거예요. 규칙 파일(AGENTS.md)에 적은 규칙은 리셋해도 유지된다는 것도 챙길 점이었어요. 큰 일을 하나의 AI가 다 하는 대신 여러 AI에게 나눠 맡기는 서브에이전트 방식도 있는데, 강력하지만 그만큼 토큰도 크게 늘어서(여러 에이전트가 협업하면 보통 채팅의 십수 배까지) 실무에선 "지휘하는 AI는 똑똑한 모델, 잔일 하는 AI는 값싼 모델"로 등급을 나눠 비용을 아낀대요. 다음 글에서는 이런 확장들을 통째로 묶어 쓰는 플러그인과, 코드보다 먼저 의도를 적어두는 명세 주도 개발을 볼게요.

이럴 때 의심하세요 — 에이전트에게 맡긴 뒤 파일이나 한도가 이상할 때

권한과 토큰 문제는 대개 일이 끝난 뒤에 알게 돼요. 승인은 이미 눌렀고, 파일은 이미 바뀌었고, 한도는 이미 찼거든요. 그래서 증상이 보이면 모델 탓을 하기 전에 에이전트가 실제로 한 일의 기록부터 봐요.

증상이 아직 없어도, AI에게 이런 부탁을 하기 직전이라면 한 번 확인하고 넘어가요.

  • "안 쓰는 파일 정리해 줘", "설정 바꿔서 배포까지 해 줘" — 지금 승인 모드가 무엇인지, 되돌릴 커밋을 만들어 뒀는지
  • "여러 에이전트로 나눠서 한꺼번에 해 줘" — 정말 나눌 만큼 큰 일인지. 나누는 만큼 토큰도 몇 배로 늘어요
이런 증상이 보이면먼저 열어 볼 자리확인 방법
에이전트 작업이 끝났는데 부탁하지 않은 파일까지 바뀌었거나 사라졌어요. 중간에 승인을 몇 번 눌렀는데, 뭘 허락했는지 기억이 안 나요 에이전트 화면에 남은 실행한 명령 기록과, 프로젝트의 Git 변경 목록이에요. 사라진 파일은 편집 기록보다 삭제·이동 명령 쪽에서 찾는 게 빨라요 터미널에서 git status로 바뀐 파일과 지워진 파일을 봐요. 작업 전에 커밋해 뒀다면 그 지점으로 되돌릴 수 있어요(위험한 작업 전 커밋). 다만 한 번도 커밋하지 않은 파일은 Git도 못 살려요
문서나 회사 자료가 든 폴더에서, 에이전트가 파일을 고치고 명령을 돌리는데 한 번도 묻지 않아요 지금 켜진 승인 모드와 에이전트를 실행한 폴더예요. Claude Code라면 입력창 아래에 자동 수락 표시가 떠 있는지, 실행할 때 --dangerously-skip-permissions를 붙였는지 봐요 Claude Code는 Shift+Tab을 누를 때마다 모드가 바뀌어요. 중요한 폴더에서는 매번 확인으로 두고, 전부 자동은 지워져도 괜찮은 실험 폴더에서만 켜요
예전엔 묻던 특정 명령만 어느 순간부터 묻지 않고 바로 실행돼요 승인 창에서 앞으로는 묻지 말라는 선택지를 골랐던 기록이에요. 그 선택은 허용 목록으로 남아요. Claude Code라면 /permissions로 그 목록을 볼 수 있어요 목록에 삭제나 푸시(원격 저장소로 올리기)처럼 되돌리기 어려운 명령이 통째로 허용돼 있는지 봐요. 있으면 그 줄을 지워서 다시 묻게 해요
긴 작업 끝 무렵, 에이전트가 없는 파일 이름을 대며 고쳤다고 하거나 그 파일을 열려다 없다는 에러를 내요. 아까 정한 규칙도 어기기 시작해요 모델의 실력보다 지금 대화의 길이예요. Claude Code라면 /context로 컨텍스트 창이 얼마나 찼는지 볼 수 있어요 파일 탐색기에서 그 이름을 찾아봐요. 없고 대화가 길었다면 꽉 찬 신호일 가능성이 커요. 지금까지 정한 것만 몇 줄로 요약해 두고 /clear로 새로 시작해요. 늘 지킬 규칙은 규칙 파일에 적어야 리셋 뒤에도 남아요. 조건을 잊는 증상은 토큰 글의 이 줄에서 더 봐요
에이전트에게 큰 작업 하나를 맡겼을 뿐인데, 사용 한도가 채팅할 때보다 훨씬 빨리 차요 그 작업에 통째로 넣은 것이에요. 긴 로그, 큰 파일 전체, 여러 에이전트로 나누라는 부탁이 있었는지 봐요. 매 단계마다 앞의 내용이 다시 읽혀서 단계 수만큼 불어나요 작업을 작게 쪼개고, 로그는 에러 줄 앞뒤만 줘요. 한도가 어느 날, 어느 작업에서 튀었는지 찾는 법은 토큰 글의 이 줄에 있어요

둘째와 셋째 줄은 모든 게 잘 돌아가서 증상이라고 느끼기도 어려워요. 그래서 문서·사진·회사 자료가 든 폴더에서 에이전트를 켤 때마다, 일을 맡기기 전에 모드와 허용 목록부터 봐요.
