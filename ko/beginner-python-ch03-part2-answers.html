문제 해설 — 지역·전역변수와 lambda·map·filter·reduce를 자세히 뜯어본다 (2)

2026. 10. 11.

※ 이 글은 다음 글의 실습 문제 5개를 제가 직접 풀어보고, 변수 값이 어떻게 바뀌는지와 자주 하는 실수까지 정리한 해설입니다. 해설을 먼저 읽은 뒤 실습 문제를 풀어 보세요.

지역·전역변수 2문제와 lambda·map·filter·reduce 3문제를, 변수 값이 바뀌는 표와 자주 하는 실수(실제 에러 메시지 포함)까지 곁들여 자세히 풀어 쓴 해설이에요.

핵심 정리

개념한 줄 정리
지역변수함수 안에서 x = ...로 만든 변수는 함수 안에서만 살고, 같은 이름의 전역 x는 그대로다.
전역변수 읽기·쓰기함수 안에서 읽기만 하면 되지만, 값을 바꾸려면 global 이름이 필요하다.
lambda 매개변수: 식이름 없는 한 줄 함수이고, 식의 결과가 return 값이다.
list(map(f, 리스트))모든 원소에 f를 적용하고, 파이썬 3에서는 list()로 감싸야 값이 보인다.
list(filter(f, 리스트))f 결과가 참인 원소만 남긴다.
reduce(f, 리스트)앞의 결과(a)와 다음 원소(b)를 계속 합쳐 하나로 만든다.
변수 추적호출·반복마다 바뀌는 값을 한 줄씩 표로 적으면 결과가 보인다.

모든 코드는 Python 3에서 직접 실행해 출력과 에러 메시지를 확인했어요. 문제 원문은 실습 문제 5개에 있어요.

문제 1 — 이름이 같은 지역변수와 전역변수

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

x = 10                    # x 에 10 을 담아 주세요

def change():             # change 라는 동작을 만들어 주세요
    x = 99                # x 에 99 를 담아 주세요
    print('함수 안:', x)  # '함수 안:' 과 x 를 화면에 보여 주세요

change()                  # change 를 실행해 주세요
print('함수 밖:', x)      # '함수 밖:' 과 x 를 화면에 보여 주세요
함수 안: 99
함수 밖: 10

한 줄씩 짚어보기

  • x = 10 — 함수 밖에서 만든 전역변수 x예요.
  • x = 99 — 함수 안에서 대입하면 파이썬은 "이 함수만의 새 변수 x"를 만들어요. 전역 x는 건드리지 않아요.
  • 함수 안 print는 가장 가까운 x, 즉 지역 x(99)를 봐요.
  • 함수가 끝나면 지역 x는 사라지고, 함수 밖 print는 처음 그대로인 전역 x(10)를 봐요.
시점전역 x지역 x
x = 10 직후10(없음)
change() 안, x = 99 직후1099
change()가 끝난 뒤10사라짐

여기서 자주 막혀요: "x = 99를 했는데 왜 밖의 x는 10이지?" → 같은 이름이어도 다른 변수예요. 집 안 메모지와 집 밖 칠판에 같은 이름을 적었다고 한쪽을 고치면 다른 쪽이 바뀌는 건 아니에요.

흔한 실수 — 지역변수를 밖에서 쓰기: 함수 안에서만 만든 변수를 함수 밖에서 부르면 아예 없는 이름이라 에러가 나요.

def make():  # make 라는 동작을 만들어 주세요
    y = 5    # y 에 5 를 담아 주세요

make()       # make 를 실행해 주세요
print(y)     # y 를 화면에 보여 주세요
NameError: name 'y' is not defined
나쁜 선택좋은 선택
함수 안에서 x = 99만 쓰고 "전역 x가 바뀌었겠지" 하고 기대함 → 밖의 값은 그대로라서 결과가 어긋남 함수가 값을 밖으로 보내야 하면 return으로 돌려주고 밖에서 받음 → 값이 어디서 바뀌는지 눈에 보임

실제 코드에서 · 함수마다 i, total 같은 흔한 이름을 써도 서로 안 부딪히는 건 지역변수 덕분이에요.

문제 2 — global로 전역 값 누적하기

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

count = 0                     # count 에 0 을 담아 주세요

def add(n):                   # n 을 받는 add 라는 동작을 만들어 주세요
    global count              # 이 안에서 count 는 바깥 전역변수를 쓰겠다고 알려 주세요
    count = count + n         # count 에 count + n 을 담아 주세요
    print('더한 뒤:', count)  # '더한 뒤:' 와 count 를 화면에 보여 주세요

add(3)                        # add 에 3 을 넣어 실행해 주세요
add(4)                        # add 에 4 를 넣어 실행해 주세요
print('최종:', count)         # '최종:' 과 count 를 화면에 보여 주세요
더한 뒤: 3
더한 뒤: 7
최종: 7

한 줄씩 짚어보기

  • global count — "이 함수 안의 count는 새로 만들지 말고 바깥 전역 count를 써라"는 선언이에요.
  • count = count + n — 이제 전역 count를 읽고, 거기에 n을 더해 전역 count에 다시 저장해요.
  • 함수가 끝나도 전역 count는 사라지지 않아서, 다음 호출이 이어받아요.
호출n계산 전 count계산 후 count
add(3)303
add(4)437

여기서 자주 막혀요: "읽기는 되는데 왜 바꾸려면 global이 필요해?" → 함수 안에서 이름에 대입하면 파이썬이 그 이름을 지역변수로 보기 때문이에요. 읽기만 하는 이름은 전역을 그대로 봐요.

흔한 실수 — global을 빼먹으면? 아래 코드는 global count 한 줄만 뺀 거예요. 실제로 실행하면 이런 에러가 나요.

count = 0              # count 에 0 을 담아 주세요

def add(n):            # n 을 받는 add 라는 동작을 만들어 주세요
    count = count + n  # count 에 count + n 을 담아 주세요

add(3)                 # add 에 3 을 넣어 실행해 주세요
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

함수 안에 count = ...가 있으니 count가 지역변수로 정해졌는데, 오른쪽 count + n에서 그 지역 count를 값도 없이 읽으려 해서 나는 에러예요.

나쁜 선택좋은 선택
global 없이 count = count + n을 씀 → UnboundLocalError 바꿀 전역 이름 앞에 global count를 선언함 → 같은 count를 읽고 쓰게 됨

실제 코드에서 · 전역변수를 함수가 고치기 시작하면 값이 어디서 바뀌는지 추적하기 어려워져서, 실무에서는 global을 가능한 한 줄이고 return으로 값을 주고받는 쪽을 더 많이 써요.

문제 3 — lambda를 바로 부르기, 변수에 담아 부르기

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

square = lambda x: x * x           # x 를 x 와 곱하는 이름 없는 함수를 square 라고 불러 주세요
print((lambda a, b: a + b)(3, 4))  # a 와 b 를 더하는 이름 없는 함수에 3 과 4 를 넣은 값을 보여 주세요
print(square(5))                   # square 에 5 를 넣은 값을 화면에 보여 주세요
print(square(square(2)))           # square 에 2 를 넣고 그 값을 다시 square 에 넣은 값을 보여 주세요
7
25
16

한 줄씩 짚어보기

  • lambda x: x * x — "x를 받아 x * x를 돌려주는" 이름 없는 함수예요. return은 쓰지 않아도 식의 결과가 돌아와요.
  • square = ... — 그 함수에 square라는 이름을 붙여 둔 거라, def square(x): return x * x와 같은 역할이에요.
  • (lambda a, b: a + b)(3, 4) — 괄호로 lambda를 감싸고 바로 (3, 4)를 넣어 부르니, a=3, b=4로 3 + 4가 돼요.
식계산 과정출력
(lambda a, b: a + b)(3, 4)3 + 47
square(5)5 * 525
square(square(2))안쪽 square(2) = 4 → square(4) = 1616

여기서 자주 막혀요: "lambda 뒤에 왜 괄호가 두 번 나와?" → 앞 괄호는 lambda를 묶는 것이고, 뒤 괄호 (3, 4)는 함수를 부를 때 쓰는 평소의 호출 괄호예요. 이름이 없을 뿐 호출 방법은 똑같아요.

흔한 실수: lambda 안에 return을 쓰면 문법 에러가 나요. lambda는 식 하나만 쓸 수 있고, 그 식의 값이 자동으로 돌려주는 값이 돼요.

실제 코드에서 · lambda는 직접 호출하기보다 map·filter·정렬 기준처럼 "함수를 인자로 넘기는 자리"에 한 줄로 끼워 쓰는 일이 훨씬 많아요(다음 두 문제).

문제 4 — map과 filter로 리스트 만들기

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

nums = [1, 2, 3, 4, 5, 6]                         # nums 에 [1, 2, 3, 4, 5, 6] 을 담아 주세요
doubled = list(map(lambda x: x * 2, nums))        # nums 의 원소마다 x * 2 를 한 리스트를 doubled 에 담아 주세요
evens = list(filter(lambda x: x % 2 == 0, nums))  # nums 에서 x % 2 == 0 이 참인 원소의 리스트를 evens 에 담아 주세요
print(doubled)                                    # doubled 를 화면에 보여 주세요
print(evens)                                      # evens 를 화면에 보여 주세요
print(list(map(lambda x: x + 1, evens)))          # evens 의 원소마다 x + 1 을 한 리스트를 화면에 보여 주세요
[2, 4, 6, 8, 10, 12]
[2, 4, 6]
[3, 5, 7]

한 줄씩 짚어보기

  • map(lambda x: x * 2, nums) — nums의 원소를 하나씩 꺼내 x에 넣고 x * 2를 만들어요. 원소 6개면 결과도 6개예요.
  • filter(lambda x: x % 2 == 0, nums) — 각 원소로 조건(짝수인가?)을 계산해서 참인 원소만 남겨요. 값 자체는 바뀌지 않아요.
  • 마지막 줄은 filter 결과인 evens = [2, 4, 6]에 다시 map으로 1씩 더한 거예요.
xx * 2 (map)x % 2 == 0 (filter)evens에 남나?
12거짓안 남음
24참남음
36거짓안 남음
48참남음
510거짓안 남음
612참남음

마지막 줄은 evens의 2, 4, 6에 각각 1을 더하니 3, 5, 7이에요. 출발이 nums가 아니라 evens라는 점이 핵심이에요.

여기서 자주 막혀요: "map은 개수가 같고 filter는 줄어든다" — 이것만 기억하면 헷갈리지 않아요. map은 값을 바꾸고, filter는 원소를 고르기만 해요.

흔한 실수 — list()로 감싸지 않으면? 파이썬 3의 map은 리스트가 아니라 map 객체를 돌려줘서, 그냥 출력하면 값이 안 보여요.

r = map(lambda x: x * 2, [1, 2])  # [1, 2] 의 원소마다 x * 2 를 하는 map 을 r 에 담아 주세요
print(r)                          # r 을 화면에 보여 주세요
<map object at 0x0000020CEEA56290>

(뒤의 주소 숫자는 실행할 때마다 달라질 수 있어요.) list(r)처럼 list()로 감싸야 [2, 4]처럼 값이 보여요. filter도 마찬가지예요.

나쁜 선택좋은 선택
print(map(...))처럼 바로 출력함 → <map object at 0x...>만 보임 print(list(map(...)))로 감쌈 → 결과 리스트가 보임

실제 코드에서 · "전부 변환(가격에 세금 붙이기)"은 map, "조건에 맞는 것만 추리기(재고 있는 상품만)"는 filter 자리예요.

문제 5 — reduce로 합치기 (숫자와 문자)

정답과 해설

실행: 로컬 파이썬 — 아무 환경 OK

from functools import reduce              # functools 상자에서 reduce 를 가져와 주세요

nums = [1, 2, 3, 4]                       # nums 에 [1, 2, 3, 4] 를 담아 주세요
print(reduce(lambda a, b: a + b, nums))   # nums 를 a + b 로 차례로 합친 값을 화면에 보여 주세요
print(reduce(lambda a, b: a * b, nums))   # nums 를 a * b 로 차례로 합친 값을 화면에 보여 주세요
print(reduce(lambda a, b: b + a, 'abc'))  # 'abc' 를 b + a 로 차례로 합친 값을 화면에 보여 주세요
10
24
cba

한 줄씩 짚어보기

  • from functools import reduce — 파이썬 3에서는 reduce가 기본으로 들어 있지 않아서 꼭 불러와야 해요. 이 줄이 없으면 NameError가 나요.
  • reduce는 앞의 두 원소를 a, b로 받아 계산하고, 그 결과를 다음 반복의 a로 넘겨요. 그다음 원소가 b로 들어와요.
  • 마지막 줄은 문자열의 글자 하나하나가 원소예요. b + a로 새로 온 글자를 앞에 붙여서 뒤집혀요.

첫 번째 줄(a + b)의 추적표예요.

반복aba + b (다음 a)
1123
2336
36410

두 번째 줄(a * b)은 같은 방식으로 1*2=2, 2*3=6, 6*4=24라서 24예요.

세 번째 줄(b + a, 문자열 'abc')의 추적표예요.

반복abb + a (다음 a)
1'a''b''ba'
2'ba''c''cba'

여기서 자주 막혀요: "원소가 4개인데 왜 반복은 3번이야?" → 첫 반복에서 원소 두 개를 한꺼번에 쓰기 때문이에요. 원소가 n개면 합치는 횟수는 n-1번이에요.

흔한 실수: b + a를 a + b로 쓰면 문자열이 뒤집히지 않고 abc 그대로 나와요. 문자열 합치기는 순서가 곧 결과라서 a와 b 자리를 꼭 확인해야 해요.

나쁜 선택좋은 선택
reduce의 a와 b가 각각 뭔지 따져 보지 않고 결과를 짐작함 → 순서가 바뀌면 틀림 반복마다 a·b를 표로 적어 봄 → 결과가 한 줄씩 보임

실제 코드에서 · 합계·곱·가장 큰 값처럼 "리스트를 하나의 값으로 줄이는" 계산이 reduce 자리예요. 다만 합계만 필요하면 sum()이 더 간단해요.

이럴 때 의심하세요 — 이 5문제를 짜다가 결과가 이상할 때

에러가 나는 경우도 있고, 에러 없이 조용히 틀리는 경우도 있어요. 결과가 예상과 다르면 이 표부터 확인해요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
함수 안에서 값을 바꿨는데 밖의 변수는 그대로예요 함수 안의 이름 = ... 줄 그 이름이 새 지역변수로 만들어진 건 아닌지, global 선언이 있는지 확인해요 (문제 1, 문제 2)
UnboundLocalError: cannot access local variable가 나요 함수 안에서 이름에 대입하는 줄 위쪽 전역변수를 바꾸려는데 global 이름을 빼먹지 않았는지 확인해요 (문제 2)
NameError: name '...' is not defined가 나요 그 이름을 만든 자리 함수 안에서만 만든 지역변수를 밖에서 쓴 건 아닌지 확인해요 (문제 1)
출력이 <map object at 0x...>처럼 나와요 map·filter를 부른 줄 list()로 감쌌는지 확인해요 (문제 4)
reduce를 부르면 NameError가 나요 파일 맨 위 import 줄 from functools import reduce가 있는지 확인해요 (문제 5)
