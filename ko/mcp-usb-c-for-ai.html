MCP — AI를 내 데이터에 꽂는 USB-C

2026. 7. 25.

※ 이 글은 모두의연구소 AI AIFFEL 과정에서 배운 내용을 제 나름의 언어로 재구성한 것입니다.

← 이전 편 에이전트는 어떻게 스스로 반복할까 — ReAct 루프와 AutoGPT 소동

문제: AI는 '내 것'을 모른다

아무리 똑똑한 AI도 기본적으로는 자기가 학습한 것만 알아요. 제 데이터베이스, 제 파일, 제 캘린더, 회사 문서는 몰라요. 그때그때 복사해서 붙여넣을 수도 있지만, 연결할 도구가 많아지면 "AI 3개 × 도구 5개 = 연결 15개"를 일일이 만들어야 하는 지옥이 돼요. 이걸 M×N 문제라고 부른대요.

MCP = "AI를 위한 USB-C 포트"

MCP(Model Context Protocol)는 이 문제를 푸는 표준 규격이에요. Anthropic이 2024년 말에 공개했고, 지금은 업계 표준이 됐어요. USB-C를 떠올려보면 딱 맞아요 — 예전엔 기기마다 충전기가 달랐지만, USB-C 하나로 통일되니 아무 기기나 아무 충전기에 꽂혀요. MCP는 도구를 한 번 MCP 규격으로 만들어두면, MCP를 지원하는 아무 AI에나 꽂힌다는 뜻이었어요. 이걸로 AI가 제 데이터베이스를 직접 조회해서 답하거나, Figma 디자인을 읽어서 그대로 화면을 만들거나, 캘린더·Notion·Slack에 접근해 개인 비서처럼 구는 게 가능해져요.

MCP가 정말 흥미로웠던 건 경쟁사들이 같은 규격에 손을 얹었다는 점이었어요. Anthropic이 2024년 11월 공개했는데, 이듬해 OpenAI(2025년 3월)와 구글(2025년 4월)이 잇따라 채택했어요. 2025년 말에는 여러 회사가 함께 관리하는 중립 재단(리눅스 재단 산하 Agentic AI Foundation)으로 넘어갔고요. 경쟁하는 회사들이 같은 규격을 함께 떠받치는 건 흔치 않은 일이라는 게 인상 깊었어요. 그래서 오늘 배우는 MCP는 특정 회사 기능이 아니라 업계 공용 약속이었어요 — 한 번 익히면 도구가 바뀌어도 계속 쓸 수 있다는 뜻이에요.

실제로 뭘 연결해서 쓸 수 있나

MCP가 추상적으로 느껴질 수 있어서 실제 사례를 봤어요. Figma를 연결하면 AI가 디자인을 읽어서 그대로 화면을 만들고, Notion을 연결하면 "이번 주 할 일 정리해줘"를 채팅 안에서 할 수 있고, 웹사이트를 훑어 상품·가격을 정리해오거나(스크래핑), "다음 주 화요일 회의 잡아줘"로 캘린더에 초대장을 만들 수 있어요. 흥미로웠던 현실은, 공개적으로 널리 쓰이는 MCP 서버는 아직 손에 꼽지만 회사 내부용 MCP(사내 DB·문서 연결)가 가장 값지다는 평가였어요. 남에게 공개하지 않아도, 제 데이터에 AI를 붙이는 것만으로 큰 힘이 되니까요.

MCP 서버한 줄 용도
파일시스템내 폴더의 파일을 읽고 쓰기
GitHub저장소 이슈·코드 읽고 커밋·검색
브라우저 자동화(Playwright)AI가 실제 웹브라우저를 열어 클릭·입력·캡처
Slack채널 내역 검색·메시지 보내기
Notion페이지·DB 읽고 쓰기
데이터베이스DB에 자연어로 물어 조회(읽기 전용 권장)
구글 드라이브·캘린더문서 검색·일정 확인/생성

딱 하나 조심할 게 있었어요 — 공개된 MCP 서버는 수천 개 이상으로 급증했고 그중엔 검증 안 된 것도 많다는 거예요. 모르는 서버를 함부로 붙이지 말고, 회사가 직접 낸 공식 서버 위주로 시작하는 게 안전해요. AI에게 내 데이터·계정 접근 권한을 주는 일이니까요.

MCP가 건네는 세 가지, 그리고 M+N의 마법

MCP로 연결하면 AI가 세 종류를 쓸 수 있게 돼요 — 도구(Tools)는 AI가 실행하는 기능(검색하기, DB 조회하기), 자원(Resources)은 AI가 읽어 들이는 데이터(파일, 문서, 기록), 프롬프트(Prompts)는 미리 만들어둔 요청 템플릿이에요. 이게 왜 좋을까 봤는데, 연결을 매번 새로 안 만들어도 되고, AI가 실제 최신 데이터를 보니 엉뚱한 답(환각)이 줄고, 학습 시점 이후의 최신 정보도 쓸 수 있었어요.

구조를 조금 더 파보면, host는 AI를 담은 앱(예: 코딩 도구)이고 그 안의 client가 연결을 관리해요. server는 Notion·파일 시스템·DB 같은 바깥 기능을 MCP 방식으로 내놓고요. 표준이 없으면 AI 앱 M개와 데이터 서비스 N개가 각각 전용 연동을 만들어야 해서 연결이 M×N개가 되는데, 공통 규약을 따르면 앱은 MCP client를 한 번, 서비스는 MCP server를 한 번씩만 구현해서 조합할 수 있어 대략 M+N개로 줄어들어요. 다만 플러그 모양이 같다고 모든 기기가 같은 권한을 갖는 게 아니듯, MCP도 연결 규칙이지 자동 안전 보장은 아니었어요. 특히 tool은 실제 행동을 할 수 있어서, 처음엔 "읽기" 도구부터 연결하고 쓰기·삭제·배포처럼 되돌리기 어려운 권한은 승인 과정을 두는 게 안전했어요. 다음 글에서는 이 MCP와 짝을 이루는, 반복 작업을 AI에게 외워두는 방법인 스킬을 볼게요.
