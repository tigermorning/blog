2.1 while을 사용하는 반복문

문제 원문: wikidocs.net/56

Q1. while 문은 정확히 무엇을 언제까지 반복하나요?

while은 조건이 참인 동안 그 아래 들여쓴 코드를 반복해서 실행해요. 매번 반복하기 전에 조건부터 다시 검사해요.

실행: 파이썬 대화형 셸 — 터미널에서 python을 입력하면 열려요

>>> num = 1
>>> while num <= 3:
...     print(num)
...     num = num + 1
...
1
2
3

이 코드가 실행되는 순서를 표로 그리면 이래요.

몇 번째 검사이때 numnum <= 3 ?동작
11참1 출력, num을 2로
22참2 출력, num을 3으로
33참3 출력, num을 4로
44거짓반복 끝, 다음 줄로
  • while 조건: 뒤에는 콜론(:)이 꼭 있어야 해요. if도 마찬가지예요.
  • 몸통은 공백 4칸(또는 Tab 1번)으로 들여써요. 들여쓴 줄들이 "조건이 참인 동안 반복할 부분"이에요.
  • num = num + 1은 "num에 1을 더한 새 값을 다시 num에 넣어라"는 뜻이에요. num += 1로 줄여 써도 똑같이 동작해요.
  • 조건이 처음부터 거짓이면(예: num = 10으로 시작) 몸통은 한 번도 실행되지 않아요.

while과 if는 뭐가 다른가요? 둘 다 조건을 검사한다는 점은 같아요. if는 조건이 참이면 딱 한 번 실행하고 끝나지만, while은 조건이 참인 동안 계속 되돌아가서 다시 실행해요.

Q2. 카운터를 갱신하는 줄을 빠뜨리면 왜 무한 루프가 되나요?

while은 조건만 보고 반복 여부를 정해요. 조건에 쓰인 값이 반복 중에 한 번도 안 바뀌면, 조건은 영원히 똑같은 결과를 내서 반복이 끝나지 않아요.

개념 설명용 코드 — 절대 실행하지 마세요. num이 계속 1이라 조건이 늘 참이에요

num = 1
while num <= 3:
    print(num)
    # num = num + 1 을 빠뜨림
  • 매번 검사할 때 num은 항상 1 → 1 <= 3은 항상 참 → 1을 영원히 찍음
  • 이런 코드를 실수로 실행했다면 터미널에서 Ctrl + C를 눌러 강제로 멈춰요

무한 루프를 피하는 원칙: while 몸통 안에는 조건에 쓰인 값을 바꾸는 줄이 최소 하나 있어야 하고, 그 값이 언젠가는 조건을 거짓으로 만들 수 있어야 해요. 카운터를 늘리다가 빼먹거나(num = num + 1 자리를 지워도, 들여쓰기를 잘못해서 while 밖으로 나가도) 같은 실수로 자주 생겨요.

실행: 파이썬 대화형 셸 — 들여쓰기가 잘못돼서 num이 while 밖에서만 바뀌는 예

num = 1
while num <= 3:
    print(num)
num = num + 1   # 들여쓰기가 한 칸 덜 됨 → while 몸통이 아님
  • 마지막 줄이 while과 같은 위치까지 나와 있으면 몸통이 아니라 while이 끝난 뒤에 딱 한 번 실행되는 코드예요
  • 그러면 몸통 안에는 print(num)만 남아서 num이 영원히 1 → 무한 루프

공식 풀이는 이래요.

num = int(input())

i = 0

i몇 번 돌았는지 세는 카운터매번 1씩 늘어남

입력이 3일 때 흐름을 표로 그리면 이래요.

검사ii < num(3) ?출력다음 i

  • num을 i < num 자리에도 쓰고 print(num) 자리에도 쓰지만, 세는 것과 찍는 것은 목적이 다른 일이라서 이름도 역할도 분리해요.
  • 만약 i 없이 num 하나로 세면서 동시에 출력하면, 출력할 값 자체가 줄어들어 버려서(예: 3, 2, 1) 원하는 결과가 안 나와요.
  • i, j, count는 "세는 용도의 변수"에 흔히 쓰는 이름이에요.

Q4. print('', num)에서 첫 번째 빈 문자열 ''은 왜 있나요?

문제의 요구 사항이 "출력 앞에 공백을 한 칸 주어서 입력과 출력이 구분되게" 하는 것이었죠. print()에 쉼표로 여러 값을 넣으면 사이에 공백이 하나씩 자동으로 들어간다는 점(1장 기본 6)을 이용한 거예요.

실행: 파이썬 대화형 셸 — 터미널에서 python을 입력하면 열려요

>>> print('', 3)
 3
>>> print(3)
3
  • print('', 3)은 빈 문자열 ''과 3을 쉼표로 나열한 것 → 그 사이에 공백 1칸이 끼어서 ' 3'처럼 보임
  • 빈 문자열 자체는 아무 글자도 없어서 화면에 아무것도 안 남기고, 오직 "공백을 만들기 위한 자리"로만 쓰임
  • print(' ', 3)처럼 써도 결과는 같아요. 다만 ' '은 공백 1칸을 담은 문자열이고 ''은 빈 문자열이라, 둘 다 그 자체로는 화면에 아무것도 안 보여준다는 점은 똑같아요.

비교: 앞에 붙이는 게 목적이면 문자열을 직접 이어 붙여 print(' ' + str(num))이라고 써도 같은 결과가 나와요. 다만 str(num)으로 숫자를 문자열로 바꿔야 +로 이어 붙일 수 있어요(1장 기본 4의 '3' + '4'처럼요).

2.1.2 연습 문제: 제곱표(while)

문제 원문: wikidocs.net/86465

Q5. 카운터가 1부터 시작하고 조건이 <= num인 이유는?

공식 풀이는 이래요.

num = int(input())
i = 1
while i <= num:
    print(i, i * i)
    i = i + 1

입력이 3일 때 1 1, 2 4, 3 9가 나와야 하죠. "1부터 num까지, num도 포함"이 목표라서 i = 1로 시작하고 조건도 <=(이하)를 써요.

ii <= 3 ?출력
1참1 1
2참2 4
3참3 9
4거짓(끝)

2.1.1의 리스트 인덱스(1장 기본 5)는 0부터 세지만, 이 문제의 "1부터 num까지의 수"는 사람이 세는 방식 그대로 1부터 세요. 0부터 세는 건 리스트 번호의 규칙이지, while의 규칙이 아니에요. 무엇을 세느냐에 따라 시작 값과 부등호를 맞추면 돼요.

나쁜 선택좋은 선택
1부터 num까지 다 돌리려고 i = 1로 시작하고 조건을 i < num으로 쓴다 → num 줄이 통째로 빠져요(입력 3이면 1, 2만 나옴). <=를 쓴다 → num까지 포함돼서 3줄이 정확히 나와요.

2.1.3 연습 문제: 얌체공

문제 원문: wikidocs.net/85687

Q6. 매번 곱하는 계산인데 왜 소수점 오차가 자꾸 나오고, round()는 그걸 완전히 없애 주나요?

공식 풀이는 이래요.

height = 100
bounce = 3 / 5

i = 1
while i <= 10:
    height = height * bounce
    print(i, round(height, 4))
    i = i + 1

round() 없이 그냥 찍으면 벌써 세 번째 줄부터 지저분한 값이 나와요.

실행: 파이썬 대화형 셸 — round() 없이 그대로 찍은 결과

>>> height = 100 * (3/5)
>>> height
60.0
>>> height = height * (3/5)
>>> height
36.0
>>> height = height * (3/5)
>>> height
21.599999999999998
  • 컴퓨터는 소수를 2진수로 저장하는데, 0.6(3/5) 같은 수는 2진수로 딱 떨어지지 않아서 아주 작은 오차가 생겨요(1장 기본 6 질문과 해설의 float 오차와 같은 현상).
  • 이 오차를 가진 값을 다시 곱하는 계산에 또 쓰기 때문에, 반복할수록 오차가 조금씩 쌓여요(누적 오차).
  • round(height, 4)는 "이 값을 소수점 넷째 자리까지 반올림한 새로운 값을 화면에 보여 달라"는 뜻이에요. height 변수 자체를 깎아 내는 게 아니라 print()에 넘길 때만 반올림해요.

그래서 round()가 오차를 "없애는" 건 아니에요. 다음 계산에도 반올림 전의 height(오차 포함)가 그대로 쓰여요. round()는 "화면에 보여 줄 자릿수를 정리하는 것"이지 "저장된 값을 고치는 것"이 아니에요.

iround(height, 4) 출력
160.0
236.0
321.6
91.0078
100.6047

참고로 round(2.675, 2)가 2.68이 아니라 2.67이 나오는 것도 버그가 아니라 같은 부동소수점 한계예요.

Q7. 앞의 예제들은 카운터가 커지는데, 이 퀴즈처럼 카운터가 줄어드는 while도 되나요?

countcount > 0 ?출력다음 count
3참32
2참21
1참10
0거짓(끝)-

정답은 "3 2 1이 각각 다른 줄에 출력"이에요. print()는 인자 하나만 넘기면 그 값을 찍고 줄바꿈까지 자동으로 해 주기 때문에, 세 번 호출하면 세 줄이 나와요. "한 줄에 출력"이 되려면 print(count, end=' ')처럼 줄바꿈 방식을 따로 바꿔야 하는데, 이건 2장 범위 밖이에요.

2.2 조건문(if-elif-else)

문제 원문: wikidocs.net/57

Q8. if/elif/else는 정확히 무엇을 하나요?

if는 "조건이 참이면 이 블록을, 아니면 건너뛰어라"예요. else를 붙이면 "참이 아닐 때 대신 실행할 것"을 정할 수 있고, elif를 끼워 넣으면 조건을 여러 개 검사할 수 있어요.

실행: 파이썬 대화형 셸 — 터미널에서 python을 입력하면 열려요

>>> a = 1234 * 4
>>> b = 13456 / 2
>>> if a > b:
...     print('a')
... else:
...     print('b')
...
b

Q17. split()으로 나눈 값을 어떻게 두 변수에 나눠 담나요?

공식 풀이의 앞부분이에요.

L = input().split()
min = int(L[0])
max = int(L[1])
# min, max = map(int, input().split())

split()은 문자열을 공백 기준으로 잘라 리스트로 돌려줘요.

실행: 파이썬 대화형 셸 — 터미널에서 python을 입력하면 열려요

>>> '10 20'.split()
['10', '20']

이 풀이는 리스트를 만든 뒤 L[0], L[1]로 인덱싱해서(1장 Q5) 각각 정수로 바꿔요. 주석으로 남겨 둔 둘째 줄은 다른 방법이에요.

>>> min, max = map(int, '10 20'.split())
>>> min
10
>>> max
20
  • map(int, 리스트)는 리스트의 원소 하나하나에 int()를 적용해 줘요. ['10', '20'] → 10, 20
  • min, max = ...처럼 왼쪽에 이름을 여러 개 쓰면, 오른쪽 값의 개수와 순서를 맞춰 한 번에 나눠 담아요. 1장 상급 8에서 본 divmod() 언패킹과 같은 문법이에요.
  • 원소 개수가 정확히 정해져 있을 때(여기서는 항상 2개)만 이렇게 바로 나눠 담을 수 있어요. 개수가 몇 개일지 모르면 for 문으로 하나씩 꺼내야 해요.

변수 이름 주의: 여기서 쓴 min, max도 sum처럼 파이썬 내장 함수 이름이에요. 자세한 이유는 Q15를 참고하세요.

Q18. min <= temp <= max처럼 부등호를 연달아 써도 되나요?

됩니다. 파이썬은 이런 연쇄 비교(chained comparison)를 지원해요. min <= temp <= max는 "temp가 min 이상이면서 동시에 max 이하"라는 뜻이에요.

실행: 파이썬 대화형 셸 — 터미널에서 python을 입력하면 열려요

>>> 10 <= 15 <= 20
True
>>> 10 <= 25 <= 20
False

수학에서 10 ≤ 15 ≤ 20이라고 쓰는 것과 똑같은 모양이에요. 풀어 쓰면 (min <= temp) and (temp <= max)와 같은 뜻인데, and는 2.2.7에서 배우니 지금은 "부등호 두 개를 나란히 쓰면 범위를 한 번에 검사할 수 있다"는 것만 기억해도 충분해요.

        print('Alert!')
        break

-999는 온도로는 절대 나올 리 없는 값을 "그만 보내겠다"는 신호로 약속한 거예요. 이런 값을 센티널 값(sentinel value)이라고 불러요. 2.2.4의 "음수면 그만"과 비슷한 발상인데, 여기서는 정상적인 온도가 음수일 수도 있어서(영하 온도) 아예 있을 수 없는 -999를 약속 값으로 정한 거예요.

예 1(최소 10, 최대 20 / 온도 15, 10, 20, 0, 15, -999)을 표로 따라가요.

temptemp != -999 ?10 <= temp <= 20 ?출력
15참참Nothing to report
10참참Nothing to report
20참참Nothing to report
0참거짓Alert! (break로 종료)
  • while의 조건(temp != -999)은 "정상 종료 신호가 왔는가"만 검사해요.
  • 범위를 벗어난 경우(Alert!)는 while 조건과 별개로 break가 직접 끊어요. 그래서 장치가 -999를 보내기 전이라도 위험하면 즉시 멈출 수 있어요.
  • 온도를 계속 읽는 줄(temp = int(input()))이 if 블록 안에만 있다는 점도 중요해요 — 정상일 때만 다음 값을 읽고, 위험하면 더 안 읽고 바로 끝나요.

이럴 때 의심하세요 — 2장 문법으로 짠 코드의 결과가 이상할 때

아래 문제들은 에러 없이 조용히 틀리거나, 아예 멈추지 않는 경우가 많아요. 결과가 예상과 다르면 이 표부터 확인해요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
프로그램이 안 끝나고 화면에 같은 내용이 계속 찍히거나, 아무 반응 없이 멈춘 것처럼 보여요 while 몸통 안에서 조건에 쓰인 변수를 바꾸는 줄 그 변수가 반복마다 실제로 값이 바뀌는지, 들여쓰기가 while 몸통 안에 제대로 들어가 있는지 봐요 (Q2)
등급·단위 같은 결과가 조용히 틀리게 나와요 (큰 수인데 작은 단위로, 젊은 나이인데 늙은 세대로) elif 체인의 조건 순서 조건이 <=면 작은 값부터, >=면 큰 값부터 쓰여 있는지 확인해요 (Q12, Q13)
sum(), min(), max() 같은 함수를 불렀는데 TypeError: 'int' object is not callable이 나요 같은 이름을 변수로 먼저 만든 적이 있는지 그 위에서 sum = ..., min = ... 같은 대입이 있었는지 찾아 total, lo 같은 이름으로 바꿔요 (Q15)
elif나 if 아래에서 IndentationError: expected an indented block가 나요 조건은 맞는데 실행할 코드를 안 쓴 블록 그 자리에 할 일이 정말 없다면 pass를 넣어요 (Q14)
