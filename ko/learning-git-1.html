저는 어제까지만 해도 Git이 뭔지 전혀 몰랐습니다. 그런데 하루 만에 GitHub 저장소를 만들고, 제 이름으로 된 블로그까지 띄웠어요. 저처럼 아무것도 몰라도 그대로 따라 할 수 있도록, 제가 했던 순서를 정리해봤습니다. 이번 1편에서는 기본 개념과 세팅까지만 다뤄요. GitHub 계정 만들기와 실제 연결은 다음 편에서 이어집니다.

0~2. 준비물, Claude 설치, 그리고 "바이브 코딩" 이해하기

  • Windows가 설치된 컴퓨터
  • 인터넷 연결
  • 이메일 주소 하나 (계정 만들 때 필요)

저는 이 모든 과정을 Claude라는 AI 도우미와 대화하면서 진행했어요. Claude는 채팅만 하는 게 아니라, 제 컴퓨터의 명령창(터미널)에 명령어를 대신 실행해주고, 파일을 만들거나 수정해줄 수 있어요. 그래서 저는 어려운 명령어를 몰라도 "이렇게 해줘"라고 말만 하면 됐어요.

  1. 브라우저에서 claude.ai 접속
  2. 계정이 없으면 이메일로 가입, 있으면 로그인
  3. 컴퓨터에서 직접 파일/터미널을 다루게 하려면 Claude Desktop(또는 Claude Code) 앱을 설치 — 사이트 안내에 따라 다운로드 후 설치 프로그램 실행
  4. 설치 후 로그인하면 채팅창이 뜸 — 여기서부터 아래 과정을 Claude에게 하나씩 요청하면 됩니다

Home이 아니라 Code로 들어가야 해요

저는 처음에 계속 Home 화면에서만 대화를 했었어요. 그런데 컴퓨터의 파일을 만들고 터미널 명령어를 실행하려면 Code 쪽으로 들어가야 해요. 화면 위쪽에 아래 그림처럼 Home / Code 탭이 있으니, 꼭 Code를 눌러서 시작하세요.

여기까지가 준비물과 설치예요. 이제 본격적으로 시작하기 전에 하나만 짚고 갈게요. 이 글에는 앞으로 회색 박스 안에 명령어 코드가 여러 번 나와요. 그런데 저는 이 코드를 직접 외우거나 타이핑하지 않았어요. 그냥 Claude에게 말로 시켰더니 알아서 실행해줬어요.

요즘은 이런 방식을 "바이브 코딩(vibe coding)"이라고 불러요 — 코드를 직접 짜는 대신, AI에게 자연어로 "이렇게 해줘"라고 말하면 AI가 코드를 대신 작성·실행하고, 사람은 결과가 원하는 대로 나오는지만 확인하는 방식이에요.

그래서 앞으로 각 단계마다 이렇게 구성했어요:
🎨 바이브 코딩으로: Claude에게 뭐라고 말하면 되는지
🔍 궁금하다면: 그 말을 들은 Claude가 실제로 어떤 명령어를 실행하는지, 그게 무슨 뜻인지
코드 부분은 몰라도 전혀 상관없어요. 이해하고 싶은 만큼만 읽으시면 됩니다.

3~4. 컴퓨터 기본기와 터미널

그런데 Claude에게 "이렇게 해줘"라고 말하려면, 최소한 "어디에"는 제가 정해줘야 했어요. 앞으로 할 일은 전부 제 컴퓨터 어딘가에 폴더를 하나 만들고, 그 폴더 안의 파일을 다루는 일이거든요. 그래서 파일이 어디에 저장되는지, 폴더는 어떻게 만드는지부터 짚고 갈게요. 이걸 대충 알고 넘어가면 나중에 "내 파일이 대체 어디 있지?"로 헤매게 돼요.

  • C드라이브: 내 컴퓨터의 메인 저장 공간 이름이에요. 파일 탐색기를 열면 왼쪽에 "로컬 디스크 (C:)"라고 보여요.
  • 폴더 만들기: 원하는 위치(예: 바탕화면이나 문서 폴더)에서 빈 곳에 마우스 오른쪽 클릭 → 새로 만들기 → 폴더
  • 파일 탐색기 여는 법: 키보드에서 윈도우 키 + E, 또는 화면 아래 작업표시줄의 폴더 모양 아이콘 클릭

저는 문서(Documents) 폴더 안에 작업 폴더들을 만들었어요. 꼭 여기일 필요는 없고, 나중에 기억하기 쉬운 위치면 됩니다.

폴더까지 정했으면, 이제 그 폴더에 대고 실제로 일을 시켜야 해요. 그런데 앞으로 쓸 도구들은 마우스로 클릭하는 프로그램이 아니라 글자로 명령을 넣는 화면에서 돌아가요. 1번에서 "Claude가 명령창에 명령어를 대신 실행해준다"고 했던 그 화면이 바로 여기예요.

터미널(terminal)은 마우스 클릭 대신 글자로 된 명령어를 입력해서 컴퓨터에 일을 시키는 화면이에요. 이름이 낯설어서 찾아봤더니, 원래 컴퓨터 용어가 아니라 통신선의 맨 끝(terminal, 종착점)에 달린 말단 장치를 부르던 말이더라고요. 옛날에는 계산을 하는 커다란 컴퓨터가 한 대 있고, 사람들은 선으로 연결된 끝단의 화면과 키보드로 그 컴퓨터에 명령을 넣었거든요. 그 "끝단 장치"의 이름이 지금은 화면 속 검은 창의 이름으로 남은 거예요. Windows에서는 PowerShell이라는 프로그램이 이 역할을 해요.

여는 법: 시작 메뉴(윈도우 키) 누르고 "PowerShell"이라고 타이핑하면 검색되어 나와요. (맥이나 리눅스에도 같은 역할을 하는 앱이 있지만, 이 시리즈의 명령어는 전부 Windows 기준입니다.)

다만 앞서 말씀드렸듯, 이 글에 나오는 명령어들은 바이브 코딩으로 Claude에게 시킨 거라 직접 타이핑하지 않았어요. 그래도 뭘 하고 있는 건지 알고 싶어서, 명령어와 뜻을 이 글에 다 적어둡니다.

5~6. Git 설치하고 나는 누구인지 알려주기

터미널이 "명령을 넣는 창"이라면, 이제 그 창에 대고 시킬 대상이 필요해요. 그게 이 시리즈의 주인공인 Git이에요. Git은 아이콘을 눌러서 여는 프로그램이 아니라 터미널에 git ...이라고 입력하면 그때그때 동작하는 도구라서, 터미널 이야기를 먼저 한 거였어요.

Git은 파일이 바뀐 이력을 기록해주는 프로그램이에요. 코드나 글을 계속 고쳐 쓰다 보면 "예전 버전으로 되돌리고 싶다", "언제 뭘 바꿨는지 보고 싶다" 같은 순간이 오는데, 그럴 때를 위한 도구예요. 파일을 그냥 덮어쓰는 게 아니라 바뀔 때마다 그 시점을 하나씩 따로 쌓아둔다는 게 핵심이에요.

🎨 바이브 코딩으로: Claude에게 "내 컴퓨터에 Git이 설치되어 있는지 확인해줘"라고 말하면 확인해줘요. 설치가 안 되어 있으면 설치까지 부탁하면 돼요.

🔍 궁금하다면: 실제로 어떤 명령어일까?

이미 설치되어 있는지 확인하는 명령어예요.

실행: 로컬 터미널

git --version

버전 번호가 뜨면 이미 설치된 거예요. 안 뜨면 git-scm.com에서 내려받아 설치 프로그램을 실행하면 됩니다 (설치 중 나오는 옵션들은 거의 다 기본값 그대로 "다음"만 눌러도 돼요).

저장(Ctrl+S)과 커밋(commit)은 달라요. 저장은 지금 상태를 덮어쓰는 거라 어제 쓴 내용은 사라지고, 커밋은 "이 시점의 상태를 사진처럼 찍어서 기록으로 남기는 것"이라 예전 사진이 그대로 남아 있어요. 커밋이라는 말도 원래 컴퓨터 용어가 아니라 "맡기다, 확정해서 넘기다"라는 뜻의 영어 commit이에요. 은행 창구에 서류를 맡기듯 "이 상태를 확정해서 기록에 넘긴다"는 느낌으로 받아들이면 편해요.

방금 "커밋은 기록으로 남기는 것"이라고 했죠. 기록이라면 누가 남긴 기록인지가 함께 적혀야 말이 돼요. 그래서 Git은 설치한 다음에 딱 한 번, "너는 누구냐"를 등록해달라고 해요. 커밋할 때마다 이 이름과 이메일이 기록에 자동으로 따라붙기 때문에, 한 번만 해두면 다시 신경 쓸 일이 없어요.

🎨 바이브 코딩으로: Claude에게 "Git 사용자 이름을 OOO, 이메일을 OOO로 설정해줘"라고 말하면 등록해줘요.

🔍 궁금하다면: 실제로 어떤 명령어일까?

실행: 로컬 터미널

git config --global user.name "내 이름"
git config --global user.email "내 이메일"

여기서 헷갈렸던 것: 이게 "초기화"인가요?

아니에요! 이 설정(config)은 "이 컴퓨터에서 커밋할 때는 항상 이 이름/이메일을 써라"는 전역 규칙일 뿐이에요. 저장소(repository)는 완전히 다른 개념으로, 특정 폴더 하나를 "여기서부터 이력을 관리하겠다"고 선언하는 거예요. 헷갈리기 쉬운 이 둘을 표로 나눠봤어요.

도장 파기 비유로Git에서는
도장을 새로 파서 등록해둔다 — 한 번만 하면 끝git config로 이름·이메일을 등록 — 컴퓨터 전체에 한 번만
그 도장을 실제로 쓸 서류철(폴더)을 연다 — 관리할 폴더마다 매번폴더 하나를 저장소로 초기화 — 이력을 관리할 폴더마다 매번

이럴 때 의심하세요 — Claude에게 첫 Git 작업을 시켰는데 막힐 때

이 편의 실수는 대부분 "시켰는데 안 된다"로 먼저 만나요. 그런데 원인은 명령어보다 어느 화면에서, 어느 폴더에 대고 시켰는지에 있을 때가 많아요. 같은 부탁을 다시 하기 전에 자리부터 확인하는 게 빨라요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
Claude가 직접 실행하지 않고 "터미널에 이 명령어를 입력하세요"라며 명령어만 알려줘요. 파일을 만들어 달라고 해도 채팅창에 내용만 보여 주고, 폴더에는 아무것도 안 생겨요 앱 화면 위쪽의 Home / Code 탭이에요. 부탁한 문장은 대개 범인이 아니에요 Home이 눌려 있으면 Code를 누르고 같은 부탁을 다시 해요. 파일과 터미널 작업은 Code 쪽에서만 돼요
git --version을 넣었더니 버전 번호 대신 'git'을 인식할 수 없다는 빨간 에러가 떠요. Git을 방금 설치했는데도 그래요 Git 설치 여부, 그리고 그 터미널 창을 언제 열었는지예요. 설치하기 전에 열어 둔 창은 Git이 새로 생긴 걸 몰라요 터미널(또는 Claude 앱)을 완전히 닫았다가 다시 열고 git --version을 한 번 더 넣어요. 그래도 같은 에러면 설치가 안 된 거라 git-scm.com에서 설치해요
Claude가 "파일을 만들었어요"라고 했는데 파일 탐색기에서 아무리 찾아도 안 보여요. 다음 날 새 대화에서 그 파일 얘기를 하면 "그런 파일이 없다"는 답이 와요 파일 이름이 아니라 Claude가 작업하던 폴더예요. 내가 생각한 폴더(예: 문서)와 Claude가 실제로 열어 둔 폴더가 다를 때가 많아요 Claude에게 "지금 작업 중인 폴더의 전체 경로를 알려 줘"라고 물어요. 받은 경로(예: C:\Users\이름\Documents\...)를 파일 탐색기 위쪽 주소창에 붙여 넣고 Enter를 누르면 그 폴더가 바로 열려요
이름·이메일을 등록했으니 됐다 싶어 커밋을 시켰더니 fatal: not a git repository (or any of the parent directories): .git이 나와요 명령을 실행한 폴더예요. git config 설정은 범인이 아니에요 — 도장은 팠는데 서류철을 안 연 상태예요 그 폴더에서 git status를 넣어 봐요. 같은 에러면 이 폴더는 아직 저장소가 아니거나, 저장소 폴더의 한 칸 바깥이에요. 저장소는 3편에서 GitHub에 만들고 클론으로 가져와요

둘째 줄은 설치를 Claude에게 맡겼을 때 특히 잘 생겨요. 설치는 끝났다는데 바로 이어서 시킨 Git 명령이 실패하면, 설치가 틀린 게 아니라 창을 새로 열 차례예요.

설치·폴더·이름표를 한꺼번에 점검하고 싶으면 Claude에게 맡겨도 돼요. 이때 바꾸지 말고 보여만 달라고 해요. 이름이나 이메일이 잘못 들어가 있을 때 Claude가 알아서 덮어쓰면, 뭐가 틀렸었는지 모르고 지나가거든요.

실행: 코딩 에이전트에 붙여넣기 — Claude Code 등 — Claude 앱의 Code 탭에서

지금 내 Git 준비 상태를 점검해서 표로 보여 줘. 아직 아무것도 설치하거나 바꾸지 마.
1. git --version 결과 (설치가 안 되어 있으면 그렇다고만 알려 줘)
2. 지금 작업 중인 폴더의 전체 경로
3. 이 폴더가 Git 저장소인지 (git status 결과로)
4. git config --global user.name 과 git config --global user.email 에 등록된 값

커밋 개념이나 "바이브 코딩"이라는 말 자체가 아직 궁금하다면 아래 글에서 더 깊게 다뤘어요.

참고 글 Git 커밋이 뭔가요? 참고 글 바이브 코딩이란 무엇인가

여기까지 하면 제 컴퓨터 안에 "이력을 기록할 준비가 된 Git"과 "그게 누구 기록인지 알려줄 이름표"가 갖춰진 셈이에요. 그런데 이 기록은 아직 전부 제 컴퓨터 안에만 있어요. 컴퓨터가 고장 나면 같이 사라지고, 남에게 보여줄 수도 없죠. 그래서 다음 2편에서는 이 기록을 인터넷에 올려둘 곳(GitHub) 계정을 만들고, 내 컴퓨터와 그 계정을 안전하게 연결하는 방법(SSH)을 다룹니다.
