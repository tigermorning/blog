초급

6.1 기본기 — 쓰기·덧붙이기·한 줄 읽기

write 와 줄 바꿈, 'w' 와 'a+' 의 차이, readline 이 줄을 넘어가는 모습을 한 문제에 한 가지씩 확인해요.

초급 1읽기

write 는 줄을 바꿔 주지 않는다

write()는 준 글자를 그대로 써요. 줄 바꿈이 필요하면 \n을 직접 넣어야 해요.

f = open('memo.txt', 'w')             # f 에 memo.txt 를 쓰기용으로 열어 담아 주세요
f.write('apple')                      # f 에 'apple' 을 써 주세요
f.write('banana\n')                   # f 에 'banana' 와 줄 바꿈을 써 주세요
f.write('cherry')                     # f 에 'cherry' 를 써 주세요
f.close()                             # f 를 닫아 주세요

print(repr(open('memo.txt').read()))  # memo.txt 의 내용을 보이는 모양 그대로 화면에 보여 주세요
print(open('memo.txt').read())        # memo.txt 의 내용을 읽어 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
힌트 보기

write('apple') 바로 다음에 write('banana\n')를 하면 두 글자가 이어져서 한 덩어리가 돼요. 줄이 바뀌는 곳은 \n이 있는 곳뿐이에요.

정답·해설 보기 
'applebanana\ncherry'
applebanana
cherry

한 문장으로: write를 세 번 해도 \n이 있는 곳에서만 줄이 바뀌어서, 파일에는 applebanana와 cherry 두 줄이 생겨요.

왜 이런 결과가 나올까요

파일에 쓴 글자는 apple + banana\n + cherry 순서로 이어진 하나의 글자예요. 첫 번째 출력(repr)은 그 글자를 \n이 보이는 모양으로, 두 번째 출력은 줄 바꿈을 적용해 보여 줘요.

헷갈리기 쉬운 곳

  • print는 자기 줄 끝에 줄 바꿈을 하나 더해요. 파일에 쓰는 write는 그러지 않으니 print 습관대로 줄이 바뀔 거라고 생각하면 안 돼요.

핵심 한 줄: write는 준 글자만 쓰고, 줄 바꿈은 \n으로 직접 넣어요.

초급 2읽기

'w' 는 지우고 'a+' 는 이어 쓴다

같은 파일을 모드를 바꿔 가며 열어요. 매번 열기 전의 내용이 남아 있는지가 핵심이에요.

with open('a.txt', 'w') as f:      # a.txt 를 쓰기용으로 열어 f 라 불러 주세요
    f.write('one\n')               # f 에 'one' 과 줄 바꿈을 써 주세요
with open('a.txt', 'a+') as f:     # a.txt 를 덧붙이기용으로 열어 f 라 불러 주세요
    f.write('two\n')               # f 에 'two' 와 줄 바꿈을 써 주세요
print(repr(open('a.txt').read()))  # a.txt 의 내용을 보이는 모양 그대로 화면에 보여 주세요

with open('a.txt', 'w') as f:      # a.txt 를 쓰기용으로 다시 열어 f 라 불러 주세요
    f.write('three\n')             # f 에 'three' 와 줄 바꿈을 써 주세요
print(repr(open('a.txt').read()))  # a.txt 의 내용을 보이는 모양 그대로 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
힌트 보기

'a+'는 기존 내용 뒤에 이어 쓰고, 'w'는 열자마자 파일을 비워요.

정답·해설 보기 
'one\ntwo\n'
'three\n'

한 문장으로: 'a+'로 연 뒤에는 one과 two가 함께 있고, 'w'로 다시 열면 앞의 것이 모두 사라지고 three만 남아요.

왜 이런 결과가 나올까요

첫 줄은 'w'로 새로 만들며 one을 쓰고, 둘째 with는 'a+'라 끝에 two를 이어 써서 두 줄이 돼요. 마지막 with는 다시 'w'라서 열 때 파일이 비워지고 three만 쓰여요.

헷갈리기 쉬운 곳

  • 'w'는 쓰기 시작할 때가 아니라 여는 순간 내용을 지워요. 아무것도 안 쓰고 열었다가 닫기만 해도 파일이 비어요.

핵심 한 줄: 'w'는 지우고 새로, 'a+'는 뒤에 이어서 써요.

초급 3읽기

readline 은 부를 때마다 다음 줄

lines.txt에는 1번째 줄부터 15번째 줄까지 한 줄에 하나씩 들어 있어요.

f = open('lines.txt', encoding='utf-8')  # f 에 lines.txt 를 UTF-8 읽기용으로 열어 담아 주세요
a = f.readline()                         # a 에 f 의 한 줄을 담아 주세요
b = f.readline()                         # b 에 f 의 다음 한 줄을 담아 주세요
print(a == b)                            # a 와 b 가 같은지 화면에 보여 주세요
print(a.strip(), b.strip())              # a 와 b 의 줄 끝을 지워 화면에 보여 주세요
print(len(a))                            # a 의 글자 수를 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측

2번째 줄?
3번째 줄?
힌트 보기

readline()은 부를 때마다 읽던 자리 다음 줄을 줘요. 글자 수를 셀 때는 줄 끝의 \n도 한 글자예요.

정답·해설 보기 
False
1번째 줄 2번째 줄
6

한 문장으로: 두 번 읽으면 서로 다른 줄(1번째 줄, 2번째 줄)이고, 줄 끝의 \n까지 세서 글자 수는 6이에요.

왜 이런 결과가 나올까요

a는 첫 줄, b는 그 다음 줄이라 둘은 달라요. a의 실제 값은 '1번째 줄\n'이라서 1·번·째·공백·줄·\n 여섯 글자예요.

헷갈리기 쉬운 곳

  • 눈에 보이는 글자는 다섯 개라 5라고 답하기 쉬워요. 줄 끝의 \n은 화면에 안 보이지만 글자 수에 들어가요.

핵심 한 줄: readline()은 부를 때마다 다음 줄이고, 줄 끝 \n도 글자예요.

중급

6.2 ~ 6.3 읽은 자리·슬라이싱·split·pickle

읽던 자리, 줄 끝 \n 과 print, 빈 줄로 자르기, pickle 로 값 되살리기를 읽어요.

중급 1읽기

다 읽으면 빈 글자 — seek 로 되돌리기

파일에는 "어디까지 읽었나"를 기억하는 자리가 하나 있어요. Python_for_Fun.txt 전체는 61글자예요.

f = open('Python_for_Fun.txt')  # f 에 Python_for_Fun.txt 를 읽기용으로 열어 담아 주세요
first = f.readline()            # first 에 f 의 첫 줄을 담아 주세요
rest = f.read()                 # rest 에 f 의 나머지 전부를 글자 하나로 담아 주세요
again = f.read()                # again 에 f 를 한 번 더 읽은 것을 담아 주세요
print(repr(first))              # first 를 보이는 모양 그대로 화면에 보여 주세요
print(len(rest))                # rest 의 글자 수를 화면에 보여 주세요
print(repr(again))              # again 을 보이는 모양 그대로 화면에 보여 주세요
f.seek(0)                       # f 의 읽는 자리를 맨 앞으로 돌려 주세요
print(f.readline() == first)    # f 의 첫 줄이 first 와 같은지 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
4번째 줄?
힌트 보기

전체 61글자 중 첫 줄이 몇 글자인지 세어 보세요. rest는 나머지예요. 그리고 다 읽은 뒤에 읽으면 무엇이 남아 있을까요?

정답·해설 보기 
'Programming is fun.\n'
41
''
True

한 문장으로: 첫 줄을 읽고 남은 41글자를 read()가 가져가서, 다시 읽으면 빈 글자이고, seek(0) 뒤에는 다시 첫 줄부터 읽혀요.

왜 이런 결과가 나올까요

첫 줄 'Programming is fun.\n'은 20글자라 나머지는 61 − 20 = 41글자예요. read()가 끝까지 읽은 뒤에는 읽을 것이 없어서 again은 빈 글자예요. seek(0)으로 자리를 맨 앞으로 되돌리면 readline()이 다시 첫 줄을 줘서 first와 같아요.

헷갈리기 쉬운 곳

  • 파일을 한 번 읽고 나서 같은 파일 객체로 다시 read()하면 에러 없이 빈 글자만 돌아와요. 아무 일도 없다는 듯 조용해서 알아차리기 어려워요.
  • 이미 읽은 내용이 필요하면 변수에 담아 두거나, seek(0)으로 되돌리거나, 파일을 새로 열어요.

핵심 한 줄: 파일은 읽은 만큼 앞으로 가고, 끝까지 읽으면 빈 글자만 나와요. seek(0)이 맨 앞으로 되돌려요.

중급 2읽기

슬라이싱과 end 로 줄 바꿈 조절

읽어 온 줄 끝에는 \n이 붙어 있어서, print를 어떻게 쓰느냐에 따라 빈 줄이 생겨요. 출력에서 빈 줄도 한 줄로 세세요.

lines = open('lines.txt', encoding='utf-8').readlines()  # lines 에 lines.txt 의 모든 줄을 리스트로 담아 주세요
print(len(lines))                                        # lines 의 원소 개수를 화면에 보여 주세요
for l in lines[-2:]:                                     # lines 의 뒤에서 두 개를 하나씩 l 이라 부르며 아래를 반복해 주세요
    print(l)                                             # l 을 화면에 보여 주세요
for l in lines[:2]:                                      # lines 의 앞 두 개를 하나씩 l 이라 부르며 아래를 반복해 주세요
    print(l, end='')                                     # l 을 줄 바꿈을 더하지 않고 화면에 보여 주세요
print(lines[0][:-1])                                     # lines 의 첫 줄에서 마지막 글자를 뺀 것을 화면에 보여 주세요

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
4번째 줄?
5번째 줄?
6번째 줄?
7번째 줄?
8번째 줄?
힌트 보기

print(l)은 l 끝의 \n에 print가 줄 바꿈을 하나 더해서 두 번 바뀌어요. [:-1]은 마지막 글자만 빼요.

정답·해설 보기 
15
14번째 줄

15번째 줄

1번째 줄
2번째 줄
1번째 줄

한 문장으로: 뒤에서 두 줄은 줄 바꿈이 두 번씩이라 사이사이 빈 줄이 생기고, 앞 두 줄은 end=''라 빈 줄 없이 붙어요.

왜 이런 결과가 나올까요

15 다음에 lines[-2:]의 두 줄을 print(l)로 출력해서 14번째 줄, 빈 줄, 15번째 줄, 빈 줄이 나와요. 이어서 앞 두 줄은 end=''라서 1번째 줄, 2번째 줄이 바로 붙어 나오고, 마지막 lines[0][:-1]은 '1번째 줄\n'에서 \n을 뺀 1번째 줄이에요.

헷갈리기 쉬운 곳

  • 마지막 print(lines[0][:-1])은 strip()과 비슷하지만, 마지막 글자가 \n이 아니면(파일의 마지막 줄에 줄 바꿈이 없을 때) 엉뚱한 글자가 지워져요. 줄 끝 정리는 strip()이 안전해요.

핵심 한 줄: 읽은 줄 끝에는 \n이 있어서, print(l, end='')나 strip()으로 다뤄요.

중급 3읽기

빈 줄로 자르면 몇 덩어리

postcard.txt는 머리말(두 줄) · 빈 줄 · 본문(여섯 줄) · 빈 줄 · 꼬리말(두 줄)로 이뤄진 열두 줄 파일이고, 마지막 줄 끝에도 \n이 있어요.

text = open('postcard.txt').read()   # text 에 postcard.txt 의 내용 전부를 글자 하나로 담아 주세요
parts = text.split('\n\n')           # parts 에 text 를 빈 줄에서 잘라 리스트로 담아 주세요
print(len(parts))                    # parts 의 원소 개수를 화면에 보여 주세요
print(len(text.splitlines()))        # text 의 줄 수를 화면에 보여 주세요
print(parts[1].count('\n'))          # parts 의 1번 자리 안에 줄 바꿈이 몇 번 나오는지 화면에 보여 주세요
print(parts[2].strip().split()[-1])  # parts 의 2번 자리를 낱말로 나눈 것의 마지막 낱말을 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
4번째 줄?
힌트 보기

빈 줄은 줄 바꿈 두 번이에요. 본문이 여섯 줄이면 그 안의 줄 바꿈은 몇 번일까요? (마지막 줄 끝은 다음 빈 줄과 함께 잘렸어요.)

정답·해설 보기 
3
12
5
Jonelis

한 문장으로: 빈 줄 두 개가 파일을 세 덩어리로 나누고, 본문 덩어리 안에는 여섯 줄 사이의 줄 바꿈 5번이 남아요.

왜 이런 결과가 나올까요

빈 줄 두 개를 기준으로 잘라서 parts는 3개예요. splitlines()는 빈 줄까지 세서 12줄이에요. 본문 parts[1]은 여섯 줄인데, 마지막 줄 끝의 \n은 구분자 \n\n에 먹혀서 안에는 \n이 5번만 남아요. 꼬리말 parts[2]는 (signed)와 이름 Frank G. Jonelis라서 마지막 낱말은 Jonelis예요.

헷갈리기 쉬운 곳

  • 구분자 \n\n은 글자 두 개짜리라서, 잘리는 곳의 줄 바꿈 두 번이 다 사라져요. 그래서 잘린 앞 덩어리들(parts[0], parts[1])의 끝에는 \n이 안 남아요. 마지막 덩어리 parts[2]는 잘린 자리가 아니라서 파일 끝의 \n이 남아 있어요.

핵심 한 줄: split('\n\n')은 빈 줄에서 자르고, 덩어리 끝의 줄 바꿈은 구분자와 함께 사라져요.

중급 4읽기

pickle 은 같은 값을 새로 만든다

pickle로 저장했다 불러오면 값이 같아지는지, 같은 대상인지 확인해요.

import pickle                      # pickle 모듈을 가져와 주세요
data = {'a': [1, 2], 'b': (3, 4)}  # data 에 리스트와 튜플이 든 딕셔너리를 담아 주세요
with open('d.bin', 'wb') as f:     # d.bin 을 바이트 쓰기용으로 열어 f 라 불러 주세요
    pickle.dump(data, f)           # data 를 f 에 저장해 주세요
with open('d.bin', 'rb') as f:     # d.bin 을 바이트 읽기용으로 열어 f 라 불러 주세요
    back = pickle.load(f)          # back 에 f 에서 되살린 값을 담아 주세요
print(back)                        # back 을 화면에 보여 주세요
print(back == data)                # back 이 data 와 같은지 화면에 보여 주세요
print(back is data)                # back 과 data 가 같은 대상인지 화면에 보여 주세요
print(type(back['b']))             # back 의 'b' 자리의 자료형을 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
4번째 줄?
힌트 보기

==는 "내용이 같은가", is는 "같은 대상인가"를 물어요. 파일을 거쳐 온 값은 새로 만들어진 값이에요.

정답·해설 보기 
{'a': [1, 2], 'b': (3, 4)}
True
False
<class 'tuple'>

한 문장으로: pickle은 내용이 같은 새 값을 만들어 주고, 리스트는 리스트로 튜플은 튜플로 그대로 되살려요.

왜 이런 결과가 나올까요

되살린 back은 data와 모양이 같아서 ==는 True예요. 하지만 파일에서 새로 만든 값이라 data 자체와는 다른 대상이라 is는 False예요. 튜플 (3, 4)는 리스트로 바뀌지 않고 튜플로 돌아와요.

헷갈리기 쉬운 곳

  • 글자로 저장하는 방식(예: 파일에 str(data)를 쓰기)은 되살릴 때 글자만 나와요. pickle은 자료형까지 그대로 되살려요.
  • 내가 저장한 파일만 불러와요. 출처를 모르는 pickle 파일은 불러올 때 코드가 실행될 수 있어요.

핵심 한 줄: pickle.dump와 pickle.load는 자료형까지 같은 새 값을 되살려요.

고급

읽고 추리하기 — glob·세기·인코딩

glob 패턴, 줄·낱말을 세는 여러 길, 윈도우의 인코딩 오류를 읽어요.

고급 1읽기

glob 패턴과 폴더 가려내기

비어 있는 폴더에서 시작해요. open(이름, 'w').close()는 아무것도 쓰지 않고 빈 파일만 만들어요. 패턴에서 *는 아무 글자 여러 개, ?는 아무 글자 딱 하나예요.

import os                                                  # os 모듈을 가져와 주세요
from glob import glob                                      # glob 모듈에서 glob 을 가져와 주세요
os.mkdir('logs')                                           # logs 라는 폴더를 만들어 주세요
for n in ['b.txt', 'a.txt', 'c.log']:                      # 이름 세 개를 하나씩 n 이라 부르며 아래를 반복해 주세요
    open(n, 'w').close()                                   # n 이라는 빈 파일을 만들어 주세요
print(sorted(glob('*.txt')))                               # .txt 로 끝나는 이름들을 정렬해 화면에 보여 주세요
print(sorted(glob('?.*')))                                 # 한 글자 뒤에 점이 오는 이름들을 정렬해 화면에 보여 주세요
print(len(glob('*')))                                      # 폴더 안 모든 이름의 개수를 화면에 보여 주세요
print([x for x in sorted(glob('*')) if os.path.isdir(x)])  # 이름들 중 폴더인 것만 정렬해 리스트로 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
3번째 줄?
4번째 줄?
힌트 보기

logs는 폴더지만 이름에는 .txt도 점도 없어요. 패턴이 이름 전체와 맞아야 해요.

정답·해설 보기 
['a.txt', 'b.txt']
['a.txt', 'b.txt', 'c.log']
4
['logs']

한 문장으로: glob은 패턴에 맞는 이름만 골라 주고, 폴더도 파일과 같은 "이름"이라 isdir로 따로 가려내요.

왜 이런 결과가 나올까요

*.txt는 .txt로 끝나는 a.txt와 b.txt예요. ?.*는 한 글자 뒤에 점이 오는 a.txt, b.txt, c.log이고 logs는 점이 없어서 빠져요. *는 파일 세 개와 폴더 하나, 모두 4개예요. 그중 isdir가 참인 것은 logs 하나예요.

헷갈리기 쉬운 곳

  • glob('*.txt')의 결과 순서는 정해져 있지 않아서, sorted()를 안 붙이면 컴퓨터마다 순서가 다를 수 있어요.
  • glob의 결과에는 폴더도 섞여서 나와요. 파일만 필요하면 isdir나 os.path.isfile로 거르세요.

핵심 한 줄: glob 패턴은 이름 전체와 맞아야 하고, 폴더도 이름 목록에 섞여 나와요.

고급 2읽기

줄 수·낱말 수·글자 수를 세는 길

postcard.txt(열두 줄, 마지막 줄 끝에도 \n)로 같은 대상을 세 가지 길로 세요. 두 번째 줄 출력에서 앞 숫자는 줄 수, 뒤 숫자는 낱말 수예요.

with open('postcard.txt') as f:                                     # postcard.txt 를 읽기용으로 열어 f 라 불러 주세요
    lines = f.readlines()                                           # lines 에 f 의 모든 줄을 리스트로 담아 주세요
words = 0                                                           # words 에 0 을 담아 주세요
for line in lines:                                                  # lines 의 줄을 하나씩 line 이라 부르며 아래를 반복해 주세요
    words += len(line.split())                                      # words 에 line 의 낱말 개수를 더해 주세요
print(len(lines), words)                                            # lines 의 개수와 words 를 화면에 보여 주세요
text = open('postcard.txt').read()                                  # text 에 postcard.txt 의 내용 전부를 글자 하나로 담아 주세요
print(len(text.split()), len(text.splitlines()), text.count('\n'))  # text 의 낱말 수, 줄 수, 줄 바꿈 수를 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
힌트 보기

줄 하나에 줄 바꿈이 하나씩 있어요. 빈 줄은 낱말이 0개인 줄이에요. 낱말 수는 어느 길로 세도 같아요.

정답·해설 보기 
12 34
34 12 12

한 문장으로: 줄을 먼저 읽어 세든 글 전체를 한 번에 읽어 세든 낱말은 같은 수이고, 줄 바꿈 수는 줄 수와 같아요.

왜 이런 결과가 나올까요

readlines()로 읽으면 12줄이고, 각 줄의 낱말을 더하면 전체 낱말 수가 나와요. 글 전체를 split()해도 같은 낱말 수가 나와요. splitlines()의 줄 수 12와 count('\n')의 12가 같은 건, 모든 줄 끝(마지막 줄 포함)에 줄 바꿈이 있기 때문이에요.

헷갈리기 쉬운 곳

  • 마지막 줄 끝에 \n이 없는 파일이면 count('\n')이 줄 수보다 1 적어요. 줄 수를 셀 때는 splitlines()나 readlines()가 안전해요.

핵심 한 줄: 낱말 수는 줄로 세든 통째로 세든 같고, 줄 바꿈 수는 줄 수와 (마지막 줄 끝에 있으면) 같아요.

고급 3읽기

한글 파일을 인코딩 없이 열면 (윈도우 기준)

이 문제의 결과는 한국어 윈도우에서 돌렸을 때예요. 이 컴퓨터에서는 파일을 열 때의 기본 글자 규칙이 cp949라서 UTF-8과 달라요. try/except는 오류가 나도 프로그램을 멈추지 않고 except 아래로 넘어가게 해요.

with open('k.txt', 'w', encoding='utf-8') as f:  # k.txt 를 UTF-8 쓰기용으로 열어 f 라 불러 주세요
    f.write('안녕하세요')                             # f 에 '안녕하세요' 를 써 주세요
try:                                             # 아래를 시도해 주세요
    print(open('k.txt').read())                  # k.txt 를 인코딩 없이 읽어 화면에 보여 주세요
except UnicodeDecodeError:                       # 글자를 읽는 규칙이 안 맞는 오류가 나면
    print('읽기 실패')                               # '읽기 실패' 를 화면에 보여 주세요
print(open('k.txt', encoding='utf-8').read())    # k.txt 를 UTF-8 로 읽어 화면에 보여 주세요

이 코드를 실행하면 무엇이 출력될까요?

출력예측
1번째 줄?
2번째 줄?
힌트 보기

파일은 UTF-8로 썼어요. 인코딩을 안 적고 읽으면 윈도우는 UTF-8이 아닌 규칙으로 읽으려 해요.

정답·해설 보기 
읽기 실패
안녕하세요

한 문장으로: 글자를 쓸 때와 읽을 때의 인코딩이 다르면 읽기 단계에서 UnicodeDecodeError가 나고, 둘을 같게 맞추면 읽혀요.

왜 이런 결과가 나올까요

쓸 때 encoding='utf-8'을 지정했는데 읽을 때 빼면 윈도우는 기본 규칙으로 읽으려다 UnicodeDecodeError가 나서 except 쪽이 실행돼요. 마지막 줄은 읽을 때도 encoding='utf-8'을 적었으니 정상으로 읽혀요.

헷갈리기 쉬운 곳

  • 맥이나 리눅스는 기본 규칙이 UTF-8이라 인코딩을 안 적어도 읽히는 일이 많아요. 같은 코드가 한 컴퓨터에서만 오류가 나면 인코딩을 의심해요.
  • 글자가 영어뿐인 파일은 이 차이가 드러나지 않아서, 한글이 들어간 뒤에야 오류가 나는 경우가 많아요.

핵심 한 줄: 한글 파일은 쓸 때도 읽을 때도 encoding='utf-8'을 적어요.
