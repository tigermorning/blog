GitHub Actions 예약 발행 (5)

2026. 7. 12.

4편까지 만들고 나니, 새로운 고민이 생겼어요. 글을 여러 편 몰아서 써두고 한꺼번에 올리면, 나중에 애드센스 심사 같은 걸 받을 때 "이거 AI가 대량으로 찍어낸 거 아니야?"라고 보일 수 있다는 거였어요. 그래서 미리 써둔 글을 하루에 몇 개씩, 시간 간격을 두고 자동으로 발행해주는 시스템을 만들어봤어요.

1. 목표 정하기, 그리고 큐(대기열) 파일 만들기

만들기 전에 "무엇을 자동으로 하게 할지"부터 문장으로 적어봤어요. 자동화는 한 번 만들어두면 제가 안 보는 사이에도 계속 도니까, 규칙이 애매하면 엉뚱한 일이 조용히 반복되거든요. 그래서 조건을 이렇게 못 박았어요.

  • 하루 최대 3개까지만 발행
  • 발행 간격은 6시간 (한국시간 09시 / 15시 / 21시)
  • 3개보다 많으면 자동으로 다음 날로 이월
  • 날짜를 일일이 계산할 필요 없이, 순서대로 큐에 넣기만 하면 되도록

네 가지 목표 중에 제일 까다로운 건 마지막 "날짜를 계산하지 않는다"였어요. 글마다 발행 날짜를 손으로 적어두면, 하루라도 밀리는 순간 뒤에 있는 날짜를 전부 다시 고쳐야 하니까요. 그래서 날짜 대신 순서만 관리하기로 했어요. 이렇게 "먼저 넣은 것이 먼저 나가는 줄 세우기"를 프로그래밍에서는 큐(queue, 대기열)라고 불러요. 매표소 줄과 똑같아요. 맨 앞 사람이 표를 받고 빠지면 뒷사람이 자동으로 맨 앞이 되니까, 아무도 순번을 다시 매길 필요가 없죠.

그래서 발행 순서를 적어두는 파일을 하나 만들었어요. _drafts/queue.txt에 발행할 글의 경로를 한 줄씩 순서대로 적어두는 방식이에요. (_drafts는 "아직 공개 안 한 글을 모아두는 폴더"로 제가 따로 만든 곳이에요.)

🎨 바이브 코딩으로: 새 글을 다 쓰고 나면 Claude에게 "이 글 예약 발행 큐에 넣어줘"라고 말하면, 큐 파일에 순서대로 추가해줘요. 날짜를 계산할 필요가 전혀 없어요.

2. GitHub Actions로 정해진 시간마다 실행하기

줄은 세워뒀는데, 정해진 시각에 그 줄의 맨 앞을 꺼내줄 누군가가 필요해요. 제 컴퓨터에 알람을 걸어둘 수도 있지만, 그러면 컴퓨터가 꺼져 있는 새벽에는 아무 일도 일어나지 않죠. 그래서 항상 켜져 있는 쪽, 그러니까 GitHub에 이 일을 맡기기로 했어요.

GitHub Actions는 "정해진 조건이 되면 GitHub 서버가 대신 특정 작업을 실행해주는 기능"이에요. 제 컴퓨터나 Claude 세션이 꺼져 있어도 GitHub 쪽에서 알아서 실행해주니까 훨씬 안정적이에요.

🔍 궁금하다면: 실제로 어떻게 설정할까?

시키는 방법이 좀 특이했어요. 사이트 화면에서 버튼을 누르는 게 아니라, 저장소 안에 파일을 하나 만들어두면 그게 곧 지시가 돼요. .github/workflows/라는 정해진 폴더 안에 publish-drafts.yml 같은 파일을 두면, GitHub이 그 파일을 읽고 "아, 이런 일을 이때 하라는 거구나" 하고 알아들어요. 이 파일 한 장을 워크플로(workflow, 작업 흐름)라고 불러요.

실행 시각은 그 안에 cron이라는 표기법으로 적어요. 이 이름은 시간을 뜻하는 그리스어 chronos에서 온 말인데, 오래전부터 컴퓨터에서 "정해진 시각마다 반복 실행"을 맡아온 기능 이름이 그대로 굳은 거예요.

on:
  schedule:
    - cron: '0 0 * * *'    # 한국시간 09:00
    - cron: '0 6 * * *'    # 한국시간 15:00
    - cron: '0 12 * * *'   # 한국시간 21:00

GitHub 서버는 한국시간이 아니라 UTC(세계표준시) 기준이라서, 한국시간 09시를 표현하려면 9시간을 빼서 UTC 00시로 적어야 해요.

시간표는 정했으니, 이제 그 시각이 됐을 때 실제로 무슨 일을 할지가 남았어요. 여기서 "하루 3개"라는 목표를 지키는 방법이 의외로 간단했어요. 한 번 실행될 때 딱 한 편만 처리하게 만들면 되더라고요. 정해진 시각이 되면 작은 스크립트가 실행돼서 이런 일을 해요.

  1. 큐 파일의 맨 위 한 줄만 읽기
  2. 그 글 파일을 _drafts에서 진짜 위치(ko/ 등)로 옮기기
  3. 큐 파일에서 그 줄 삭제 (나머지는 자연스럽게 다음 차례로)
  4. 커밋하고 push
  5. (덤으로) sitemap.xml에도 새 글 주소를 자동으로 추가

한 번 실행에 딱 하나만 처리하기 때문에, 아무리 큐에 글이 쌓여 있어도 하루 3번(3개)을 절대 넘지 않아요.

3. 저장소 권한 설정, 그리고 하루 발행 개수 챙기기

그런데 여기까지 만들고 돌려보니 한 번에 되지 않았어요. 위 4단계의 마지막이 "커밋하고 push"인데, 이건 사람이 아니라 GitHub Actions가 제 저장소에 직접 글을 쓰는 행위거든요. GitHub은 안전을 위해 자동화에게 기본적으로 읽기 권한만 주기 때문에, 쓰기 권한은 제가 따로 열어줘야 했어요.

  1. 저장소 Settings → 왼쪽 메뉴 Actions → General
  2. 맨 아래 Workflow permissions 항목에서 Read and write permissions 선택
  3. 저장

이 설정을 안 해두면, 자동화가 실행은 되는데 마지막에 push하는 단계에서 권한 오류가 나요.

이제 자동으로 잘 도는데, 돌려놓고 보니 이 시스템이 못 보는 사각지대가 하나 있었어요. 처음 정한 목표가 "하루 최대 3개"였잖아요. 그런데 이 자동화는 자기가 실행한 횟수만 셀 뿐, 제가 그날 직접 커밋해서 올린 글은 전혀 몰라요. 자동으로 3개가 나가고 제가 직접 2개를 더 올리면, 그날 하루에 5개가 나가버리는 거죠. 애초에 이 시스템을 만든 이유가 "한꺼번에 쏟아내지 않기"였는데 말이에요. 그래서 "오늘 이미 직접 올린 게 있으니 큐에 있는 글은 내일로 미뤄야 한다"는 판단만큼은 사람(저와 Claude)이 따로 챙겨야 하는 부분으로 남았어요.

이 스크립트는 발행할 때마다 sitemap.xml도 자동으로 갱신하는데, sitemap이 왜 필요한지는 아래 글에서 자세히 다뤘어요.
