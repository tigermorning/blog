에이전트가 정말 일했는지는 채팅창의 답변 문장이 아니라 세션 기록의 결과 줄과 사용량 숫자로 확인한다.

2편에서 WebChat에 첫 문장을 보냈어요. 화면에는 답이 떴죠. 그런데 강의는 여기서 한 박자 멈추게 했어요. "답변 문장은 작업이 끝났다는 인상을 줄 뿐이다." 실제로 도구를 불렀는지, 파일이 바뀌었는지, 토큰을 얼마나 썼는지는 화면 뒤의 기록을 봐야 알아요. 이 편은 강의의 두 절(세션 기록 읽기, 모니터링)을 하나로 묶었어요. 둘 다 "화면 말고 흔적을 보라"는 같은 질문이라서요.

비유 — 병원의 진료 기록과 영수증

병원에 갔다 오면 의사가 "약 처방했고 검사도 했어요"라고 말해요. 하지만 정말 무슨 검사를 했는지는 진료 기록부에 적힌 검사 항목과 결과지를 봐야 알고, 얼마가 들었는지는 영수증을 봐야 알아요. 진료 기록부는 환자별로 따로 보관되고, 병원의 운영 규정집은 또 다른 서랍에 있어요.

비유 속 요소원래 개념
의사의 말 "검사했어요"채팅창에 보이는 답변 문장 (text)
진료 기록부의 "검사 지시" 항목모델이 하겠다고 요청한 도구 호출 (toolCall)
검사 결과지실제 실행 결과 줄 (toolResult)
지시와 결과지를 잇는 접수 번호toolCallId

핵심 한 줄: "했다"는 말과 "한 기록"과 "든 비용"은 세 군데 따로 있고, 완료를 판단하려면 말이 아니라 기록과 영수증을 봐요.

전체 그림 — ~/.openclaw 아래는 세 종류로 나뉜다

2편에서 ls -la ~/.openclaw로 열어 본 폴더예요. 안에 있는 것들은 역할이 셋으로 갈려요. 저는 이 구분을 표로 정리하고 나서야 어디를 봐야 할지 감이 왔어요.

종류어디에무엇이 있나
설정~/.openclaw/openclaw.json기본 설정 파일. 채널 토큰, 에이전트 정의 같은 "어떻게 동작할지"
세션 기록~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite에이전트별 대화 기록·세션 행·실행 상태. SQLite1 파일 하나
(이전 형식)~/.openclaw/agents/<agentId>/sessions/옛 형식의 입력과 보관·지원용 자료
워크스페이스~/.openclaw/workspace파일 도구가 상대 경로를 해석하는 기본 작업 폴더. MEMORY.md(오래 남길 사실·결정), memory/(날짜별 메모)

워크스페이스2의 메모 파일은 memory/2026-09-04-제목.md처럼 날짜에 제목이 붙은 이름으로 만들어져요. 이 메모가 색인3된 상태는 openclaw memory status로 볼 수 있어요. 설정 파일, 세션 기록, 워크스페이스는 같은 파일이 아니고 각자 역할이 달라요. 규칙 파일로 AI에게 기억을 남기는 발상 자체는 스킬과 규칙 파일에서 봤는데, OpenClaw는 그걸 워크스페이스라는 폴더로 정해 두는 셈이에요.

WebChat에서 주고받는 직접 메시지는 기본적으로 메인 세션이라는 하나의 이어지는 대화로 들어가요. 이 대화의 표준 키는 agent:<agentId>:main이고, 웹 화면에서는 Home으로 열려요. 대화가 이어진다는 건 화면만이 아니라 설정·세션·워크스페이스에 남는 정보와 함께 읽어야 해요.

세션 기록의 한 줄 — 말한 것과 한 것은 다른 줄

강의에서 제일 인상 깊었던 그림이에요. 세션 기록 안에서 "말한 것"과 "한 것"은 서로 다른 줄로 저장돼요.

읽는 법: 왼쪽 상자가 모델이 낸 한 줄이에요. 그 안에 "말한 문장"(text)과 "이 도구를 이렇게 쓰겠다"는 요청(toolCall)이 같이 들어 있어요. 오른쪽 상자는 그 요청을 에이전트가 실제로 실행한 결과 줄이에요. 두 상자를 잇는 점선이 번호(toolCallId)예요. 완료 여부를 묻는다면 왼쪽의 문장이 아니라 오른쪽의 결과 줄을 봐야 해요. 왼쪽에 "정리했어요"가 있어도 오른쪽에 짝이 되는 결과 줄이 없으면 실제로는 안 한 거예요.

이 발상은 이 블로그에서 여러 번 나왔어요. 하네스 보는 법에서 "관찰"을 강조했고, 멀티 에이전트 판정에서 "통과했다는 말로는 부족하다"고 했죠. OpenClaw는 그 원칙을 기록 파일의 구조 자체에 박아 둔 경우예요.

직접 관찰하는 순서

  1. 터미널에서 ~/.openclaw/ 아래를 열고 설정 파일과 에이전트별 폴더 이름을 먼저 찾아요. 개인 대화와 자격 증명은 복사하거나 공유하지 않아요.
  2. WebChat의 Home에서 짧은 대화를 한 번 더 보내요.
  3. 같은 위치에서 세션 저장소와 워크스페이스의 파일 이름과 수정 시각을 다시 비교해요. 어느 대화가 어떤 흔적을 남겼는지가 여기서 보여요.

사용량 보기 — 채팅 안에서, 그리고 명령줄에서

맡긴 일이 늘수록 "얼마나 쓰고 있나"가 중요해져요. 단위부터 정리하면, 토큰4은 모델이 글을 주고받는 양을 세는 단위예요. 입력과 출력을 각각 세고, 비용은 이 양에서 계산돼요. 그리고 지금 대화가 얼마나 커졌는지(세션 단위)와 지금까지 얼마를 썼는지(전체 요약)는 다른 질문이에요. 이 둘을 나눠 보는 습관이 이 절의 목표였어요.

WebChat 대화창에 슬래시로 시작하는 명령을 그대로 입력해요.

/status

상태 카드가 답으로 와요. 세션 토큰과 추정 비용이 적히고, 인증 방식에 따라 현재 모델 제공사의 사용량 창 요약이 같이 보여요. 사용량 표시는 토글이에요. /usage를 인수 없이 입력할 때마다 끄기 → 토큰 → 자세히 순서로 돌아가고, 자리를 바로 지정할 수도 있어요.

/usage

/usage full
/usage cost
명령보여 주는 것

입력 토큰과 출력 토큰 중 어느 쪽이 큰지, 대화가 길어지면서 어느 쪽이 빨리 불어나는지가 "이 대화를 얼마나 더 이어 붙일지"를 판단하는 재료가 돼요. 컨텍스트 창이 왜 유한하고 왜 길어지면 비용이 느는지는 컨텍스트 창은 왜 유한한가에서 다뤘어요.

터미널에서는 같은 정보를 표로 봐요. 첫 줄은 게이트웨이가 살아 있는지와 제공자별 사용량·할당량을, 둘째 줄은 인증 프로필의 상태를 보여 줘요. 2편의 온보딩에서 고른 인증 경로가 여기 다시 나타나는지 확인하고, 연결이 죽었거나 인증이 만료된 프로필이 있다면 이 표에서 먼저 보여요.

openclaw status --usage
openclaw models status

구독 한도와 API 비용은 같은 숫자가 아니다

제가 이 절에서 가장 중요하게 본 대목이에요. 사용량 화면의 숫자는 2편에서 고른 인증 경로에 따라 뜻이 달라져요.

인증 경로화면의 숫자누가 계산하나이 숫자의 뜻
API 키호출마다 계산한 추정 비용OpenClaw (키를 직접 들고 있으니까)돈
구독 로그인남은 한도 비율 (제공사의 사용량 창)제공사남은 양

같은 화면에 있어도 하나는 돈이고 하나는 남은 양이에요. 어느 경로로 접속했는지 모른 채 숫자만 보면 "남은 비율"을 "남은 돈"으로 잘못 읽어요. 접속 경로와 숫자의 뜻은 함께 읽어야 해요. 토큰 비용의 감각은 AI에게 컴퓨터를 맡길 때 — 권한, 로컬 모델, 토큰 비용에서 처음 잡았어요.

운영용 관측 도구는 따로 있다

지금까지 본 화면은 "내 세션을 내가 보는" 도구예요. 여러 사람이 함께 쓰는 설비에는 관측이 더 필요하고, OpenClaw는 그 운영용 도구를 따로 갖추고 있어요. OpenTelemetry로 지표를 밖으로 내보내거나 Prometheus로 모아 보거나, audit(감사 기록)로 누가 무엇을 승인했는지 이력을 남기는 것들이에요. 오늘은 이름과 "운영용"이라는 사실까지만 알아 뒀어요.

문제를 보고할 때 쓰는 진단 번들도 있어요. 상태와 로그를 압축 파일 하나로 모아 주는데, 개인정보를 가려 주더라도 로그 요약이 들어 있으니 함부로 나누지 않고 비밀 자료처럼 다뤄요. 제품이 스스로 보내는 통계는 하루 한 번 버전 확인이 전부이고, 기능 사용 통계는 동의하기 전까지 꺼져 있어요. 정리하면 내 사용량 관찰, 문제 분석 자료, 제품 개선 통계는 목적과 개인정보 경계가 다른 세 가지예요. 데이터가 어디에 남는지의 감각은 데이터는 어디에 남는가와 같은 결이에요.

나쁜 선택 vs 좋은 선택 — 진료 기록을 읽을 때

나쁜 선택좋은 선택

WebChat에서 "워크스페이스에 오늘 날짜 메모를 하나 남겨 줘"라고 시켜 보세요. 그다음 세 곳을 순서대로 봐요. 답변 문장, ~/.openclaw/workspace/memory/의 새 파일과 수정 시각, 그리고 /usage tokens의 입력·출력 숫자. 셋이 서로 맞으면 "했다"가 진짜예요. 하나라도 어긋나면 어디가 어긋났는지가 그날의 공부예요.

  1. SQLite — 서버 없이 파일 하나로 동작하는 작은 데이터베이스로, 데이터베이스 자체는 SQL 구경하기에서 처음 다뤘어요. ↩
  2. 워크스페이스 — 에이전트가 파일을 읽고 쓸 때 기준으로 삼는 기본 작업 폴더. ↩
  3. 색인 — 나중에 빨리 찾을 수 있도록 내용을 미리 정리해 둔 목록. ↩
  4. 토큰 — 모델이 글을 읽고 쓰는 최소 단위로, AI 토큰이란 무엇인가에서 처음 다뤘어요. ↩
  5. 컨텍스트 창 — 모델이 한 번에 읽을 수 있는 토큰의 최대 양으로, 컨텍스트 창은 왜 유한한가에서 다뤘어요. ↩

"OpenClaw로 내 에이전트 운영하기" 시리즈

(1) 새 껍데기, 같은 바닷가재 — OpenClaw는 무엇이고 어디서 왔나 (2) 연습 폴더에 들이기 — 설치·온보딩·첫 대화
