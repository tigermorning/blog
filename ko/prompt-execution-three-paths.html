프롬프트 기법의 역사에서 system·이력이 답을 어떻게 바꾸는지 이론으로 봤다면, 이번엔 손으로 직접 세 가지 실행 경로를 돌려봤다. 결론부터 말하면 같은 "system 지시"라는 개념도 라이브러리마다 받는 자료형이 다르다. 인터페이스 차이를 감춰야 할 결함이 아니라, 실행 환경을 고를 때 확인할 조건으로 보는 법을 배웠다.

세 번째 경로에 나오는 Ollama는 내 컴퓨터 안에서 AI 모델을 내려받아 돌려 주는 무료 프로그램이다. 설치와 첫 실행은 직접 Ollama로 로컬 LLM 돌려보기에서 다뤘으니, 아직 안 깔았다면 그 글부터 보고 오는 편이 낫다.

1. 세 경로, 세 가지 자료형

경로되는 것주의할 점
Claude Agent SDKClaude Code 구독 로그인으로 인증, ClaudeAgentOptions(system_prompt=...)와 query()의 비동기 user 메시지 생성기로 실행범용 chat completions식 messages 배열 API가 아니다. assistant 이력을 배열로 주입하는 방식이 이 SDK의 자연스러운 사용이 아니다
LangChain + GeminiAPI 키로 인증, SystemMessage, HumanMessage, AIMessage 객체 목록을 invoke()에 전달추상화가 공급자별 고유 기능을 감출 수 있다. 일시적 503 UNAVAILABLE처럼 호출 실패는 지시 실패가 아니다
Ollama인증 없이 로컬 모델 실행, system·user·assistant role 딕셔너리 목록을 chat()에 전달로컬이라는 사실이 품질을 보장하지 않는다. 이력을 넣은 호출에서 소형 모델의 응답이 매우 짧을 수 있다

한쪽의 입력 모양을 다른 쪽에 억지로 옮기지 말고, 각 인터페이스가 실제로 받는 것을 읽어야 한다는 게 첫 번째 교훈이었다.

2. Claude Agent SDK — 에이전트 입력 스트림 그대로 쓰기

Claude 경로는 Claude Code 로그인과 claude-agent-sdk 설치가 필요하다. 공통 지시는 system_prompt에, 사용자의 현재 요청은 비동기 생성기가 내보내는 user 메시지에 둔다. max_turns=1은 에이전트 턴 수를 제한할 뿐 답변 길이를 제한하지 않고, tools=[]는 도구 호출을 제외한다.

실행: 로컬 파이썬 — claude-agent-sdk 설치 + Claude Code 로그인 필요

import asyncio
from pathlib import Path
from claude_agent_sdk import ClaudeAgentOptions, query

QUESTION = "배송일은 언제인가요?"
SYSTEM_A = "고객 문의에 정중하게 답한다"
SYSTEM_B = "기술 문서 톤으로 답한다"

async def user_messages(text):
    yield {"type": "user", "message": {"role": "user", "content": text}}

async def save_run(filename, system_prompt):
    options = ClaudeAgentOptions(system_prompt=system_prompt, max_turns=1, tools=[])
    record = [f"system_prompt: {system_prompt}", f"user: {QUESTION}"]
    async for event in query(prompt=user_messages(QUESTION), options=options):
        record.append(f"{type(event).__name__}\n{event!r}")
    Path(filename).write_text("\n\n".join(record), encoding="utf-8")

async def main():
    await save_run("claude-system-a.txt", SYSTEM_A)
    await save_run("claude-system-b.txt", SYSTEM_B)

asyncio.run(main())

이 SDK는 앞선 assistant 답변을 입력 문자열에 role 태그로 다시 조립해 넣는 걸 지원하지 않는다. 멀티턴 효과를 role 배열로 관찰하려면 LangChain이나 Ollama 경로를 쓴다.

3. system만 바꿔 재호출한 결과 — 문체 자체가 달라진다

같은 질문("배송일은 언제인가요?")을 system만 바꿔 두 번 돌렸다. 실측 결과다.

고객 문의 톤(system_prompt: 고객 문의에 정중하게 답한다) — "문의해 주셔서 감사합니다. 다만 제가 지금 확인할 수 있는 주문·배송 정보가 없어서, 배송일을 바로 안내드리기 어렵습니다. 정확한 안내를 위해 아래 내용을 알려주시면 도움이 됩니다. 주문번호 또는 주문 시 사용한 이메일/연락처, 어떤 상품을 주문하셨는지, 주문 일자."

기술 문서 톤(system_prompt: 기술 문서 톤으로 답한다) — "질문에 필요한 컨텍스트가 없습니다. 현재 세션에는 주문·배송 관련 정보가 없고, 연결된 도구(캘린더, 드라이브, DB, 브라우저)에도 배송 조회용 데이터 소스가 지정되지 않았습니다. 확인이 필요한 항목입니다. 어떤 배송인가, 조회 경로, 대체 소스."

둘 다 배송일을 단정하지 않았다는 점은 같다. 그러나 하나는 감사·사과와 주문자 정보 요청으로 고객 문의를 구성했고, 다른 하나는 컨텍스트·연결 도구·조회 경로로 기술적으로 분류했다. "더 좋다"가 아니라 "system 변경으로 무엇이 달라졌다"를 한 문장으로 남기는 게 이 실습의 목적이다.

4. LangChain + Gemini — 메시지 객체 목록

GEMINI_API_KEY를 셸 환경 변수로 설정한 뒤, system 지시와 대화 이력을 각각 알맞은 메시지 객체로 표현한다.

실행: 로컬 파이썬 — GEMINI_API_KEY 환경변수 필요

from pathlib import Path
from langchain_core.messages import AIMessage, HumanMessage, SystemMessage
from langchain_google_genai import ChatGoogleGenerativeAI

QUESTION = "배송일은 언제인가요?"
model = ChatGoogleGenerativeAI(model="gemini-3.7-flash")

def save_run(filename, messages):
    answer = model.invoke(messages)
    Path(filename).write_text(str(answer.content), encoding="utf-8")

save_run("gemini-with-history.txt", [
    SystemMessage("고객 문의에 정중하게 답한다"),
    HumanMessage(QUESTION),
    AIMessage("정확한 안내를 위해 주문번호 또는 운송장 번호를 알려 주세요."),
    HumanMessage("주문번호가 없으면 무엇을 확인해야 하나요?"),
])

한 걸음 더: LangChain이 이런 부품(모델 연결·메시지·도구 정의)을 맡는다면, 그 부품을 어떤 순서로 돌릴지는 같은 회사의 LangGraph가 맡아요. 두 도구와 LangSmith의 관계는 다음에 어느 코드가 실행될까 — LangGraph와 워크플로·에이전트에서 정리했어요.

5. Ollama — role 딕셔너리 목록

Ollama 앱을 실행하고 ollama pull qwen3.5:2b로 모델을 준비한 뒤, 같은 관찰을 role 딕셔너리로 표현했다.

실행: 로컬 파이썬 — Ollama 앱 실행 + 모델 준비 필요

from pathlib import Path
from ollama import chat

def save_run(filename, messages):
    response = chat(model="qwen3.5:2b", messages=messages)
    Path(filename).write_text(response.message.content, encoding="utf-8")

save_run("ollama-with-history.txt", [
    {"role": "system", "content": "고객 문의에 정중하게 답한다"},
    {"role": "user", "content": "배송일은 언제인가요?"},
    {"role": "assistant", "content": "정확한 안내를 위해 주문번호 또는 운송장 번호를 알려 주세요."},
    {"role": "user", "content": "주문번호가 없으면 무엇을 확인해야 하나요?"},
])

6. 앞선 대화를 넣었을 때, 모델이 정말 참조하는가

Claude Agent SDK 경로는 이력을 assistant role 배열로 못 넣으니, 앞선 대화를 설명한 문장을 새 user 메시지에 통째로 담아 재호출한다. 이 방식으로 "주문번호 또는 운송장 번호"라는 앞선 제안이 마지막 답에서 어떻게 이어지는지 확인하는 게 핵심이었다. 참조가 안 보이면 "앞선 대화를 user 입력에 포함했으나 응답에서 분명한 참조를 확인하지 못했다"라고 그대로 기록한다 — 이력이 입력이라는 사실과, 모델이 매번 이력을 원하는 방식으로 활용한다는 보장은 다르다.

정리

환경을 고르는 기준은 세 코드를 같은 모양으로 만드는 일이 아니었다. 구독 로그인으로 에이전트 실행을 관찰할지, API 키와 범용 메시지 추상화를 쓸지, 로컬 모델의 조건과 한계를 시험할지 결정하는 일이었다. 어느 경로든 비교할 질문은 같다 — user 요청을 고정하고 system만 바꿨을 때 문체·구조·추가 정보 요청이 무엇이 달라지는지, 앞선 대화 이력을 넣었을 때 새 응답이 그 이력을 실제로 반영하는지를 원문으로 확인하는 것.

이럴 때 의심하세요 — 세 경로를 직접 돌리다 막히거나 결과가 이상할 때

세 경로를 AI에게 짜 달라고 하면, 막히는 자리는 대개 코드 줄보다 경로 사이의 차이예요. 한 경로에서 되던 모양을 다른 경로에 옮기거나, 호출 실패를 지시 실패로 읽거나, 이력을 넣었으니 참조했겠지 하고 넘어갈 때 생겨요.

이런 증상이 보이면먼저 열어 볼 자리확인 방법
"LangChain 코드처럼 이력도 넣어 줘"라고 했더니 Claude Agent SDK 코드에서 unexpected keyword argument가 들어간 TypeError가 나고, AI가 옵션 이름을 계속 바꿔 가며 다시 시도해요 에러가 가리키는 줄의 함수와 거기 넘긴 모양이에요. query()나 ClaudeAgentOptions(...)에 role 딕셔너리 목록처럼 다른 경로의 입력 모양을 넣고 있는지 봐요 AI의 기억 말고 설치된 패키지에 물어요. 파이썬에서 help(ClaudeAgentOptions)를 실행하면 받을 수 있는 이름이 나와요. 거기 없는 이름이면 버그가 아니라 그 경로가 원래 그렇게 받지 않는 거라, 이 SDK에서는 앞선 대화를 설명한 문장을 새 user 메시지에 담는 쪽으로 가요
이력을 넣고 돌렸는데 마지막 답이 앞에서 제안한 "주문번호 또는 운송장 번호"를 이어받지 않고 처음 받은 질문처럼 답해요 모델에 실제로 넘긴 메시지 목록이에요. 호출 직전에 목록을 출력해 보고, assistant 답(AIMessage나 "assistant" 줄)이 두 user 질문 사이에 순서대로 들어갔는지 봐요 목록이 맞다면 이력을 뺀 판을 같이 돌려 두 원문을 나란히 비교해요. 차이가 안 보이면 "이력을 넣었으나 응답에서 분명한 참조를 확인하지 못했다"라고 그대로 적어요. 넣었다는 사실이 참조했다는 증거는 아니에요
system 문구를 바꾸고 돌렸더니 출력 파일이 아예 안 생기고 터미널에 긴 트레이스백(에러가 난 경로를 줄줄이 적은 기록)이 남았어요 트레이스백의 맨 마지막 줄이에요. 503 UNAVAILABLE처럼 공급자 쪽 오류인지, API 키 인증 오류인지 봐요. 방금 바꾼 system 문구는 이런 오류를 만들지 않아요 호출이 실패했다면 모델은 답을 쓰지도 않은 거예요. 지시를 그대로 둔 채 잠시 뒤 다시 돌려요. 인증 오류라면 GEMINI_API_KEY를 설정한 터미널과 코드를 실행한 터미널이 같은지 봐요. 새로 연 터미널에는 설정이 없을 수 있어요. 오류 없이 답만 이상할 때 가르는 법은 4편의 이 줄에 있어요
ollama-with-history.txt의 답이 한두 줄로 아주 짧아요. 다른 경로는 같은 입력에 길게 답했어요 코드보다 모델 태그예요. qwen3.5:2b의 2b는 매개변수가 약 20억 개인 작은 모델이라는 뜻이에요. 내 컴퓨터에서 돈 들이지 않고 반복해 볼 수 있는 대신, 답의 품질은 보장되지 않아요 같은 모델로 이력을 뺀 판도 돌려 봐요. 이력을 넣을 때만 짧아지면 그 모델의 조건으로 기록하고, 메모리가 허락하면 더 큰 태그로 같은 입력을 비교해요. 긴 문서를 넣었는데 내용을 모르는 듯 답한다면 입력이 잘렸을 수 있어요 (Ollama 글의 이 줄)

둘째 줄은 에러가 없어서 제일 놓치기 쉬워요. 그래서 이력을 넣은 판을 돌릴 때는 이력을 뺀 판도 처음부터 같이 돌려 원문을 남겨 둬요.

첫째 줄처럼 AI가 없는 옵션을 붙들고 도는 중이라면, 더 고치게 하지 말고 설치된 패키지 기준으로 대조부터 시켜요. AI가 기억하는 사용법과 내 컴퓨터에 깔린 버전이 다를 수 있거든요.

실행: 코딩 에이전트에 붙여넣기 — Claude Code 등 — 세 경로 실습 코드가 있는 폴더에서

이 폴더에서 Claude Agent SDK, LangChain, Ollama를 호출하는 곳을 전부 찾아 아래를 표로 보여 줘. 아직 코드는 고치지 마.
1. 호출마다 파일 이름·줄 번호, 부르는 함수, 넘기는 입력의 모양(비동기 생성기 / 메시지 객체 목록 / role 딕셔너리 목록)
2. 설치된 패키지 버전과, 그 버전에서 그 함수가 실제로 받는 인자 이름 (네 기억 말고 설치된 패키지의 소스나 help() 결과 기준)
3. 2에 없는 인자나 다른 경로의 입력 모양을 쓰고 있는 줄

코드가 낯설다면: 이 글의 파이썬 블록을 한 줄씩 한국어로 읽는 법은 파이썬 코드 눈으로 읽기 — 함수·변수·반복·오류·async에 정리해 두었어요.

한 걸음 더: 여기서 처음 부른 Claude Agent SDK의 query()로 같은 버그를 세 방식(단일·워크플로·오케스트레이션)으로 고쳐 비교한 글이 같은 버그를 세 방식으로 — 기준선·워크플로·오케스트레이션 실행이에요. allowed_tools로 읽기 전용 서브에이전트를 만들고 agents= 로 리드에 붙이는 코드가 나와요.
